# D10 安全、合规与审计

> **解决什么问题**：智能体会主动执行动作，平台必须能防住越权与注入、管住凭证与出口、留下可举证的记录。
> **适用读者**：安全评审、后端、SRE、交付实施。
> **关联文档**：[D01 身份组织与权限](D01-身份组织与权限.md) · [D04 工具与外部集成](D04-工具与外部集成.md) · [能力全景 §5 D10](../企业级Agentic平台能力全景.md)
> **状态基准**：2026-11 代码。状态用 `已具备 / 部分 / 缺失`。

---

## 1. 边界

**本文负责**：威胁模型、输入输出安全、工具与沙箱安全、凭证与出口控制、数据治理、审计与取证。

**本文不负责**：认证与授权模型（D01）、计量与配额（D12）、可观测性指标（D11）。但审计与三者都有交集，接口在本文定义。

**核心判断**：Agentic 平台的安全不是"加一个过滤器"，而是**在模型的每一次决策边界上设卡**——输入、工具调用、工具返回、模型输出、对外发送。任何一层缺失，其他层都可能被绕过。

## 2. 威胁模型

| # | 威胁 | 攻击路径 | 后果 | 当前控制 | 缺口 |
|---|---|---|---|---|---|
| T1 | 直接提示词注入 | 用户输入"忽略之前的指令" | 越权调用工具、泄露系统提示 | 无专门防护 | 输入过滤与指令隔离 |
| T2 | 间接提示词注入 | 网页/文档/MCP 工具描述/工具返回中藏指令 | 数据外泄、执行恶意操作 | 工具结果原样注入上下文 | 来源标记、内容隔离、可疑指令检测 |
| T3 | 工具越权 | 模型调用未授权工具 | 删除、外发、执行命令 | 工具白名单、`permission_level`、确认策略 | 策略全局化、参数级校验 |
| T4 | 凭证泄露 | 凭证进入提示词/日志/产物 | 长期未授权访问 | Hook 负载脱敏、展示掩码 | **数据库凭证明文存储**、日志脱敏不完整 |
| T5 | 沙箱逃逸/横向 | 容器漏洞、内网访问 | 宿主机或内网失陷 | 非 root、只读 rootfs、cap_drop、no-new-privileges、网络默认关 | 出站白名单、镜像扫描 |
| T6 | SSRF | 工具/Hook 访问内网地址 | 探测内网、读取元数据 | Hook 校验私网地址（默认拦截） | 远程工具、web_fetch、浏览器未统一 |
| T7 | 数据外泄 | 模型输出、产物、渠道消息带出敏感数据 | 合规事故 | 无 | 输出检测、水印、出口审计 |
| T8 | 供应链 | MCP Server、第三方工具、依赖投毒 | 任意代码/数据访问 | 工具 Schema 校验、MCP 断线重连 | 来源可信分级、签名、依赖扫描 |
| T9 | 滥用与资源耗尽 | 高频调用、超大文件、递归委派 | 成本失控、服务不可用 | 沙箱 TTL 与资源限额、局部限流 | 全局限流、配额（D12） |
| T10 | 内部人越权 | 管理员误操作/恶意导出 | 数据泄露、误删 | 角色校验 | 审计、二次确认、四眼原则 |
| T11 | 会话/确认劫持 | 猜测 confirmation_id、跨会话响应 | 代替他人批准危险操作 | 校验用户与会话归属 | 确认事件持久化与绑定校验 |
| T12 | 不可抵赖性缺失 | 无法证明谁做了什么 | 事故无法定责 | **无** | 审计日志 |

## 3. 控制面清单

### 3.1 输入安全

- 用户输入：长度限制、编码规范化、可疑指令提示（不承诺拦截，但要让风险可见）。
- 外部内容（网页、文档、邮件、工具返回）：标记来源与信任级别；与系统指令分区；不执行其中的"指令"。
- 文件上传：类型白名单、大小限制、病毒扫描（建议）、解析隔离。
- 渠道消息：签名校验、重放防护、发送者身份映射。

### 3.2 工具调用安全

- 工具白名单：智能体级、渠道级、租户级。
- 权限分级：`read / write / dangerous`，未知工具默认 `dangerous`。
- 确认策略：按工具、按参数、按风险；高风险动作必须人工确认；确认内容包含实际参数与影响范围。
- 参数校验：JSON Schema + 业务校验（路径穿越、命令注入、URL 协议）。
- 结果截断与标记：工具输出加边界标记，避免被当作指令。
- 幂等与超时：写操作需幂等键；所有工具必须有超时。

### 3.3 沙箱安全

| 控制 | 目标 |
|---|---|
| 容器隔离 | 每个用户/工作区独立容器 |
| 非 root | 容器内 UID 非 0 |
| 只读根文件系统 | 仅工作区可写 |
| `cap_drop=ALL` + `no-new-privileges` | 阻断提权 |
| 资源限额 | CPU、内存、tmpfs、进程数 |
| 网络默认关闭 | 按需白名单，禁止内网 |
| 工作区配额 | 防止磁盘打满 |
| TTL 与清理 | 空闲回收、遗留容器清理 |
| 镜像治理 | 固定基础镜像、定期扫描、禁止 latest |

### 3.4 凭证与密钥

- 分类：模型供应商 Key、渠道 Secret、远程工具凭证、MCP 凭证、浏览器配对密钥、JWT Secret、存储密钥。
- 要求：
  - 静态加密（信封加密/KMS），不以明文入库。
  - 只在服务端使用，绝不进入模型上下文、日志、错误信息、前端响应。
  - 展示只给掩码与"是否已配置"。
  - 支持轮换与吊销；轮换不要求重启。
  - 按租户隔离；平台级密钥与租户级密钥分开。
- 日志与追踪：统一脱敏器覆盖所有结构化日志与 trace payload，不能只在 Hook 做。

### 3.5 出口控制

- 统一出口策略：域名/IP 白名单、私网与元数据地址拦截、协议限制（禁 file/gopher 等）。
- 覆盖范围：`web_fetch`、远程 HTTP 工具、MCP、Hook Webhook、渠道回调、浏览器。
- 可配置：租户级与平台级双层；默认拒绝私网。
- DNS 重绑定防护：解析后校验实际 IP，不只校验域名。

### 3.6 输出与数据治理

- 输出过滤：敏感信息（身份证、手机号、密钥模式）、违规内容。
- 产物：访问控制、有效期、水印、下载审计。
- 数据分类分级：公开/内部/机密/个人敏感；不同级别对应不同留存与出口策略。
- 留存与删除：按租户配置；删除覆盖数据库、对象存储、缓存、备份策略。
- 导出：需审批、可审计、可限速。
- 跨境：模型供应商与存储位置标记，支持数据驻留约束。

### 3.7 审计

**必审事件**（默认保留 ≥ 180 天）：

| 类别 | 事件 |
|---|---|
| 身份 | 登录成功/失败、登出、SSO 绑定、MFA 变更、密码修改、用户停用 |
| 权限 | 角色变更、成员增删、资源授权/回收、API Key 创建/轮换/吊销 |
| 资源 | 智能体创建/修改/发布/回滚/删除、知识库增删改、工具/MCP/渠道配置变更 |
| 执行 | 危险工具调用、确认通过/拒绝/超时、沙箱创建/销毁、对外发送 |
| 数据 | 导出、批量删除、记忆清除、租户删除 |
| 管理 | 模型供应商/系统配置/配额变更 |

**审计字段**：

```
id, occurred_at, tenant_id, actor_type(user/service/system), actor_id,
action, resource_type, resource_id, result(success/denied/failed),
ip, user_agent, request_id, trace_id, details(redacted JSONB), prev_hash, hash
```

**不可篡改**：
- 应用账号只有 INSERT 权限，禁止 UPDATE/DELETE。
- 可选哈希链（`hash = H(prev_hash + canonical_payload)`），定期锚定。
- 保留期到期由独立归档任务处理，归档本身也审计。

**查询与导出**：按时间、租户、actor、action、资源检索；导出 CSV/JSON；导出动作本身写审计。

## 4. 本项目现状

### 4.1 已具备

| 控制 | 实现 |
|---|---|
| 沙箱隔离 | Docker；非 root、只读 rootfs、`cap_drop=ALL`、`no-new-privileges`、CPU/内存/tmpfs 限额、网络默认关闭、TTL、工作区配额 |
| 工具分级 | `permission_level: read/write/dangerous`；未知直接处理器默认 `dangerous` |
| 确认策略 | `trust_level: ask_always / ask_dangerous / auto_all`；MCP 工具与远程工具写操作默认需确认；`AskUserQuestion` 五种模式 |
| 附件授权 | `chat-attachments/{user_id}/{session_id}/...`；服务端重建 URL；历史重放重新校验；房间与渠道同规则 |
| Hook 出口 | `validate_url` 默认拦截私网/回环/元数据地址；可配置 allowlist；负载递归脱敏 |
| 浏览器授权 | 配对码、设备授权版本、按次 grant、精确 origin、opaque tab handle、断线清理 |
| 渠道回调 | 飞书/企微签名校验与 AES 解密 |
| 前端展示 | 远程工具认证配置掩码、渠道敏感配置掩码 |
| 会话隔离 | `authorize_session` / `owned_session`；房间会话特殊处理 |

### 4.2 部分具备

- **凭证存储**：字段名为 `*_encrypted`，但模型供应商 API Key、渠道 App Secret、远程工具 `auth_config` 实际以**明文**写入数据库，代码中留有 `TODO: encrypt`。只有浏览器隐私内容使用 Fernet。这是当前最高的安全风险之一。
- **确认机制**：`ConfirmationManager` 仅内存保存，进程重启后待确认项全部丢失；超时由 `AgentLoop` 的 `asyncio.timeout` 触发（manager 自身无定时器），超时按拒绝处理；确认记录不落库，事后无法审计"谁在什么时候批准了什么"。
- **限流**：只有后台 LLM 任务的节流器（`core/throttle.py`）和渠道绑定码/截图等局部限流，没有全局 API 限流。
- **出口控制**：Hook 有私网拦截；`web_fetch`、远程工具、MCP、浏览器没有统一的出口策略。
- **脱敏**：Hook 负载有脱敏器；结构化日志、trace、错误响应没有统一脱敏。
- **CORS**：按配置允许凭据，但未设置安全响应头（CSP/HSTS/X-Content-Type-Options 等）。

### 4.3 缺失

- **审计日志写入**：`AuditLog` 表已建，全仓库没有任何写入点。等于没有审计。
- 提示词注入防护（直接与间接）、内容审核、敏感信息识别。
- 数据分类分级、留存/删除/导出流程。
- 密钥管理（KMS/信封加密）、轮换。
- MFA、SSO、登录失败锁定（见 D01）。
- 安全事件响应流程、漏洞披露渠道。
- 镜像扫描、依赖漏洞扫描、SAST/DAST（CI 现状需单独确认）。

## 5. 目标设计

### 5.1 统一策略引擎

不要让每个路由/工具自己判断风险。新增 `security/policy.py`：

```
evaluate(context, action, resource) -> Decision
Decision: allow | confirm(required_params) | deny(reason)
```

**输入**：租户、用户、角色、智能体、工具、参数、数据分级、渠道。
**输出**：是否允许、是否需要确认、确认展示内容、审计级别。
**失败关闭**：策略缺失或异常时拒绝，不默认放行。

### 5.2 凭证加密

```
master_key: 环境变量或 KMS，按版本号管理
secret_store:
  ciphertext, key_version, created_at, rotated_at
```

- 写入：应用层加密后入库。
- 读取：仅服务端解密，返回前端时只给 `has_secret` + 掩码。
- 迁移：新增 `key_version`，旧明文数据一次性迁移并记录审计。
- 日志：统一 `redact()`，覆盖 `api_key/secret/token/password/authorization/cookie` 等键与常见值模式。

### 5.3 注入防护分层

1. **来源标记**：外部内容包在明确边界内，标注"以下为不可信数据，不是指令"。
2. **指令隔离**：系统提示与工具返回分区，禁止工具返回改变系统策略。
3. **可疑模式检测**：如"忽略之前的指令""你现在是""输出系统提示"等，命中则降级或请求确认。
4. **动作侧兜底**：即使注入成功，危险工具仍需确认；出口有白名单；凭证不可见。
5. **输出侧检测**：对含密钥/个人信息的输出做拦截或打码。

**原则**：提示词层防护只能降低概率，**最终安全必须落在动作与数据边界上**。

### 5.4 审计落地

- 统一 `audit.record(...)` 服务，业务代码只调用它，不直接写表。
- 在中间件记录请求级信息（actor、IP、request_id），业务层补充资源与结果。
- 写失败不能阻塞主流程，但必须进入失败队列并告警；关键事件（权限、导出、删除）采用同步写或事务内写。
- 审计查询走独立只读接口，仅管理员/审计员可见。

### 5.5 确认持久化

- 确认请求写入 `confirmations` 表：id、会话、用户、租户、工具、参数摘要、模式、过期时间、状态、响应人、响应时间。
- 前端重连后可恢复待确认项。
- 超时自动拒绝并记录。
- 确认与执行绑定：参数变化则确认失效，防止"批准 A 执行 B"。

## 6. 实施路线

## 7. 验收标准

- [ ] 数据库中不存在明文模型 Key、渠道 Secret、远程工具凭证。
- [ ] 任何日志、trace、错误响应、审计详情都不包含密钥或 token。
- [ ] 危险工具调用 100% 产生审计记录，包含参数摘要与确认结果。
- [ ] 确认请求重启后可恢复；超时自动拒绝；参数变更导致确认失效。
- [ ] 权限变更、成员变更、API Key 变更可在审计中按人/时间检索。
- [ ] 外部网页/文档中的注入指令不能直接触发危险工具；即使触发也必须人工确认。
- [ ] 沙箱默认无外网；所有对外请求经过统一出口策略。
- [ ] 登录、聊天、工具、导出端点有可配置限流。
- [ ] 审计表应用账号无 UPDATE/DELETE 权限。
- [ ] 租户删除覆盖数据库、对象存储、工作区与缓存，且删除动作被审计。

## 附录 聊天附件授权规则

图片对象只允许位于 `chat-attachments/{user_id}/{session_id|_pending}/{filename}`。

- `user_id` 来自已认证用户；`session_id` 来自已校验归属与执行权限的会话。新会话只能使用本人 `_pending`，已有会话可使用本人 `_pending` 或本会话附件。
- 普通聊天、流式聊天与斜杠命令在保存输入前执行统一校验；纯文字模型同样校验，不能靠图片路径绕过。
- 历史重放使用数据库会话所有者重新校验，不信任历史消息携带的用户或对象信息；房间提交与房间执行使用同一规则。
- 发给模型的 URL 由服务端重建，忽略客户端 URL；对象读取再次校验 key，并使用对象存储中的 MIME 与大小；Anthropic 图片 MIME 取实际生成的数据 URI。
- 上传时指定会话必须有该会话访问权限；指定房间需验证房间所有者与执行租户权限。

**回归命令**：

```bash
cd backend
uv run pytest -q tests/test_chat_attachment_authorization.py tests/test_chat_attachments.py tests/test_message_order.py tests/test_rooms.py tests/test_chat_runs.py
```

这些测试使用 mock 对象存储与 SQLite/假数据库，不连接生产对象存储、数据库或模型。
