# D13 可靠性与性能

> **解决什么问题**：Agent 链路长、外部依赖多，平台如何在依赖故障、进程崩溃、并发争用下给出明确行为、可恢复终态和可度量的容量边界。
> **适用读者**：后端、SRE/运维、测试与交付实施。
> **关联文档**：[D02 智能体运行时](../D02-智能体运行时/README.md) · [D03 模型接入与治理](../D03-模型接入与治理/README.md) · [D04 工具与外部集成](../D04-工具与外部集成/README.md) · [D11 可观测性与运营](../D11-可观测性与运营/README.md) · [D14 部署交付与运维](../D14-部署交付与运维/README.md) · [能力全景 §5 D13](../../00-平台总览/README.md)
> **状态基准**：2026-11 版本。状态统一用 `已具备 / 部分 / 缺失`。

## 1. 边界

**负责**：
- 可用性：无状态服务、健康检查、优雅停机、多实例行为。
- 异步化：长任务持久化、幂等、重试、死信、削峰。
- 隔离：租户/会话/沙箱/子智能体故障不扩散。
- 降级：模型、工具、对象存储、Redis、容器运行时、数据库故障时的明确行为。
- 一致性：事件序号、消息去重、工具副作用未知语义。
- 容量与性能：并发会话、沙箱、连接数、数据库连接池、对象存储带宽、延迟目标。

**不负责**：
- 运行时语义与协议细节 → D02。
- 部署形态、备份恢复、RTO/RPO → D14。
- 安全边界与审计 → D10。
- 配额、预算与成本分摊 → D12。

**设计底线**：每个长任务必须有所有者、租约和终态；每种依赖故障必须明确“失败关闭”还是“降级继续”；每个容量上限必须有执行点，否则按“缺失”记录。

## 2. 能力清单

### 2.1 可用性

| 能力 | 应该提供 | 关键点 |
|---|---|---|
| 无状态服务 | 请求可落到任意实例 | 会话与任务状态存数据库，不存进程内存 |
| 健康检查 | 存活检查 + 就绪检查 | 就绪检查要验证数据库、Redis、对象存储、容器运行时，而非只返回进程存活 |
| 优雅停机 | 停止接新请求、等待在途、写终态、释放租约 | 后台任务标记中断，沙箱同步后保留容器 |
| 多实例 | 重连、停止、查询跨副本 | 进程内确认与浏览器管理器需要粘性会话 |
| 启动降级 | 可选依赖不可用仍能启动 | 只有数据库是硬依赖；对象存储/容器运行时可以降级 |

### 2.2 异步化与任务

| 能力 | 应该提供 | 本项目做法 |
|---|---|---|
| 任务持久化 | 任务与请求生命周期解耦 | 任务主记录与事件记录落库 |
| 幂等 | 同一任务重复触发不重复产生副作用 | 同会话唯一运行任务；续跑复用已完成工具结果 |
| 重试 | 区分可重试与不可重试 | 模型瞬时错误退避重试；任务本身不自动重跑 |
| 死信 | 失败任务可查询、可人工处理 | 缺失；只有终态与未知工具结果提示 |
| 队列与削峰 | 超过容量时排队而非直接失败 | 缺失；Web 轮次直接起进程内执行单元 |
| 定时抢占 | 多副本同一时刻只执行一次 | Redis 原子抢占，失败关闭 |

### 2.3 隔离

- 租户/用户：所有查询按执行租户与用户过滤；后台任务显式设置租户上下文（覆盖的表见 D01）。
- 会话：同一会话只允许一个运行任务，会话行锁与部分唯一索引双重约束。
- 子智能体：子智能体失败转成工具错误返回父级，不终止整轮。
- 沙箱：按用户隔离容器，内存文件系统工作区，非 root、只读根文件系统、移除全部特权能力、默认断网、CPU/内存限额。
- 并发互斥：同一用户的创建、执行、同步、删除使用进程内锁与文件锁串行；多进程必须共享同一锁目录。

### 2.4 降级矩阵

| 依赖 | 故障表现 | 当前行为 | 评价 |
|---|---|---|---|
| 数据库 | 启动失败或心跳写入失败 | 初始化超 600 秒拒绝启动；心跳无法证明所有权时取消本地执行 | 失败关闭，合理 |
| Redis | 通知、宠物任务、节流失效 | 任务订阅退化为 1 秒轮询；宠物任务静默；后台模型调用节流退化为进程内 | 部分降级 |
| 容器运行时 | 沙箱不可用 | 后端仍启动并记录启动降级，后台周期重试；沙箱工具明确报错 | 已具备 |
| 对象存储 | 工作区无法注入/同步 | 新工作区不可用；已有容器保留文件；同步失败保留容器并告警 | 已具备 |
| 模型供应商 | 限流、服务端错误、超时 | 可重试错误最多 3 次指数退避；流式仅在零产出时重试 | 部分；无熔断与主动切换 |
| 上下文溢出 | 模型拒绝请求 | 同步接口/发布接口紧急压缩重试一次；Web 后台流只告警 | 部分；行为不一致 |

### 2.5 一致性

- 事件以任务内单调递增的序号排序，订阅方按游标去重；完成等终态提交后才发送。
- 工具调用事件先持久化再执行，工具结果在推进下一步前提交；崩溃最多丢失最后一个文本批次。
- 工具结果未知不是失败：历史标记为未知并禁止一键续跑，避免重复外部副作用。
- 渠道入站按事件标识去重，当前是进程内 1 小时内存缓存，多副本不共享。
- 记忆更新使用版本冲突检测；冲突要求重读后再写。
- 通用外部系统无法承诺 exactly-once，只能做到“至少一次 + 已成功调用复用 + 未知时人工核对”。

### 2.6 容量与性能

| 资源 | 当前口径 | 执行点 | 风险 |
|---|---|---|---|
| 数据库连接 | 每进程连接上限 30（20 常驻 + 10 溢出），获取超时 8 秒，取连接前探活 | 连接池 | 多副本叠加可能打满数据库 |
| 沙箱 | 每活跃用户 1 个容器；默认 1 CPU / 512MB | 空闲 3600 秒回收，后台每 300 秒检查 | 无全局并发上限，宿主机可能被占满 |
| SSE 连接 | 每标签页一个订阅者 | 无上限 | 每连接周期性查库，长连接占用内存 |
| 任务事件 | 每次运行逐条写入数据库 | 删除会话时级联清理 | 无定时清理，长会话表持续增长 |
| Redis | 宠物任务状态 30 分钟过期；定时任务抢占记录保留 24 小时 | 各模块自行设置 | 无统一容量规划 |
| 性能目标 | 首字延迟、SSE 延迟、工具 P95、页面加载 | 未定义 SLO，未做压测 | 无法判断扩容时机 |

## 3. 本项目现状

### 3.1 已具备

| 能力 | 实现 |
|---|---|
| 持久后台任务 | 任务状态、所有者、心跳、快照与事件表；断线重连与游标回放 |
| 任务租约 | 心跳 1 秒、租约 30 秒；过期任务在状态查询或订阅时标记中断 |
| 显式停止 | 停止请求跨进程可见；取消父任务与子任务；等待终态后返回 |
| 优雅停机 | 停机时将本地任务标记为中断；沙箱同步后保留容器 |
| 定时任务抢占 | Redis 原子抢占，60 秒宽限、24 小时保留；Redis 故障时失败关闭 |
| 沙箱生命周期 | 懒连接容器运行时、启动降级、每用户锁、空闲回收、周期同步、关闭前同步 |
| 沙箱安全 | 非 root、只读根文件系统、移除全部特权能力、禁止提权、默认断网、CPU/内存/工作区限额 |
| 故障隔离与并发 | 子智能体异常转工具错误；同会话串行；同用户沙箱操作互斥；记忆更新乐观锁冲突 |
| 渠道去重 | 按事件标识进程内去重，有效期约 1 小时 |
| 通知降级 | Redis 发布订阅唤醒；不可用时退化为进程内唤醒 + 1 秒轮询 |

### 3.2 部分具备

| 能力 | 现状 | 缺口 |
|---|---|---|
| 多实例 | 任务状态、重连、停止可跨副本 | 执行单元仍在进程内；确认与浏览器动作管理器不共享；渠道去重不共享 |
| 健康检查 | 健康检查只返回进程存活与活跃沙箱数 | 不检查数据库、Redis、对象存储、容器运行时，不能作为就绪判断 |
| 优雅停机 | 任务写中断、沙箱同步 | 没有显式等待在途 HTTP/SSE 连接的排空阶段 |
| 限流 | 后台模型工作有 Redis 节流 | 无网关级 QPS/并发限制；部分一次性放行策略在 Redis 故障时放行 |
| 容量上限 | 沙箱回收期与单用户互斥 | 沙箱并发数、每租户并发任务无执行点 |

### 3.3 缺失

- 统一任务队列、死信队列与背压；Web 任务超过容量时没有排队语义。
- 沙箱全局并发上限的实际执行（并发上限有配置项，但没有执行点）；熔断器与模型主动降级路由（与 D03 共同补齐）。
- 就绪/存活探针、SLO、告警规则、容量压测，以及多实例端到端验证（真实数据库锁、租户隔离、Redis、容器运行时）。
- 跨进程任务迁移或自动恢复。

## 4. 可靠性设计与容量模型

### 4.1 任务租约模型

- **预留**：会话行锁加“运行中”状态的部分唯一索引，保证同一会话同时只有一个运行任务。
- **执行**：执行单元以进程标识作为所有者，每秒更新心跳。
- **停止**：写入停止请求并取消本地执行；其他副本通过心跳观察到后取消。
- **过期**：心跳超过 30 秒未更新时，按快照是否完成判定为完成或中断。
- **停机**：取消本地执行并写入中断终态。

**边界**：过期检测发生在状态查询和订阅轮询中。若无人查询，数据库中的“运行中”状态不会自行消失；系统没有独立回收器。这是可接受的懒回收，但不能用于计费或容量统计。

### 4.2 事件持久化与重放

- 生产者按事件边界提交；相邻流式文本增量合并写入，文本按时间或条数批量刷新。
- 在非增量事件边界或固定检查点写入快照；崩溃最多丢失一个检查点窗口的文本。
- 订阅者批量读取事件并按序号推进；终态且读完后发送运行状态并结束。
- Redis 只做唤醒，数据库仍是事实源；Redis 不可用时退化为 1 秒超时回查。

### 4.3 沙箱生命周期与故障保护

- 容器按命名空间与用户标识确定归属，标签绑定命名空间、用户与工作区，重启后可发现并接管。
- 同一用户的创建、执行、同步、删除用进程内锁与文件锁串行；同一容器运行时的所有后端必须共享锁目录。
- 空闲回收前同步全部工作区；同步失败或对象存储不可用时保留容器并告警，不用空目录覆盖已有文件。
- 初始化失败或取消时移除本次新建容器，不把半成品同步回对象存储。
- 配置变化、元数据缺失、重复运行容器一律保留并报错，不直接删除用户文件。

### 4.4 定时任务抢占

- 每次触发按任务标识与计划时间原子抢占，抢占记录保留 24 小时；成功、失败、取消都保留记录，防止迟到副本重复执行。
- 超过 60 秒宽限的触发直接放弃，不补跑；Redis 错误时失败关闭，宁可不发也不重复发。

### 4.5 失败模式

| 场景 | 后果 | 防护 / 现状 |
|---|---|---|
| 进程崩溃 | 任务停在运行中 | 租约过期后标记中断；不自动续跑 |
| 数据库抖动 | 心跳/事件写入失败 | 执行单元取消本地执行；订阅端可能重复读最后一段 |
| Redis 不可用 | 跨进程唤醒失效 | 1 秒轮询兜底；宠物任务与节流失效 |
| 容器运行时不可用 | 沙箱工具失败 | 后端继续启动；工具返回明确错误 |
| 对象存储不可用 | 新工作区无法初始化 | 拒绝初始化，保留已有容器与文件 |
| 同一会话重复提交 | 两个执行单元并发 | 会话行锁加唯一索引，第二个请求被拒绝 |
| 渠道重复投递 | 重复回复 | 进程内事件标识去重；多副本仍有窗口 |
| 长工具执行 | 请求长时间挂起 | 沙箱命令超时 60 秒；容器运行时调用线程本身不可取消 |

### 4.6 容量模型

- **数据库**：每后端进程最多 30 个连接（20 常驻 + 10 溢出）。部署 N 个副本时，数据库最大连接数必须大于 30N 加运维预留。
- **沙箱**：每活跃用户 1 个容器，默认 1 CPU / 512MB / 512MB 工作区；全局没有上限，宿主机容量就是实际上限。
- **SSE、事件表与对象存储**：每个任务页面 1 个订阅者，空闲时每秒查库；事件量随 token 与工具调用增长且无分区/保留期；容器创建、销毁、每 5 分钟同步都走压缩包传输，接近 500MB 时恢复与同步是主要延迟来源。

## 5. 实施建议

### P0

1. **容量执行点**：落实沙箱全局并发上限（或删除没有执行点的并发配置），增加每租户并发任务上限与明确的排队/拒绝语义。
2. **就绪与依赖健康**：健康检查拆分存活与就绪，就绪检查数据库、Redis、对象存储、容器运行时，并暴露降级状态。
3. **事件保留策略**：为任务事件增加按时间/大小的归档或清理任务，明确索引与分区方案。
4. **多实例验证**：在真实数据库、Redis、容器运行时下验证锁、租户隔离、重连、停止与心跳过期。

### P1

5. 统一任务队列与死信，或明确写入文档：当前只支持进程内执行与人工续跑。
6. 熔断器与模型降级路由（与 D03 一起做），避免供应商持续故障拖住执行单元。
7. SLO 与指标：首字延迟、SSE 延迟、工具 P95、任务成功率、沙箱等待时间、事件写入延迟。
8. 容量压测：N 并发会话 × 沙箱 × SSE，测数据库连接池、Redis、对象存储带宽与宿主机资源。

### P2

9. 沙箱预热池，降低首次工具调用延迟。
10. 跨实例任务迁移或自动恢复，并为 4.5 的每个失败模式补齐告警与故障手册。
