# D01 身份、组织与权限

> **解决什么问题**：谁能进入平台、属于哪个组织、能看到和操作哪些资源。
> **适用读者**：后端、前端、安全评审、交付实施。
> **关联文档**：[D10 安全合规与审计](../D10-安全合规与审计/README.md) · [D12 成本与配额](../D12-成本与配额/README.md) · [能力全景 §5 D1](../../00-平台总览/README.md)
> **状态基准**：2026-11 代码。状态用 `已具备 / 部分 / 缺失`。

## 1. 边界

**本文负责**：
- 组织模型：租户、部门/项目、用户、成员关系。
- 认证：账号密码、会话、SSO、MFA、服务身份。
- 授权：角色、资源可见性、资源级 ACL、数据行级权限。
- 生命周期：注册、邀请、加入/退出、停用、离职、租户切换。

**本文不负责**：
- 操作留痕与合规取证 → D10；用量计量与配额 → D12。
- 智能体内部的工具白名单与子智能体权限继承 → D04 / D07。

**设计底线**：任何资源都必须能回答三个问题——**属于谁（租户/用户）**、**谁能看（可见性）**、**谁能改（角色/ACL）**。三者缺一，隔离就不成立。

资源逐项归属、租户级与用户级的划分口径，以及各执行入口的租户来源，属于实现细节，见本目录《用户与租户隔离》。

## 2. 能力清单

### 2.1 组织模型

| 层级 | 作用 | 最低要求 |
|---|---|---|
| 平台 | 跨租户运营、模型供应商、系统配置 | 超级管理员 |
| 租户 | 数据隔离与计费单元 | 必须有 |
| 部门/项目 | 资源归属与权限分组 | 企业版建议有 |
| 用户 | 身份主体 | 必须有 |
| 服务账号 | 机器调用主体 | 对外 API 必需 |

**决策点**：
- 用户允许属于多个租户时，必须有“当前活动租户”和“执行租户”两个概念；后台任务不能用界面当前租户推断。
- 部门建议同时作为资源归属与权限授予维度；租户间默认不共享资源，需要时走显式发布/订阅，不做隐式可见。

### 2.2 认证

| 能力 | 企业要求 | 说明 |
|---|---|---|
| 账号密码 | 必须 | 密码策略、安全哈希、失败锁定 |
| 访问令牌 | 必须 | 短期访问令牌，含用户与角色 |
| 刷新令牌 | 必须 | 哈希存储、轮转、可吊销 |
| SSO | 企业采购硬门槛 | OIDC / SAML / CAS，至少一种 |
| 目录同步 | 中大型企业 | LDAP/AD 或 SCIM |
| MFA | 安全评审常见要求 | TOTP / 企业 MFA |
| 服务身份 | 开放平台必需 | API Key / OAuth Client Credentials |
| 会话管理 | 建议 | 查看登录设备、主动下线 |

**令牌设计要点**：
- 访问令牌短（15 分钟级），刷新令牌长但必须可吊销、可轮转；轮转后旧令牌立即失效，防止重放。
- 用户停用后刷新流程必须拒绝；访问令牌在过期前仍有窗口，关键操作需二次校验用户状态（当前实现每次请求都校验用户启用状态）。
- 角色变更后旧访问令牌仍携带旧角色声明，敏感操作应以数据库角色为准，不能只信令牌。

### 2.3 授权

建议采用四层判定，顺序不可颠倒：

1. **租户边界**：资源所属租户必须等于当前执行租户。
2. **资源可见性**：租户内公开 / 仅创建者或授权者。
3. **角色**：超级管理员 / 租户管理员 / 成员 / 只读。
4. **资源 ACL**：显式授予某用户或部门读、写、管理操作。

**权限点建议**：
- 平台级：租户管理、模型供应商、系统配置、全局审计。
- 租户级：成员管理、智能体发布、知识库管理、渠道配置、工具/MCP 管理、配额查看。
- 资源级：查看、编辑、删除、发布、调用、授权他人；数据级：知识库文档、会话、记忆、产物。

**禁止的做法**：
- 只靠前端隐藏按钮，或只靠令牌里的角色、不查数据库。
- 先检索再按权限过滤（会泄露存在性与数量）；必须在查询条件里过滤。
- 用“租户内公开”代替 ACL 表达“某部门可见”。

### 2.4 资源归属与可见性

| 资源 | 归属 | 建议可见性 |
|---|---|---|
| 智能体 | 租户 | 租户内公开 / 仅创建者 / 指定成员 |
| 知识库、图谱 | 租户 | 租户内公开 / 仅创建者 |
| MCP Server、远程工具 | 租户 | 租户内公开 |
| 渠道配置 | 租户 | 管理员可见 |
| 会话、消息 | 用户 | 仅本人；房间会话属房间 |
| 记忆、画像 | 用户 | 仅本人 |
| 技能 | 用户或租户 | 仅本人 / 租户内公开 |
| 定时任务 | 租户或用户 | 创建者 + 管理员 |
| 工作区、产物 | 用户 | 仅本人；按会话/房间校验 |
| 宠物包 | 租户 | 租户内公开 / 仅创建者 |

**租户切换的坑**：用户属于多个租户时，前端切换只改变界面选择；后台任务（定时任务、渠道回调、异步执行）必须在创建时固化租户，并在执行时重新校验成员资格，不能读取“当前租户”。

### 2.5 生命周期与服务身份

- 注册：首个用户成为超级管理员；后续注册默认创建独立租户或走邀请（二选一，必须明确）。
- 邀请：邀请码/邮件，带过期与使用次数；加入后写成员关系。
- 停用：立即禁止登录与刷新，保留数据、可恢复；租户停用后其所有用户不可登录、后台任务停止。
- 离职/删除：转移或删除资源、吊销全部刷新令牌、清理渠道绑定与外部身份；租户删除采用软删 + 保留期 + 最终物理删除，需二次确认与审计。

对外 API 不能用人类令牌。服务身份至少需要：
- API Key：可识别前缀 + 哈希存储、作用域（租户/智能体/权限）、过期、轮换、吊销。
- 调用审计：每次调用记录密钥标识、来源 IP、资源、结果；按密钥做 QPS/并发/日额度限流。
- 密钥展示：创建时明文仅显示一次，之后只显示掩码。

## 3. 本项目现状

### 3.1 已具备

| 能力 | 实现事实 |
|---|---|
| 租户/用户 | 多租户数据模型；用户与租户为多对多成员关系，用户保留当前活动租户 |
| 角色 | 角色分为普通用户、管理员、超级管理员；管理员与超级管理员有独立校验 |
| 注册登录 | 支持注册、登录、令牌刷新、登出；密码以安全哈希存储，要求至少 8 字符且不超过 72 字节 |
| 令牌 | 访问令牌默认 15 分钟、刷新令牌默认 7 天；刷新令牌只保存哈希，刷新时轮转旧令牌 |
| 租户切换 | 用户可在所属租户间切换；每次请求校验成员资格 |
| 后台执行租户 | 后台任务在创建时固化执行租户，执行前重新校验用户、租户与成员资格 |
| 资源可见性 | 智能体、知识库、图谱知识库、宠物包、钩子等租户级资源区分租户内公开与仅创建者两档 |
| 会话归属 | 会话访问校验本人归属，并排除房间来源 |
| 管理入口 | 超级管理员可管理用户与租户；租户成员可增删 |
| 前端 | 登录/注册、租户切换、用户管理、租户管理页 |

### 3.2 部分具备

- **隔离**：数据库行级安全只覆盖少数用户级辅助表，核心业务表仍依赖应用层过滤，数据库没有兜底。
- **角色**：只有全局角色，租户成员关系没有独立角色；“租户管理员”实际等于全局管理员，无法表达“只管理某个租户”。
- **可见性**：只有租户内公开/仅创建者两档，没有“指定成员/部门”；仅创建者的判断分散在各路由，没有统一策略。
- **停用**：停用后登录与刷新被拒绝；已签发的访问令牌在剩余有效期内仍可用，直到下一次请求校验用户状态（当前每次请求都会校验，实际窗口很小），但不会主动吊销。
- **邀请**：依赖管理员直接创建用户或加入成员，没有完整邀请流程。

### 3.3 缺失

- SSO（OIDC/SAML）、LDAP/AD、SCIM、MFA。
- 租户内角色、资源级 ACL、部门/项目层级。
- 服务账号、API Key、OAuth Client Credentials。
- 登录失败锁定、异常登录检测、会话设备管理；权限判定的统一策略层（当前散落在各路由）；权限变更审计（见 D10）；离职/删除的自动化清理。

## 4. 目标设计

### 4.1 数据模型增量

- **租户内角色**：成员关系增加角色（所有者/管理员/成员/只读）与状态（活跃/已邀请/已停用），使“租户管理员”不再等同于全局管理员。
- **资源 ACL**：按资源类型与资源标识记录授权主体（用户/租户角色/部门）及操作集合（读/编辑/删除/发布/调用）。
- **部门**：租户内支持多级部门，用户可属于多个部门。
- **服务账号**：服务账号归属租户；API Key 记录可识别前缀、密钥哈希、作用域、过期时间、最后使用时间与吊销时间。

### 4.2 统一授权入口

新增统一授权层，所有路由只调用统一入口，禁止各自拼查询条件：

- 校验成员资格与租户状态。
- 按角色 + 可见性 + ACL 判定操作是否允许。
- 在查询层追加过滤，避免“先检索后过滤”。
- 无权访问统一按“不存在”处理，避免泄露资源是否存在；仅管理员可用的操作返回明确的禁止语义。

### 4.3 认证与服务身份扩展

- OIDC：授权码 + PKCE；校验身份令牌的签发方、受众与随机数；按邮箱或外部主体标识绑定用户；首次登录走邀请或即时创建（可配置）。
- SAML：断言签名校验、属性映射、单点登出。SCIM：用户/组增删改同步，删除即停用。MFA：TOTP，敏感操作（创建 API Key、修改权限、导出数据）强制二次验证。
- API Key 只存哈希，明文仅展示一次；作用域至少包含允许的租户、智能体与操作。
- 每次调用记录密钥标识，接入 D10 审计与 D12 计量；支持按密钥限流与配额。

## 5. 失败模式

| 场景 | 后果 | 防护 |
|---|---|---|
| 后台任务读取界面当前租户 | 用户切换租户后任务写到错误租户 | 执行时使用固化租户 + 重新校验成员资格（已有执行租户机制） |
| 用户停用但访问令牌未过期 | 短期内仍可调用 | 每次请求校验用户状态；敏感操作二次校验；缩短访问令牌有效期 |
| 租户内公开被当作“部门可见” | 越权读取 | 引入显式 ACL；不要复用可见性表达复杂授权 |
| 先检索后过滤 | 泄露数量与存在性 | 查询层过滤；权限条件进查询 |
| 跨租户管理员 | 一个管理员管理所有租户 | 引入租户内角色；全局管理员只做平台运维 |
| 删除租户未清理对象存储 | 数据残留 | 删除流程编排：数据库 → 对象存储 → 沙箱工作区 → 渠道 |
| 邀请链接被转发 | 非预期用户加入 | 一次性、绑定邮箱、过期、审计 |
| API Key 泄露 | 长期未授权访问 | 前缀可识别、哈希存储、轮换、吊销、异常调用告警 |

## 6. 实施路线

**P0（交付阻断）**

1. **租户内角色**：为租户成员关系增加独立角色，替换全局管理员的租户管理语义；提供成员管理界面。
2. **统一授权层**：先覆盖智能体、知识库、会话、记忆四类资源；所有列表查询在查询层过滤。
3. **服务账号与 API Key**：支持创建/轮换/吊销、作用域、最后使用时间；对外 API 接受 API Key。
4. **停用即时生效**：权限或状态变更时吊销该用户全部刷新令牌；敏感端点校验数据库状态与角色。
5. **SSO（至少 OIDC）**：登录页支持企业登录；首次登录绑定/邀请策略可配置。

**P1**

6. 部门/项目层级与按部门授权；资源级 ACL 与授权界面。
7. MFA、登录失败锁定、异常登录提醒；SCIM/LDAP 同步。
8. 会话设备管理与主动下线。

**P2**

9. OAuth Client Credentials；细粒度数据权限（知识库文档级）；权限自查工具（回答“为什么我看不到这个资源”）。
