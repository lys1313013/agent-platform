# D12 成本与配额

> **解决什么问题**：Agent 的 token 消耗不可预测，企业必须知道钱花在哪、并且能封顶。
> **适用读者**：后端、财务/运营、SRE、交付实施。
> **关联文档**：[D11 可观测性与运营](D11-可观测性与运营.md) · [D03 模型接入与治理](D03-模型接入与治理.md) · [能力全景 §5 D12](../企业级Agentic平台能力全景.md)
> **状态基准**：2026-11 代码。状态用 `已具备 / 部分 / 缺失`。

---

## 1. 边界

**本文负责**：计量、定价、成本核算、配额、限额执行、告警、账单与成本优化。

**本文不负责**：性能指标与告警平台（D11）、模型选型与路由质量（D03）、租户计费合同（商务）。

**核心原则**：
1. **先计量，再限额**。没有准确计量，配额只是拍脑袋。
2. **在请求进入前拦截**，不要等花完再报错。
3. **预算要传播**。父任务、子智能体、后台任务共享同一笔预算。
4. **计量要可归因**。租户、用户、智能体、模型、会话、任务六个维度至少能下钻到其中四个。

---

## 2. 计量维度

| 维度 | 用途 | 粒度 |
|---|---|---|
| 输入 token | 成本主因 | 每次 LLM 调用 |
| 输出 token | 成本主因 | 每次 LLM 调用 |
| 缓存读/写 token | 折扣核算 | 每次 LLM 调用 |
| 工具调用次数 | 外部 API 成本 | 每次工具调用 |
| 沙箱时长 | 计算资源成本 | 每个会话/任务 |
| 存储 | 对象存储/工作区 | 每日快照 |
| 渠道消息 | IM 平台费用 | 每条消息 |
| 重试次数 | 隐性成本 | 每次调用 |

**归因键**：`tenant_id`、`user_id`、`agent_id`、`session_id`、`trace_id`、`model`、`provider`。

**时间口径**：按 UTC 日聚合；账单按租户时区展示。价格变更要记录生效时间，历史账单不重算。

## 3. 本项目现状

### 3.1 已具备

| 能力 | 实现 |
|---|---|
| 调用级明细 | `LLMCallLog`：模型、供应商、prompt/completion/total/cache token、TTFT、耗时、吞吐、重试次数、状态、错误类型、上下文利用率、工具数 |
| 日聚合 | `TokenUsageDaily`：按 `user_id + date + model` 累加 token 与请求数 |
| 用量接口 | `/api/analytics/summary`、`/trend`、`/distribution`、`/detail`；支持 `mine/global` |
| 前端 | 用量/分析页面 |
| 后台节流 | `core/throttle.py`：记忆提取、摘要等后台 LLM 调用降频 |
| 资源限额 | 沙箱工作区配额、TTL（全局并发上限目前只有配置项，无执行点）；宠物气泡、渠道绑定码、截图等局部配额 |

### 3.2 部分具备

- **成本字段存在但未计算**：`TokenUsageDaily.cost_usd` 在 `core/usage.py` 中**硬编码为 0**；`LLMModel` / `LLMProvider` 没有价格字段。系统当前只能统计 token，不能算钱。
- **归因维度不足**：日聚合只有 `user_id + date + model`，没有 `tenant_id`、`agent_id`；`LLMCallLog` 有这些字段，但没有聚合表。
- **统计权限边界**：`/api/analytics?scope=global` 只检查 `role in {admin, superadmin}`，查询**没有按租户过滤**。在只有全局管理员的当前模型下可用，但一旦引入租户管理员就会跨租户泄露。
- **限额是资源级不是用量级**：沙箱 `max_concurrent` 是进程/平台级，没有按租户分配；没有任何 token/费用上限。

### 3.3 缺失

- 模型价格表与成本计算。
- 租户/部门/用户/智能体/单任务的多层配额。
- 请求准入控制与超额策略。
- 预算传播到子智能体与后台任务。
- 成本告警与账单导出。
- 缓存计费、工具成本、沙箱时长计费。
- 成本优化策略（模型路由、提示词压缩、结果截断已有部分但未与成本联动）。

## 4. 目标设计

### 4.1 价格与成本

**模型价格表**

```
model_prices
  id, provider_type, model_pattern
  input_per_1m, output_per_1m, cache_read_per_1m, cache_write_per_1m
  currency, effective_from, effective_to
```

- 按 `provider_type + model_pattern` 匹配，支持通配。
- 价格变更插入新行，不覆盖历史。
- 支持租户自定义加价系数（`tenant_pricing`）。

**成本计算**

```
cost = input_tokens/1e6 * input_price
     + output_tokens/1e6 * output_price
     + cache_read_tokens/1e6 * cache_read_price
     + cache_write_tokens/1e6 * cache_write_price
```

写入 `LLMCallLog.cost_usd`，并累加到 `usage_daily`。价格缺失时记为 `NULL` 并告警，不要记 0 掩盖问题。

**聚合表**

```
usage_daily
  tenant_id, date, user_id, agent_id, model_id, model
  prompt_tokens, completion_tokens, cache_read_tokens, cache_write_tokens
  request_count, tool_calls, sandbox_seconds, cost
  PRIMARY KEY (tenant_id, date, user_id, agent_id, model_id)
```

保留原 `token_usage_daily` 作为用户维度视图，或迁移后废弃。

### 4.2 配额层级

```
platform (可选：全平台日/月上限)
  └── tenant (月度预算、日 token、并发)
        └── department (可选)
              └── user (月度预算、日 token)
                    └── agent (单次预算、模型白名单)
                          └── task (单次运行上限)
```

**继承规则**：子级未配置则继承父级；子级配置不得高于父级（除非显式放开）。所有层级都可设置：

- `monthly_cost_limit`
- `daily_token_limit`
- `max_concurrent_runs`
- `max_tokens_per_call`
- `allowed_models`

### 4.3 准入控制

在三个位置检查：

1. **请求进入**：创建 run 前检查租户/用户/智能体配额与并发。
2. **每次 LLM 调用前**：检查本次预计 token 是否超单次上限与剩余预算。
3. **每次工具调用前**：检查工具调用次数与外部成本配额。

**预算上下文**：创建 run 时生成 `BudgetContext`，随执行上下文传播：

```
BudgetContext(tenant_id, user_id, agent_id, run_id,
              cost_limit, cost_used, token_limit, token_used,
              on_exceed: warn | downgrade | block)
```

- 子智能体继承父预算，不能单独超额。
- 后台任务（cron、渠道、房间）使用来源租户的预算。
- 并发更新用原子累加（Redis/数据库 `UPDATE ... SET used = used + ?`），避免竞态。

### 4.4 超额策略

| 阈值 | 动作 |
|---|---|
| 50% | 通知租户管理员 |
| 80% | 通知 + 前端提示 |
| 100% | 按配置：拒绝新请求 / 降级到低价模型 / 只读模式 |
| 单次任务超限 | 终止任务并返回明确原因 |

**降级顺序**：便宜模型 → 缩短上下文 → 关闭非必要工具 → 拒绝。降级必须记录，事后可解释。

### 4.5 告警与账单

- 告警：租户/用户预算阈值、单日突增（同比/环比）、模型价格缺失、成本写入失败。
- 账单：按租户出月账单，含模型明细、工具、沙箱、存储；支持 CSV 导出。
- 成本看板：按租户、部门、用户、智能体、模型下钻；支持时间对比。

### 4.6 成本优化

- 模型路由：按任务复杂度选择模型，质量达标前提下优先低价。
- 上下文：压缩、缓存、工具结果截断（已有基础能力）。
- 工具：限制无意义重复调用，缓存只读结果。
- 批处理：非实时任务合并调用。
- 预算感知提示：接近上限时提示模型收敛。

## 5. 实施路线

### P0（先能算钱、能封顶）

1. **价格表 + 成本计算**：替换 `cost_usd=0`；价格缺失记 `NULL` 并告警。
2. **用量归因**：聚合表补 `tenant_id`、`agent_id`；修复 `analytics` global 查询的租户过滤。
3. **租户 + 用户两级配额**：月度费用、日 token、并发；请求准入检查。
4. **单次运行预算**：`max_cost_per_run`、`max_tokens_per_run`，超限终止。
5. **子智能体预算传播**：父预算被子任务共享，超支即停。
6. **告警**：50/80/100% 阈值通知。

### P1

7. 部门/智能体级配额。
8. 超额降级策略（低价模型、上下文缩短）。
9. 账单导出与成本看板下钻。
10. 工具调用、沙箱时长、存储计入成本。
11. 缓存计费与价格变更历史。

### P2

12. 成本预测与预算建议。
13. 按项目/成本中心分摊。
14. 多币种与合同价。

## 6. 验收标准

- [ ] 每次 LLM 调用都能算出费用，价格缺失时有明确告警而不是记 0。
- [ ] 能按租户、用户、智能体、模型查询费用，且租户之间不可互查。
- [ ] 租户月度预算耗尽后，新请求按配置被拒绝或降级，并返回明确原因。
- [ ] 单次任务有硬上限，子智能体不能绕过父预算。
- [ ] 后台任务与渠道任务使用正确的来源租户预算。
- [ ] 成本突增、预算阈值、计价失败都有告警。
- [ ] 账单可导出，金额与明细可对账。
- [ ] 并发配额在多实例下仍准确（原子计数，不依赖进程内状态）。
