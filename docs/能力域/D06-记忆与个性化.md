# D06 记忆与个性化

> **解决什么问题**：让智能体记住用户稳定的事实、偏好和做事方法，同时不让记忆变成不可控、不可纠正、不可删除的黑箱。
> **适用读者**：后端、前端、产品、安全与合规评审。
> **关联文档**：[D02 智能体运行时](D02-智能体运行时.md) · [D05 知识与检索](D05-知识与检索.md) · [D10 安全合规与审计](D10-安全合规与审计.md) · [能力全景 §5 D6](../企业级Agentic平台能力全景.md)
> **状态基准**：2026-11 代码。状态只用 `已具备 / 部分 / 缺失`；设计稿未实现的内容不计入已具备。

---

## 1. 边界

**本文负责**：
- 用户记忆的分层、写入、检索、注入、纠错与删除。
- 每日记忆、用户画像、画像版本。
- 技能作为"程序性记忆"的创建、修改、版本、发现与复用。
- 记忆与画像的作用域隔离和用户可见性。

**本文不负责**：
- 会话历史截断、上下文压缩与摘要 → D02。
- 知识库、文档、图谱 → D05。
- 技能附件的沙箱执行与工具权限 → D04。
- 审计、合规导出、配额 → D10 / D12。

**设计底线**：记忆必须可回答四个问题——**属于谁**（用户/智能体/租户）、**为什么写**（来源会话/工具）、**用户能否改**（查看/纠正/删除）、**删了是否真的没了**（版本与备份）。

## 2. 能力清单

### 2.1 记忆分层

| 层级 | 定位 | 注入方式 |
|---|---|---|
| L1 常驻上下文 | 必须始终遵守的事实/规则 | 每轮全量注入 |
| L2 长期记忆 | 稳定偏好、事实、角色边界 | 按相关性 Top-K |
| L3 情景记忆 | 会话摘要、阶段性进展 | 相关 + 最近 |
| 每日记忆 | 一人一天一条的当日汇总 | 按日期与相关性注入 |
| 用户画像 | 角色、偏好、沟通风格、长期目标 | 每轮系统提示注入 |

### 2.2 写入

- 自动提取：对话结束后异步抽取，不能阻塞回复。
- 显式写入：`memory_write` / 管理页新增。
- 去重：完全重复直接复用；语义重复候选交给模型判定 skip/merge/update/create。
- 事实边界：只写用户明确表达或确认的信息；助手建议不能自动当用户偏好。
- 临时状态：题号、今日作业、单次进度不进 L2，进 L3/每日记忆。

### 2.3 检索

- 相关性：文本/语义相似度。
- 时效性：最近更新优先，避免旧事实压过新事实。
- 重要性：稳定规则/偏好权重高于一次性事件。
- 预算：记忆注入受 token 预算限制，不能挤占工具结果与对话历史。

### 2.4 纠错与遗忘

- 用户可查看、编辑、删除单条记忆。
- 批量整理：合并重复/互补条目，先预览再确认。
- 版本与撤销：每次修改保留旧版本；整次操作可撤销。
- 彻底删除：用户要求"忘掉"时，活动数据与历史快照都应处理。

### 2.5 隐私

- 记忆不跨用户；按智能体区分共享/专属；隐私会话不触发自动提取。
- 敏感信息识别与脱敏；日志不打印正文。
- 导出与删除满足合规；保留期可配置。

### 2.6 用户画像

- 与自由文本记忆分离，结构为 Markdown。
- 精确编辑：追加、唯一匹配替换、清空、全文重写。
- 并发保护：读取后他人已改，本次写入失败。
- 版本历史：每次修改保存快照，可查看/恢复。

### 2.7 技能（程序性记忆）

- 创建：从任务总结、从零编写、从工作区文件整理。
- 修改：读取原版本后局部修改，保留 ID 与完整旧版本。
- 附件：脚本、参考资料、模板作为不可变版本快照。
- 发现：按相关性 + 绑定关系注入摘要，正文按需读取；结构校验与真实执行证据分离。

## 3. 本项目现状

### 3.1 已具备

| 能力 | 实现 |
|---|---|
| 三层记忆 | `memories.layer` 取 L1/L2/L3；`MemoryService.get_memories_for_prompt` 按层组装 |
| 检索 | jieba 分词写入 `search_vec`，pg_trgm `similarity` 排序；L1 全量、L2 Top-K、L3 相关 + 最近各半 |
| 自动提取 | `extract_memories_from_conversation`：对话结束异步触发，每会话 180 秒节流；取最近 40 条 L1/L2 防重复；每轮最多 5 条 L2 + 1 条 L3 |
| 写入去重 | `reconcile_memory`：完全重复复用；L1/L2 候选为相关 12 条 + 最近 12 条，由模型判定 skip/merge/update/create |
| 并发保护 | PostgreSQL advisory lock 覆盖候选、模型判定与写入；等待上限 20 秒，超时失败不绕过 |
| 记忆工具与版本 | `memory_read/write/update/delete`；更新/删除要求 `expected_version` 并加行锁；`memory_versions` 存完整快照，`memory_changes` 支持整次撤销与版本恢复 |
| 记忆整理 | 预览最多 200 条；完全重复先合并，其余按相似度选最多 30 条交模型；预览服务端保存 1 小时；确认时校验快照，冲突返回 409 |
| 每日记忆与画像 | `daily_memories` 一人/智能体/天一条（东八区），00:40 汇总，L3 摘要实时追加；`user_profiles` 按 `(user_id, tenant_id)`，工具支持 create/append/replace/clear/overwrite |
| 画像并发保护 | 条件更新以读取原文为条件；冲突失败；每次修改前快照写入 `portrait_versions`（`source=ai`） |
| 画像生效 | 工具执行后 AgentLoop 重新读库并刷新系统提示，不依赖并行工具返回顺序 |
| 技能创建/修改 | `create_skill`、`update_skill`、`read_skill_file` 等工具；版本递增、完整快照、幂等回执、用户级 advisory lock |
| 技能发现与页面 | 检索相关技能 + 绑定技能，按 ID 去重，摘要含 ID/版本，至少保留一个绑定槽位；管理端列表/详情/版本下载，Portal "我的技能"只读入口 |

### 3.2 部分

| 能力 | 现状 | 缺口 |
|---|---|---|
| 自动提取范围 | 自动链路只写 L2 与 L3 | L1 只能手工/工具写入；没有自动识别"必须常驻规则"的稳定策略 |
| 检索质量 | pg_trgm 文本相似度，阈值默认 0.1 | 无语义向量、rerank、重要性衰减；同义表达召回有限 |
| 租户维度 | `memories.tenant_id` 已存；查询按 `user_id` + `agent_id` 过滤 | 同一用户属于多租户时，记忆查询未按 `tenant_id` 过滤，跨租户是否共享需确认 |
| 删除语义 | 删除前把快照写入 `memory_versions` / `memory_changes`，再删活动行 | "彻底删除"后历史快照仍保留正文，可被撤销恢复；与合规遗忘存在冲突 |
| 画像人工编辑 | 设置页使用人工全文保存接口 | 人工页面过期表单提交不具备工具的 `expected_portrait` 校验 |
| 技能能力 | `report_skill_result` 需版本、证据调用 ID、预期输出三项齐备，仅验证单次样例输出 | 主动建议/自动沉淀未实现；证据仅进程内缓存；团队共享/市场未实现 |

### 3.3 缺失

- 敏感信息识别与脱敏（手机号、证件、地址、密钥）。
- 记忆导出、按保留期清理、跨版本/备份的合规删除流程。
- 语义向量检索、重要性评分、主动遗忘与衰减。
- 租户级记忆策略配置（开关、保留期、可见范围）。
- 记忆质量指标（提取准确率、重复率、用户纠正率、注入命中率）。
- 记忆冲突的人工裁决界面（当前依赖编辑与整理）。
- 团队共享技能、技能市场、自动评测与回滚。

## 4. 关键设计

### 4.1 数据模型

- `memories`：`user_id`、`tenant_id`、`agent_id`（空=用户共享）、`layer`、`content`、`search_vec`、`metadata`、`version`（乐观锁）。
- `memory_versions`：`(memory_id, version)` 主键，保存完整快照、变更类型、操作 ID；`memory_changes` 保存一次操作前后状态与 `undone_by`。
- `memory_organize_plans`：服务端预览、原始快照、确认摘要与操作凭据。
- `daily_memories`：`(user_id, agent_id, date)` 唯一；`content`、`highlights`、`source_session_ids`。
- `user_profiles`：`(user_id, tenant_id)` 联合主键；`portrait_versions` 存快照与来源。
- `skills` / `skill_versions` / `skill_mutations`：当前技能、不可变版本快照、幂等回执。

### 4.2 写入与去重

1. 对话结束且非隐私会话，满足最小长度后异步触发提取。
2. 加载当前作用域最近 40 条 L1/L2，提示模型不重复提取；每轮最多 5 条 L2。
3. 每条写入调用 `reconcile_memory`，先取用户/智能体/层级维度的 advisory lock；完全相同的正文直接复用并合并标签/来源，不调用模型。
4. L3 走旧文本去重；L1/L2 取"相关 12 + 最近 12"候选，调用用户默认模型判定。
5. 非法 JSON、超时、伪造 ID 一律降级为新增，绝不覆盖旧正文；每条提交后释放锁，后续条目失败不回滚已成功条目。
6. 工具写入与自动写入共用该链路；手工编辑不保证与自动写入的全局去重。

### 4.3 检索与注入

1. L1 全量加载。
2. L2 按 `similarity(search_vec, tokenized_query)` 过滤阈值后取 Top-K；K 来自用户配置 `memory_top_k`。
3. L3 一半按相关性、一半按最近更新，去重后合并。
4. 每日记忆按日期与相关性裁剪后注入。
5. 用户画像独立注入，放在标记块内，正文以 JSON 字符串封装；记忆正文进入系统提示，不进入工具结果，注入失败不影响对话。

### 4.4 纠错、版本与整理

- 编辑：`PUT /api/memories/{id}` 可带 `expected_version`；不匹配返回 409。
- 删除/批量删除：先记录 `memory_changes` 与 `memory_versions` 快照，再删除活动行。
- 撤销：校验操作后没有新版本，整组恢复原 ID、正文、来源、标签与元数据；恢复版本要求 `expected_version`，恢复动作本身再生成一个新版本。
- 整理：预览无副作用；确认时锁定记录并比较完整快照，任一变化返回 409，不做部分合并。
- 每日记忆不参与整理；L3 普通 CRUD 留存版本，但不提供整理入口。

### 4.5 用户画像

- `read_user_portrait({})` 返回当前租户当前用户全文。
- `update_user_portrait` 必须显式 `operation`，只传对应字段；多余字段、空正文、NUL 在访问数据库前拒绝。
- `replace` 要求 `old_str` 精确且唯一匹配；找不到或多处匹配都拒绝，不能改用 `overwrite` 绕过。
- `clear` / `overwrite` 必须提供 `expected_portrait` 且与当前全文一致；每次成功修改前的非空画像写入 `portrait_versions`，正文未变化不新增快照。
- 工具批量执行后重新读库刷新提示，避免按并行结果顺序覆盖。

### 4.6 技能作为程序性记忆

- 创建：名称/描述/触发条件/正文/分类/标签 + 可选附件；正文最多 128 KiB，单附件 1 MiB，合计 10 MiB、50 个。
- 修改：必须带 `skill_id`、`expected_version`、非空 `change_summary`；未传字段保留，删除附件必须显式 `remove_files`。
- 版本与幂等：只有实际变化才递增，旧版 `object_key` 永不覆盖，完整快照存 `skill_versions.snapshot`；`(user_id, request_id)` 保存回执，重试返回原结果。
- 发现：相关技能优先占槽位，但保留至少一个绑定技能槽；主对话、委派、发布 API 共用同一选择逻辑。
- 部署：`/workspace/{workspace_slug}/skills/{skill_id}/v{version}/`，按版本隔离，不执行附件。

### 4.7 失败模式

| 场景 | 后果 | 当前处理 |
|---|---|---|
| 模型不可用/超时 | 记忆不写或降级新增 | 记录日志；自动提取失败静默返回空 |
| 并发写同一事实 | 可能重复 | advisory lock + 事务；手工编辑不受保护 |
| 模型把相似当同一事实 | 错误合并 | 只允许引用候选 ID；非法输出降级新增 |
| 用户删除后要求遗忘 | 历史快照仍含正文 | 未实现彻底清除，需产品与合规确认 |
| 画像并发修改 | 覆盖他人修改 | 条件更新 + 原文比较；人工页面无此保护 |
| 技能版本冲突 | 覆盖他人编辑 | `expected_version` + advisory lock；冲突返回最新版本 |
| 技能附件存储失败 | 出现缺件技能 | 带附件创建整体失败；纯文本允许仅存 DB |

## 5. 实施建议

### P0（交付阻断）

1. **明确删除语义**：区分"删除（可撤销）"与"彻底遗忘"；后者需清理 `memory_versions` / `memory_changes` 中的正文或做不可恢复脱敏，并提供审计记录。
2. **记忆查询补租户维度**：确认同一用户跨租户记忆是否应共享；若不共享，所有查询加 `tenant_id`，并补迁移与回归测试。
3. **敏感信息识别与脱敏**：写入前检测手机号、证件号、地址、密钥；可配置"拒绝写入/掩码存储"，日志不打印正文。
4. **自动提取可观测**：记录提取成功/失败、去重动作、模型耗时；失败不能只停留在日志。

### P1

5. **语义检索**：引入向量或混合检索，解决同义表达召回；保留 pg_trgm 作为降级路径。
6. **记忆导出与保留期**：用户可导出全部记忆与画像；按租户配置保留期，到期清理活动数据与版本。
7. **画像人工编辑一致性**：设置页保存也带 `expected_portrait` 或版本号，避免过期表单覆盖。
8. **技能主动建议**：在不自动写入的前提下，任务结束时提示"可保存为技能"，用户确认后创建。

### P2

9. 重要性评分、衰减与主动遗忘。
10. 团队共享技能、技能市场与技能评测集。
11. 记忆质量看板（提取准确率、重复率、纠正率）与跨会话学习进度的唯一事实源。

## 6. 验收标准

- [ ] L1 每轮全量注入；L2 只注入 Top-K；L3 相关与最近各半；每日记忆按日期裁剪。
- [ ] 相同事实重复写入只保留一条并合并来源，不调用判定模型。
- [ ] 换词表达的重复事实由模型判定后复用原 ID，不覆盖旧正文。
- [ ] 用户明确修改事实时更新原条目，旧正文可在版本记录查看。
- [ ] 非法 JSON、超时、越权 ID 均不能覆盖旧数据；两个并发自动写入相同事实只产生一条。
- [ ] 删除记忆后，用户可在修改记录中撤销并恢复完整原条目；"彻底删除"路径不保留可恢复的正文副本（待实现后验收）。
- [ ] 用户画像 `replace` 在歧义匹配时拒绝；`clear/overwrite` 在全文不一致时拒绝。
- [ ] 画像修改后当前对话下一轮使用最新内容，不依赖工具返回顺序。
- [ ] 自动提取在隐私会话中不触发，且不读取其他用户/智能体/层级的数据。
- [ ] 技能更新保留原 ID、只递增一次版本，未传字段与附件按原字节保留；版本冲突返回最新版本，重试不重复递增。
- [ ] 新会话能发现刚创建的个人技能，同时不挤掉 Agent 已绑定技能。
- [ ] 同一用户跨租户的记忆访问符合已确认的隔离策略。
