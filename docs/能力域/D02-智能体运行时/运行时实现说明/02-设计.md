# 运行时实现说明（后台任务、执行契约、运行环境）

> 合并说明：本文由 3 份原始文档合并，内容保持原样，仅调整标题层级。

## Web 对话后台执行与中断恢复

### 用户行为

- 普通聊天、智能体聊天、门户、宠物对话都使用后台任务。刷新、切换会话、离开页面、关闭宠物面板仅断开订阅。
- 再次进入会话自动查询任务，加载历史并从头重建该轮实时进度。通过任务 ID、事件序号和消息 ID 去重，不把回放重复追加到旧状态。
- 普通聊天地址增加 `/chat/:sessionId`，刷新和前进后退可定位对应会话。
- “停止”显式请求后端取消父任务及其委派子任务，保存已有进度。队列“立即发送”等待停止完成后才发送下一条，不再靠固定延迟猜测。
- 同一会话只能有一个运行中的 Web 任务。运行中会话必须先停止才能删除。
- 正常停机保存任务为中断；进程被强制终止时，心跳超出 30 秒后，在状态查询或订阅时标记中断。不会因另一副本启动而把健康任务误标为中断。
- 停止、失败、中断后的任务满足安全条件时显示“继续任务”。有结果未知或失败的工具调用时禁止一键续跑，提示先核对外部实际结果。

### 执行与持久化

`POST /api/chat/stream` 保留现有 SSE 形状，新增后台生产者。响应流只是 PostgreSQL 事件订阅者，不拥有 `AgentLoop` 的生命周期。

- `chat_runs`：任务归属、状态、执行进程、心跳、请求、快照、助手消息 ID、续跑来源。
- `chat_run_events`：按 `(run_id, sequence)` 排序的持久事件。
- 会话行锁和运行任务部分唯一索引共同防止并发重复启动。所有查询显式限制用户，新增表同时启用 RLS。
- 工具调用事件在推进 AgentLoop 到执行阶段前持久化，工具结果也在推进下一步前提交。文本增量按时间/条数批量提交；强制终止可能丢失最后尚未提交的文本批次。
- 运行任务每秒更新心跳并检查停止请求；数据库不可用或任务所有权失效时取消本地执行。旧执行者不能把已中断任务重新写为完成。
- 完成事件在任务终态提交后才发给订阅者，避免前端队列抢跑。完成事件已持久化后进程崩溃，会恢复为已完成。
- 删除会话同时删除任务和事件记录；当前没有额外的定时日志清理策略。

### 安全续跑的含义

续跑建立关联到原任务的新一轮，并使用持久化对话与工具结果继续。它不是 Python 调用栈恢复，也不会重新提交原始用户问题。

- 同名、同参数的已完成工具调用直接复用旧结果，包含连续多次续跑的结果；不再次执行对应外部操作。
- 存在没有持久成功结果的调用时，禁止一键续跑。即使错误响应已到达，外部系统也可能已产生副作用，因此不把失败自动视作安全重试。
- 工具结果未知时，历史消息明确标记未知，并补充符合模型协议的工具响应，避免缺少 `tool_call_id` 对应结果导致后续请求失败。
- 历史浏览器动作不会因事件回放而重新点击、输入或提交。离开页面后的浏览器工具仍受现有前台/超时约束；后端计算和工具调用可以继续。
- 保护针对已有调用记录和精确匹配的参数。修改参数的业务操作仍由正常工具权限、确认机制及用户核对约束，不能承诺外部系统的通用 exactly-once。
- 当前确认和浏览器动作管理器仍在进程内；多副本部署的确认/浏览器回包需要保持原有会话粘性。任务状态、事件重连和停止请求本身可跨副本访问。

### 新增接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/chat/sessions/{session_id}/run` | 最新任务状态和续跑条件 |
| GET | `/api/chat/runs/{run_id}/events?after=0` | 回放与实时订阅，`after` 为最后消费的序号 |
| POST | `/api/chat/runs/{run_id}/stop` | 明确停止，等待保存终态 |
| POST | `/api/chat/runs/{run_id}/resume` | 安全条件检查后建立续跑任务，并返回 SSE |

新增事件 `run`、`run_status` 携带任务 ID、状态、助手消息 ID、可续跑标志和结果不确定的工具列表。事件保留原有业务字段，并增加 `run_id`、`sequence`、`replay`。

### 迁移与验证

迁移版本：`e1f2a3b4c5d6`，前置版本 `d0e1f2a3b4c5`。发布时先执行 `cd backend && uv run alembic upgrade head`，再启动包含新代码的服务。

自动回归：

```bash
cd backend
uv run pytest tests/test_chat_runs.py tests/test_chat_turn_history.py tests/test_agent_time_context.py -q
uv run ruff check src/
uv run mypy src/

cd ../frontend
npm run test
npm run build
```

`test_chat_runs.py` 使用独立临时数据库，覆盖实际聊天路由断线后后台完成、多个订阅、持久事件游标、任务停止和子任务取消、过期心跳、消息抢救、归属隔离、重复启动、续跑保护及已完成工具结果复用。前端测试覆盖自动连接、切换会话只断开订阅、过期回调隔离、去重、显式停止及不安全续跑拦截。

本轮未连接业务数据库或真实模型；Docker 未运行，尚未做真实 PostgreSQL 锁/RLS 及线上重启验收。当前 Node 运行前端全量测试时需要 `NODE_OPTIONS=--no-experimental-webstorage`，避免 Node 自带实验性 localStorage 覆盖测试 DOM 的实现。

## 执行与接口契约

### 执行边界

`core/session_access.py` 统一会话归属、绑定智能体可见性、执行租户及成员状态校验。
执行与查询已有对象的接口使用 `ExecutionUser`，不先校验用户界面当前选中的租户。
聊天请求中的 `agent_id` 必须与已有会话一致；显式改绑只能在同租户且没有运行中任务时进行。

`ChatRun.request` 中的 `_execution_tenant_id`、`_execution_agent_id` 由服务端写入。
状态、回放、续跑及停止均复查来源对象；SSE 持续复查，失去权限时发送 `access_revoked` 并结束。
取消后的内部清理允许写入终态，不能因此恢复外部读取权限。缺失归属的历史无智能体任务拒绝访问和续跑，不自动回填。

### 公共执行准备

普通 HTTP、Web SSE、WebSocket 和已发布 API 使用 `ChatExecutionService.prepare`。
`PreparedExecution` 固定一次模型选择，历史中的图片格式与实际 provider 使用同一模型；会话模型覆盖仅适用于实时配置，已发布配置继续使用快照。
历史加载、记忆/技能/画像提示词组装和 AgentLoop 创建使用公共实现；发布快照明确的空提示词仍保留空值。
渠道、定时任务和房间保留各自的输入与持久化流程，共用 provider、工具过滤和 AgentLoop 工厂。

### 工具授权与确认

- 未绑定智能体不获得任何 MCP 工具；进程级 MCP 连接池不代表权限。调用时再次核验服务租户、启用状态和用户成员资格。
- 工厂读取当前执行用户的 `UserConfig.trust_level`，无设置时使用全局默认值。委派继承同一用户的策略。
- 普通工具遵循 `ask_always` 每次确认；`ask_dangerous` 确认危险内置工具、MCP、非只读 HTTP 工具和未声明权限的直接处理函数；`auto_all` 跳过这一层确认。工具白名单及沙箱校验仍然生效。本地浏览器使用独立的持久/单轮授权及逐命令确认，不重复套用普通工具确认。
- 确认在 AgentLoop 中等待，并通过事件队列通知前端。确认归属由服务端固定为执行租户，恢复和提交时复查成员资格，不受界面切换租户影响。只有 `approved` 执行原参数；拒绝、修改、超时、取消或缺少交互通道均不执行。
- 新增直接处理函数应通过 `register_direct_handler(..., permission_level=...)` 声明权限；未声明时视为危险。渠道投递工具显式声明 `write`，仍需各自的渠道上下文校验。

### HTTP 与流式契约

| 场景 | 契约 |
|---|---|
| 删除会话 | 仅由 sessions 路由注册，成功 `204`，无响应体 |
| Agent PATCH | 省略字段表示不修改；不可空字段显式 `null` 返回 `422`；允许清空的字段仍接受 `null` |
| Web SSE | `text/event-stream`；`data` 为 JSON，以 `type` 区分事件；持久化任务包含 `sequence` / `replay` |
| 已发布 SSE | `text/event-stream`；保留 `event:` 名称及 `text_delta.text` 字段 |
| 房间 SSE | `snapshot` 包含完整房间 DTO；权限撤销发送 `access_revoked` |
| 房间 / 本地浏览器 | 明确的响应 DTO；房间消息保留工具、附件等扩展字段 |

OpenAPI 中 SSE HTTP body 声明为字符串，`x-event-schema` 描述解码后的 JSON 数据。
`test_api_contracts.py` 检查重复路由、HTTP 状态码、媒体类型、响应 schema 和 PATCH 空值语义。
`test_execution_security.py` 覆盖真实 SQL 权限复查与批准/拒绝/超时/关闭行为。
前端 CI 在镜像任务之前执行测试；测试失败会阻止镜像构建与推送。

测试数据库必须使用显式传入的本机临时数据库，不读取或修复业务数据库。

## 运行环境查询

`get_runtime_info` 是后端直接执行的只读内置工具，用于回答“智能体运行在哪台设备”“当前是 macOS 还是 Linux”“沙箱是否可用”。不需要配置设备名称、设备 ID 或新的环境变量。

### 使用

默认调用参数为 `{}`；需要资源信息时传入：

```json
{
  "include_resources": true,
  "check_sandbox": true
}
```

`include_resources` 默认 `false`，`check_sandbox` 默认 `true`。关闭 `check_sandbox` 时完全不连接 Docker。工具遵循现有智能体工具白名单和信任级别规则，不绕过 `enabled_tools`、`allowed_tools` 或渠道工具黑名单。

### 返回内容与边界

| 字段 | 内容 |
| --- | --- |
| `collected_at` | 查询时刻，包含 UTC 偏移 |
| `device` | 设备显示名称、名称来源、hostname、基于 hostname 哈希生成的标识 |
| `os` | 系统、发行版、版本、内核、CPU 架构 |
| `runtime` | 后端进程位置、Python/平台版本、PID、实例标识、工具模块初始化时间与运行时长、容器检测证据 |
| `time` | 本地时区缩写和 UTC 偏移；缩写不等于 IANA 时区名 |
| `execution` | 当前已绑定的执行租户、智能体、会话和工作区标识 |
| `resources` | 可选：逻辑 CPU 数、进程可用 CPU 数、系统负载、内存及后端工作目录所在文件系统容量 |
| `sandbox` | 可选：Docker 连接状态及当前用户、当前部署的沙箱状态 |

- macOS 优先执行固定命令 `/usr/sbin/scutil --get ComputerName` 获取电脑名称，读取失败或一秒超时后回退 hostname；Linux 直接使用 hostname。
- 设备标识是 hostname 的哈希，不是硬件 ID。hostname 修改后标识会变化，同名设备也可能相同。实例标识仅用于区分后端进程。
- 后端运行在容器内时，返回容器中的可见信息，不能可靠确定物理宿主机名称。容器标记检测是启发式判断，未检测到标记不保证未容器化。
- 信息来自智能体编排后端，不是打开网页的设备或远程 LLM 服务。Docker 可能位于另一台设备，不能据此推断沙箱与后端共用宿主机。
- 资源标注为 `backend_os_view`，可能显示宿主机容量，不代表容器配额或沙箱资源。macOS 只报告物理内存总量，未测量的可用内存返回 `null`；无法读取的资源部分返回 `unknown`。
- 执行租户只从已绑定的执行上下文读取，不查询、缓存或写回用户界面当前租户。跨用户上下文会拒绝查询。该工具不构成新的智能体执行入口。
- 返回字段使用白名单，不枚举环境变量、密钥、网络接口、硬件序列号或完整路径。

### 沙箱检查和降级启动

检查使用独立的 Docker 客户端，每个请求一秒超时，不修改执行客户端的超时。只执行连接检查及当前用户固定容器名的 inspect，校验用户、部署、临时沙箱标签后才返回容器信息；不会枚举其他用户容器、创建或启动容器、执行命令、接管容器、同步文件或刷新空闲时间。

Docker 可连接不代表代码执行成功，因此返回 `execution_verified=false`。容器不存在返回 `not_created`；Docker 不可用时仍返回设备信息及脱敏错误原因。

`SandboxManager` 连接 Docker 改为异步懒加载。启动恢复遇到 Docker 连接错误时记录 `sandbox_startup_degraded` 并启动后台维护，不终止后端；其他数据库、配置和文件归属错误仍按原规则处理。需要沙箱的操作会重试连接，仍失败则明确报错；后台维护也会按现有周期重试恢复。实际执行超时保持原值，设备查询不触发恢复或清理。

### 验证

`backend/tests/test_runtime_info.py` 覆盖自动命名、系统和资源来源、只读沙箱查询、Docker 故障、白名单、并发租户上下文、异常及取消清理。`backend/tests/test_sandbox_lifecycle.py` 覆盖离线降级启动、连接恢复、安全关闭及原有容器生命周期约束。
