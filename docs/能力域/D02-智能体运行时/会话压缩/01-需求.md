# 会话压缩 — 需求

> 让长会话在上下文窗口接近上限时自动压缩历史、保留关键信息并释放 token 预算。技术实现见 [设计](02-设计.md)。

## 1. 背景与问题

Agent 在复杂编码、多轮调试、跨日恢复等长对话中会快速逼近模型上下文窗口。超限后，早期关键信息被简单截断，Agent 丢失决策上下文；prompt 长度线性增长推高 token 成本；工具调用历史占据大量预算，但绝大多数内容后续不再被引用。

现有实现只有基于字符的 token 估算、简单截断和基础摘要，缺少分阶段、可配置、可恢复的压缩策略。更关键的是，已压缩消息没有被标记，每次加载仍读取全量历史并重复摘要，压缩收益被抵消；压缩过程没有记录，无法解释“Agent 为什么忘了某件事”；前端也无法区分哪些历史已被压缩。

## 2. 目标

- 在会话接近上下文预算时自动压缩，无需用户干预。
- 压缩后仍保留用户显式指令、已做技术决策、关键文件路径和未解决问题。
- 丢弃寒暄、完整工具输出、中间推理和重复确认等低价值内容。
- 压缩结果可持久化、可增量累积、可审计、可被用户查看。
- 压缩失败不破坏会话可用性，不丢失原始历史。

## 3. 范围（纳入 / 不纳入）

纳入：

- 阈值触发的自动压缩，以及工具输出过大、用户主动、上下文溢出三类补充触发。
- 三级压缩：工具输出裁剪、历史轮次合并、LLM 结构化摘要。
- 保留最近若干轮原始消息作为热区，只压缩更早历史。
- 压缩结果的持久化、消息归档标记与历史摘要增量累积。
- 前端查看完整原始历史、压缩分界线与摘要内容。
- 用户主动触发压缩与压缩审计记录。

不纳入：

- 物理删除历史消息；原始消息必须保留。
- 记忆系统 L1/L2/L3 的压缩与维护；仅复用摘要模型与模板。
- 压缩策略的自动调优或按租户学习。
- 跨会话的全局摘要。

## 4. 功能需求

### 4.1 触发

- 每轮发送前估算上下文 token，达到预算阈值时自动压缩；阈值必须可配置。
- 工具输出特别大时，可先执行零成本的工具输出裁剪。
- 用户可通过指令或界面按钮主动触发压缩，主动触发应直接产出 LLM 摘要。
- 模型报告上下文溢出时，执行一次紧急压缩后重试。

### 4.2 保留与丢弃

- 必须保留：用户显式指令、已确认的技术决策、关键文件路径、未解决的问题。
- 必须丢弃：寒暄、完整工具输出、中间推理过程、重复确认。
- 最近若干轮原始消息作为热区保持不变，只压缩热区之前的历史；热区轮数可配置。
- 图片等内联大体积数据不得原样进入摘要输入。

### 4.3 分级压缩

- 第一级：裁剪超长工具输出，保留工具名、参数摘要与执行状态，完全确定性、不调用模型。
- 第二级：将热区之外的连续同主题轮次按工具调用链合并为摘要消息，仍不调用模型。
- 第三级：使用低成本模型生成结构化摘要，必须包含决策、指令、待办、关键路径四类信息。
- 每级完成后重新估算 token，低于阈值即停止，不继续升级。
- LLM 摘要失败时必须回退到前两级的结果继续推理，不得阻断本轮对话。

### 4.4 持久化与加载

- 被压缩的消息必须被标记归档，后续加载只取未压缩的活跃消息，避免重复读全量、重复摘要。
- 摘要以系统消息形式注入会话头部，并明确标识为历史摘要而非当前轮指令。
- 多次压缩时，新摘要必须带入上一次摘要的关键信息，避免信息断裂。
- 会话始终指向最新摘要，并记录累计压缩次数。
- 压缩结果、消息归档状态和会话摘要必须保持一致，不得出现摘要已生效但消息仍被重复加载的中间态。

### 4.5 可解释与可查看

- 每次压缩必须记录：触发原因、压缩前后 token 数、应用的压缩级别、使用的模型、耗时。
- 原始消息不得物理删除，用户在前端可查看完整历史。
- 前端必须能展示压缩分界线，并允许查看对应摘要。
- 累计压缩次数过高时，应提示用户新开会话。

### 4.6 隔离与失败处理

- 压缩必须按会话归属用户隔离，不得把其他用户的历史带入摘要。
- 压缩失败时不写入压缩结果、不标记消息，下一轮可重试。
- 同一会话多次触发压缩，结果应稳定，不重复丢失信息。

## 5. 非功能需求

- 延迟：单次压缩含模型摘要应控制在 5 秒内。
- 成本：摘要使用廉价小模型，单次成本控制在 0.01 美元以内。
- 可配置：阈值、热区轮数、摘要模型和压缩策略均可调整。
- 可观测：每次压缩的触发原因、前后 token、级别、耗时必须可查询。
- 兼容性：压缩不得改变前端查看完整历史的既有能力；已归档消息仍可被正常展示。

## 6. 验收标准

- [ ] 长会话达到阈值后，无需用户操作即自动产生压缩，下一轮正常继续。
- [ ] 压缩摘要中能找到用户显式指令、技术决策、关键文件路径和未解决问题。
- [ ] 寒暄、完整工具输出、中间推理和重复确认不出现在摘要中。
- [ ] 最近若干轮原始消息在压缩后仍逐字保留，更早历史才被压缩。
- [ ] 超长工具输出被裁剪为带截断标记的摘要，工具名、参数与状态仍在。
- [ ] 第二次压缩生成的摘要包含第一次摘要的关键信息，不出现信息断裂。
- [ ] 压缩后重新加载会话，只读取活跃消息，不会对已压缩消息再次摘要。
- [ ] 前端能查看全部原始消息，并在压缩处显示分界线与摘要入口。
- [ ] 用户主动触发压缩后，立即得到新的结构化摘要。
- [ ] 每次压缩均可查询触发原因、前后 token 数、压缩级别与耗时。
- [ ] 摘要模型调用失败时，本轮仍能基于前两级结果继续，且未写入半成品压缩记录。
- [ ] 不同用户会话的压缩互不串扰。
- [ ] 单次压缩耗时与摘要成本满足上述非功能指标。
