# D02 智能体运行时

> **解决什么问题**：一次用户请求如何被转换成可流式观察、可中断、可恢复的多轮推理与工具执行，并在上下文窗口内稳定完成。
> **适用读者**：后端运行时与接口开发、前端流式/任务恢复接入、测试与交付排障。
> **关联文档**：[D03 模型接入与治理](../D03-模型接入与治理/README.md) · [D04 工具与外部集成](../D04-工具与外部集成/README.md) · [D07 多智能体协作](../D07-多智能体协作/README.md) · [D13 可靠性与性能](../D13-可靠性与性能/README.md) · [能力全景 §5 D2](../../00-平台总览/README.md)
> **状态基准**：2026-11 代码。状态统一用 `已具备 / 部分 / 缺失`。

---

## 1. 边界

**负责**：
- 决策循环：ReAct、最大迭代、停止条件、并行与取消。
- 上下文工程：预算、截断、工具结果压缩、历史摘要、溢出兜底。
- 流式协议：事件模型、帧格式、序号与重放、客户端幂等依据。
- 后台执行：任务脱离请求生命周期、断线重连、停止、续跑。
- 状态与恢复：消息、快照、工具结果未知语义。
- 提示词组装、运行环境查询，以及运行时入口的执行/接口契约。

**不负责**：
- 模型目录、路由、配额与供应商密钥 → D03。
- 工具实现、MCP 连接与沙箱隔离 → D04。
- 多智能体编排策略与预算传播 → D07。
- 队列、容量、SLO 与多实例部署验证 → D13 / D14。

**设计底线**：每次执行必须有唯一 owner、单调事件序号和明确终态；没有代码支撑的压缩表、死循环检测、跨进程迁移，一律按“缺失”记录。

## 2. 能力清单

### 2.1 决策循环

| 能力 | 应该提供 | 关键设计点 / 坑 |
|---|---|---|
| ReAct 循环 | 推理 → 工具 → 结果注入 → 再推理 | 工具结果必须作为工具角色消息回填，且与调用标识一一对应 |
| 最大迭代与停止 | 硬上限、无工具调用终答、用户停止、超时、权限撤销 | 上限是兜底不是完成条件；取消要覆盖流式读取、工具执行、确认等待三段 |
| 死循环检测 | 连续重复工具调用/重复参数熔断 | 仅靠最大迭代会在烧掉大量 token 后才停 |

### 2.2 上下文工程

| 能力 | 应该提供 | 关键设计点 / 坑 |
|---|---|---|
| 窗口预算 | 总窗口减输出预留；达到比例自动压缩 | 预算应来自模型能力；阈值过低会频繁摘要，过高会撞硬限制 |
| 分层截断与工具压缩 | 保留热区；老消息与图片截断；工具结果近期全量、中期截断、远期摘要 | 图片内联数据必须剥离；迭代内压缩与跨轮摘要不能互相替代 |
| LLM 摘要 | 结构化保留决策、指令、待办、关键路径 | 摘要失败要有非 LLM 兜底；增量摘要要带入旧摘要 |
| 溢出兜底 | 模型报超长时激进裁剪后重试一次 | 只裁剪内存消息不落库，重试后仍可能再次超限 |
| 压缩持久化 | 标记已压缩消息，避免重复摘要 | 只保存摘要文本而不标记已压缩消息，下次加载仍读全量 |

### 2.3 流式协议

| 事件组 | 内容 | 用途 |
|---|---|---|
| 文本 | 文本增量、思考、推理 | 实时输出与推理展示 |
| 工具 | 工具调用、工具结果、文件变更 | 工具卡片、文件变更 |
| 交互 | 确认请求、确认完成、前端动作 | 人工确认与前端 UI 动作 |
| 任务 | 任务标识、状态、完成、错误、权限撤销 | 任务标识、终态、权限撤销 |
| 委派 | 子智能体开始/结束/思考/文本/工具/心跳 | 子智能体进度 |

**协议规则**：
- Web 流式事件为 JSON，以类型字段区分；持久任务额外携带任务标识、事件序号与回放标记。
- 已发布 API 的流式响应保留命名事件与文本增量字段；接口描述中声明解码后的事件结构。
- “完成”事件必须等任务终态提交后才发，避免前端抢跑下一轮；空闲连接发送保活心跳。
- 客户端按任务标识 + 序号去重，重连时以最后消费序号作为回放起点。
- 权限在订阅期间持续复查，失效时发送权限撤销事件并结束。

注意：事件模型与前端强耦合，当前没有 schema 版本号；任何字段改名都是破坏性变更。

### 2.4 并发、取消与确认

- 同一批工具中，委派并发启动，普通工具顺序执行；委派结果按原始调用顺序回填。
- 用户提问与前端界面动作类工具在运行时内拦截，不能进工具执行器，否则等待回包会死锁。
- 确认等待必须可分片（带心跳）并受超时约束；流式连接断开时取消并清理待确认状态。
- 取消后仍允许写终态，但不能借此恢复已撤销的外部读取权限；确认归属由服务端固定为执行租户，恢复和提交时复查成员资格。

### 2.5 后台执行

| 能力 | 应该提供 | 本项目做法 |
|---|---|---|
| 任务与请求解耦 | 断开订阅不终止执行 | 任务持久化，HTTP 响应只是事件订阅者 |
| 并发约束 | 同一会话最多一个运行任务 | 会话级并发控制 + 运行任务唯一约束 |
| 重连 | 按游标回放并继续实时订阅 | 事件按任务与序号读取 |
| 停止 | 显式取消父任务与子任务并保存进度 | 停止标记 + 本地执行取消 + 跨进程轮询 |
| 续跑 | 只在安全条件下允许 | 所有工具调用必须已有成功结果；否则提示先核对 |

**续跑语义**：续跑是“关联原任务的新一轮”，不是调用栈恢复，也不重新提交原始问题。同名同参数的已完成工具调用直接复用旧结果；结果未知的调用禁止一键续跑，因为失败响应也可能已在外部产生副作用。

### 2.6 状态与恢复

- 会话消息是长期事实；任务快照是任务级实时摘要，事件日志是权威重放依据。文本增量按时间或条数批量提交；工具边界在推进下一步前提交。
- 中断时未保存结果的工具调用标记为未知，并在历史里补一条符合模型协议的工具响应，避免缺少对应结果导致后续请求失败。
- 强制终止可能丢失最后一个尚未提交的文本批次；已完成事件已持久化时，进程崩溃会恢复为已完成。

### 2.7 提示词与运行环境

- 系统提示由模板组装，注入人格、记忆、技能、画像、工具清单与当前时间；发布快照明确的空提示词保持为空。
- 运行环境查询是后端直接执行的只读工具，返回设备、系统、后端进程、时区、执行上下文，可选资源与沙箱状态；不绕过工具白名单，也不构成新的执行入口。设备标识是主机名哈希，容器内只能看到容器视角；Docker 可连接不等于代码可执行，因此明确标注“未验证可执行”。

### 2.8 执行与接口契约

| 契约 | 要求 |
|---|---|
| 执行用户 | 已有对象的执行/查询先校验对象归属，不读取界面当前租户 |
| 会话绑定 | 请求中的智能体必须与会话一致；显式改绑需同租户且无运行中任务 |
| 不可变归属 | 执行租户与执行智能体由服务端写入，执行期内不可变 |
| 模型冻结 | 一次执行内固定模型，历史格式与供应商调用使用同一模型 |
| 删除会话 | 仅由会话入口提供，成功不返回响应体 |
| 流式响应 | 使用事件流媒体类型；接口描述声明事件数据结构 |

## 3. 本项目现状

### 3.1 已具备

| 能力 | 实现事实 |
|---|---|
| ReAct 循环 | 核心运行时实现完整 ReAct 循环，最多 100 轮（可配置） |
| 并行委派 | 普通工具串行，委派工具并发执行，结果按调用顺序回填 |
| 流式事件 | 类型化事件 + 兼容编码；事件集合由接口契约统一描述 |
| 流式断连重试 | 仅在本次迭代零产出时重试，最多 2 次，1 秒/2 秒退避 |
| 上下文预算 | 窗口 128k、输出预留 8k、阈值 0.75；第 4 轮起仅在接近阈值时压缩早期工具结果 |
| 跨轮摘要 | 截断后按预算分割，LLM 摘要 + 非 LLM 兜底；摘要增量折叠并节流 |
| 溢出兜底 | 识别上下文溢出错误并执行一级紧急压缩；同步接口与发布 API 会重试一次 |
| 后台任务 | 任务与事件持久化，心跳 1 秒、租约 30 秒、同会话唯一运行任务 |
| 重连与停止 | 按最后消费序号回放事件；停止请求等待终态 |
| 安全续跑 | 复用已完成工具结果；结果未知的任务禁止续跑 |
| 执行契约与运行环境 | 执行准备、会话访问、运行环境查询均有实现与契约测试 |

### 3.2 部分具备

| 能力 | 现状 | 缺口 |
|---|---|---|
| 取消与清理 | 停止会取消父任务和子任务 | 无轮次级墙钟超时；沙箱线程操作不可中断，只能等其结束 |
| 压缩持久化 | 摘要写入会话级摘要字段 | 没有消息级压缩标记与独立压缩记录，每次加载仍读全量并重复摘要 |
| 溢出重试 | 同步接口与发布 API 重试 | Web 后台流只发警告后报错，不重试；三条路径行为不一致 |
| 事件协议 | 序号与回放已用于去重 | 无 schema 版本；运行指标口径分散 |
| 多实例 | 任务状态、重连、停止可跨副本 | 确认与浏览器动作管理器仍在进程内，需要会话粘性 |

### 3.3 缺失

- 死循环主动检测（连续重复工具调用/参数）；轮次级墙钟超时与统一取消预算。
- 显式运行模式（Ask / Plan / Agent，含 Agent 全自动档）：当前只有动作级确认与信任级别，没有任务级模式选择、计划批准与模式切换；需求见 [运行模式](运行模式/01-需求.md)。
- 用户主动压缩与压缩审计的接口/界面；运行时指标的统一聚合口径（每轮 token、工具耗时、首字延迟）；提示词模板的运行时版本化归 D09。

## 4. 关键设计

### 4.1 状态模型

- 会话保存长期消息历史；一次 Web 轮次对应一个持久任务；任务下按序号保存持久事件。
- 任务状态包括：运行中、已完成、失败、已停止、已中断。
- 续跑条件：状态属于已停止/失败/已中断，且快照中不存在结果未知的工具调用。
- 任务快照只保存任务级摘要，事件日志才是重放事实源。

### 4.2 执行流程

1. 入口校验附件、会话与智能体一致性，加会话行锁并创建任务。
2. 执行准备冻结模型与供应商类型，加载历史并组装系统提示。
3. 估算 token；超阈值先截断再摘要；溢出时由入口决定是否紧急压缩重试。
4. 运行时以按需产出方式生成事件；生产者消费并批量持久化，HTTP 响应作为独立订阅者回放并实时接收。
5. 工具调用事件在进入执行前持久化，工具结果在推进下一步前提交；文本增量按时间或条数批量提交。
6. 终态由生产者提交后再通知完成；正常停机取消执行并写中断，停止请求写停止。

### 4.3 失败模式与防护

| 场景 | 后果 | 现有防护 |
|---|---|---|
| 流式连接断开 | 前端看不到进度 | 任务继续执行；按任务与序号重连回放 |
| 进程崩溃 | 任务卡在运行中 | 心跳超过 30 秒后，状态查询或订阅时标记中断 |
| 数据库抖动 | 心跳写入失败 | 无法证明所有权时取消本地执行（失败关闭） |
| 用户停止 | 子任务继续跑 | 取消父任务并取消已登记子任务；等待终态后才允许下一条 |
| 上下文溢出 | 模型拒绝请求 | 同步路径紧急压缩重试一次；后台路径仅告警 |
| 工具结果未知 | 续跑可能重复副作用 | 标记未知，禁止一键续跑，要求人工核对 |
| 重复启动 | 同一会话两个任务 | 会话并发控制，拒绝重复启动 |
| 权限撤销 | 继续读取数据 | 订阅期间复查，发送权限撤销事件并结束 |

## 5. 实施建议

**P0**

1. **死循环检测**：对“同名同参数工具调用连续出现 N 次”熔断，返回可解释错误并终止本轮。
2. **轮次级墙钟超时**：为整轮执行设置上限，覆盖模型流、工具执行、确认等待；超时走统一取消与终态写入。
3. **压缩持久化**：落地消息级压缩标记与独立压缩记录，加载时只取活跃消息，避免重复摘要。
4. **统一溢出重试**：Web 后台路径与同步路径使用同一套紧急压缩策略，避免行为分叉。

**P1**

5. 事件 schema 版本化，明确新增字段与破坏性变更规则。
6. 运行时指标统一：每轮 token、工具耗时、首字延迟、迭代次数进入同一聚合口径。
7. 确认与浏览器动作管理器外置，支持多副本无粘性部署。

**P2**

8. 用户主动压缩、压缩历史查询与“查看摘要”前端展示。
