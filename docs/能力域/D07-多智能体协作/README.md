# D07 多智能体协作

> **解决什么问题**：复杂任务需要分工，但多智能体一旦失控，权限、成本与故障会沿调用链放大。本域负责"谁能调用谁、调用时继承什么、失败如何隔离、结果如何还原"。
> **适用读者**：后端、平台架构、交付实施、安全评审。
> **关联文档**：[D02 智能体运行时](../D02-智能体运行时/README.md) · [D04 工具与外部集成](../D04-工具与外部集成/README.md) · [D08 交互与人机协同](../D08-交互与人机协同/README.md) · [D10 安全合规与审计](../D10-安全合规与审计/README.md) · [能力全景 §5 D7](../../00-平台总览/README.md)
> **状态基准**：2026-11 实现。状态只用「已具备 / 部分 / 缺失」，设计稿不等于已实现。

---

## 1. 边界

**本文负责**：协作模式、智能体层级关系、委派与群聊执行、权限与预算传播、并发与终止、协作可观测、跨平台协作协议。

**本文不负责**：单智能体推理循环与上下文压缩（D02）、工具自身的安全校验（D04）、租户与用户隔离模型（D01）、成本计量口径（D12）。本域只定义这些能力在"多智能体"场景下的传播规则。

**核心判断**：子智能体不能获得父级没有的权限，子任务不能突破父任务预算，任何一层都能被单独终止和还原。

## 2. 能力清单

### 2.1 协作模式

| 模式 | 要求 | 本项目状态 |
|---|---|---|
| 父→子委派 | 父智能体按需调用已关联子智能体，返回结构化结果 | 已具备 |
| 动态临时子智能体 | 运行时按角色描述生成临时专家，不落库 | 已具备 |
| 层级关系 | 多父多子有向无环图、防环、限深 | 已具备 |
| 群聊协作 | 多智能体入群、用户点名、顺序发言、共享上下文 | 已具备（MVP） |
| 主编排 / 路由分发 | 按能力或负载选择执行者 | 缺失（由模型自主选择替代） |
| 辩论 / 交叉评审 | 多角色互评、收敛结论 | 部分（聊天室支持人工组织的交叉评审，无自动辩论） |
| 自动讨论 | 多轮自主发言、主持人调度 | 缺失（明确不在 MVP） |

### 2.2 权限继承

- 子智能体工具集必须是父级授权集合的**子集**，不能通过委派提权。
- 子智能体沿用父级的用户、租户、工作区与信任级别，不因委派获得新资源。
- 前端执行类工具默认不授予子智能体，避免子智能体直接操作用户浏览器。
- 委派本身要求父级显式持有委派授权。

### 2.3 预算传播

- 子任务应共享父任务的 token / 时间 / 费用预算，超支即停。
- 需要能回答"这棵调用树一共花了多少、每个子任务花了多少"。
- 本项目当前只有**迭代次数与深度**约束，没有统一预算对象在父子间传递。

### 2.4 并发与顺序

- 同一轮的多个委派并行执行，总耗时取决于最慢者。
- 部分失败不影响其他分支，失败结果以工具错误回注父级，由模型决策。
- 群聊按用户点名顺序串行执行，后发言成员可读取前序公开消息。
- 需要可取消：停止父任务时，子任务与等待中的确认一起收敛。

### 2.5 可观测

- 每次委派记录父会话、父子智能体、深度、任务、状态、耗时、结果与错误。
- 前端能还原"哪个结论来自哪个子智能体"，包括子智能体内部的思考与工具调用。
- 能按会话查询委派历史，支撑审计与复盘。

### 2.6 协议兼容

- 跨平台协作应支持 A2A 等标准；工具侧复用 MCP。
- 本项目只实现了平台内部的函数调用式委派，未实现 A2A、跨租户或跨平台智能体互操作。

## 3. 本项目现状

### 3.1 已具备

- **层级关系**：父子关系为多对多，支持多父多子；创建与更新时检测环路；删除智能体时清理双向关系；提供子级、父级链与树形查询。
- **委派执行**：内置委派工具支持"已有子智能体"与"动态临时子智能体"两种模式；子智能体拥有独立运行时，不继承父级对话历史，复用父级会话与工作区。
- **并行与事件**：同一轮多个委派并发启动并统一收口；子智能体事件转换为委派事件推给父级事件流；心跳事件防止长任务被误判。
- **权限收敛**：子工具集与父级授权取交集；委派工具仅在深度未超限时注入；前端执行类工具强制排除；执行前校验租户、用户与父子关系。
- **深度防护**：工具过滤、处理器深度检查、配置上限（默认 3，最高 10）三层。
- **记录与展示**：委派记录保存深度、状态、耗时、结果与错误；支持按会话或单条查询；前端以委派卡片展示思考、工具调用与结果。
- **聊天室**：房间与成员、默认回答成员、点名与全体回答、串行执行、引用追问、共享上下文（摘要加近期消息）、确认、停止、失败重试、请求幂等、跨 worker 心跳，均有后端实现与前端页面。

### 3.2 部分具备

- **权限继承**：工具白名单是运行时过滤，不是显式的"能力清单"；知识检索与再委派由绑定关系自动注入，父级授权语义需靠交集兜底。
- **可观测**：委派记录预留了 token 用量字段，但委派链路未写入；耗时与状态完整，token 与费用不完整；前端以卡片呈现，缺全局调用树视图。
- **超时**：配置项中存在委派超时，但处理器未用统一超时包裹子运行时，实际超时控制不明确；工具元数据中的超时也未被执行器强制执行。
- **群聊总结**：房间有上下文自动摘要，但"用户点击总结讨论、输出共识/分歧/待确认/下一步"未实现。
- **失败隔离**：委派异常转为错误结果回注父级，但无重试、无熔断、无失败分支的预算回收。

### 3.3 缺失

- 统一预算传播（token / 时间 / 费用）与超支终止。
- A2A 协议、跨租户/跨平台智能体协作。
- 协作质量评估、子智能体结果可信度校验。
- 自动主持、有限轮次自动讨论、成员并行执行（聊天室明确排除）。
- 委派结果缓存与编排策略配置。

## 4. 关键设计

### 4.1 数据模型

- 父子层级采用多对多关系，形成有向无环图，由应用层维护；建立关系时向上遍历检测环路。
- 委派记录保存父会话、父子智能体、用户、深度、任务、上下文、状态、结果、错误、token 用量与耗时。委派按"函数调用"处理，不创建独立用户会话，避免污染用户会话列表。
- 聊天室分别保存房间、成员、一次运行、成员任务与公开消息。同一房间同时只允许一个活跃运行。

### 4.2 委派执行流程

1. 父级模型产出委派调用，参数可以是已有子智能体，也可以是角色名称与角色描述（动态临时子智能体）。
2. 父级运行时识别委派调用，为每个调用创建后台任务；普通工具与委派并发推进。
3. 处理器校验委派授权、深度、租户与父子关系，创建运行中的委派记录。
4. 构建子智能体：工具集取父级授权与子级配置的交集，并排除前端执行类工具；系统提示注入角色、记忆、技能与用户画像；模型按子级、父级、默认顺序回退；信任级别沿用父级。
5. 子智能体复用父级会话与工作区执行，事件转换为委派事件推给父级事件流。
6. 结果作为工具结果回注父级；失败与异常同样以错误文本回注，父级继续推理。
7. 更新委派记录并推送结束事件。

### 4.3 聊天室执行

- 用户提交一次运行：根据点名规则冻结目标成员与顺序，记录本次运行与各成员任务。
- 后台任务逐成员串行执行；每个成员构建独立运行时，禁用委派与前端工具。
- 成员输入包含房间目标、成员职责、历史摘要、近期公开消息、本次问题与引用内容。
- 运行监控定期检查停止请求与跨 worker 确认回包，并持续续租；进程中断时把未完成任务标记为停止或失败，不静默重跑。
- 同一请求幂等，多标签页不能绕过"单房间单运行"约束。

### 4.4 失败模式

| 失败 | 当前行为 | 风险 / 缺口 |
|---|---|---|
| 子智能体不可用 | 返回错误文本给父级 | 父级可能反复重试，无熔断 |
| 委派超时 | 依赖外部取消或工具超时，处理器未强制 | 长任务可能占住父级迭代 |
| 子级越权调用工具 | 交集过滤后不可见 | 自动注入工具绕过手工白名单的语义需持续审计 |
| 并行分支部分失败 | 失败分支单独回注，其他继续 | 无结果汇总者，成本仍已发生 |
| 聊天室成员失败 | 保留失败原因，其他成员继续 | 无自动补偿；重试需用户发起 |
| 服务重启 | 运行标记中断，不自动续跑 | 已发生的工具副作用不回滚 |
| 深度/环 | 三层防护拒绝 | 动态临时子智能体不产生关系边，环路概念不适用 |

## 5. 实施建议

### P0（先补边界，避免协作失控）

1. **统一预算对象**：委派上下文携带剩余 token 与时间预算，子运行时每轮扣减，超限终止并回注"预算耗尽"。
2. **强制单次委派超时**：用统一超时包裹子运行时，超时写入超时状态。
3. **补齐委派 token 用量**：从子运行时汇总并写入委派记录，再并入用户日用量。
4. **权限清单显式化**：委派时生成"父级授权与子级配置的交集"最终能力清单并记录，便于审计。

### P1（可观测与群聊闭环）

5. 前端增加会话级调用树视图，至少能展开/定位每个委派及其子委派。
6. 实现聊天室"总结讨论"：指定成员输出共识、分歧、待确认事项、下一步与缺失意见。
7. 委派失败增加有限重试与熔断，避免模型在同一失败分支反复消耗。
8. 增加跨 worker 的任务注册与取消广播，替代进程内登记（聊天室已有心跳与回包机制，可复用）。

### P2（协议与生态）

9. 评估 A2A 协议适配层，先做平台内智能体的标准描述与发现。
10. 委派结果缓存与按能力路由，作为成本优化项，不改变默认自主委派行为。
11. 协作质量评估：对子智能体输出做结构化校验（引用、产物、工具证据）。
