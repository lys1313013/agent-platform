# D05 知识与检索

> **解决什么问题**：让智能体在回答前拿到"对的资料"，并且只拿到调用者有权看的那部分；回答能指回原文，而不是凭空生成。
> **适用读者**：后端、前端、知识库管理员、安全评审、交付实施。
> **关联文档**：[D01 身份组织与权限](D01-身份组织与权限.md) · [D06 记忆与个性化](D06-记忆与个性化.md) · [D10 安全合规与审计](D10-安全合规与审计.md) · [能力全景 §5 D5](../企业级Agentic平台能力全景.md)
> **状态基准**：2026-11 代码。状态只用 `已具备 / 部分 / 缺失`；PRD 中的设计未实现的一律不计入已具备。

---

## 1. 边界

**本文负责**：
- 外部知识库接入（RAGFlow 数据集）与自建图谱知识库。
- 文档上传、解析、切分、实体关系抽取。
- 检索入口：`knowledge_retrieval`、`graph_retrieval`、文档读取/检索工具、大文件访问工具。
- 检索结果的权限过滤、来源信息与上下文注入。
- 知识库资源管理与 Agent 绑定。

**本文不负责**：
- 网页搜索与网页抓取 → D04 工具与外部集成。
- 工作区文件存储、沙箱生命周期与产物链路 → D04。
- 会话上下文压缩、会话摘要 → D02 智能体运行时。
- 用户记忆、画像与技能 → D06。
- 知识库操作的审计留痕与配额 → D10 / D12。

**设计底线**：检索必须同时满足三件事——**查得准**（召回相关片段）、**权限对**（在 SQL 条件里过滤，不是先查后删）、**可溯源**（能回到文档/页码/分块）。缺任何一项，知识库在企业环境里都不可用。

## 2. 能力清单

### 2.1 知识接入

| 接入方式 | 企业要求 | 关键点 |
|---|---|---|
| 文件上传 | 必须 | PDF/Office/图片/表格；大小与类型校验；工作区配额 |
| 网页抓取 | 常见 | 与知识库入库解耦，抓取结果可再入库 |
| 数据库同步 | 中大型企业 | 增量游标、字段映射、权限继承 |
| API 同步 | 常见 | 幂等、失败重试、删除传播 |
| 增量更新 | 必须 | 文档变更后索引可更新；删除可下架 |

### 2.2 解析

| 能力 | 说明 |
|---|---|
| 版面分析 | 标题层级、段落、列表、表格结构 |
| 表格抽取 | 保留单元格坐标；不把表格拍平成不可读文本 |
| OCR | 扫描 PDF、图片；中英文；失败要显式报错 |
| 公式/图表 | 可选；不支持时明确说明，不假装已解析 |

### 2.3 切分与索引

- 切分：固定长度、按结构（Markdown 标题/章节）、语义切分；必须有重叠与来源定位。
- 索引：向量、关键词（BM25/全文）、混合检索；元数据过滤（租户/知识库/文档/标签）。
- 重排：rerank 或融合排序；多知识库结果去重与稳定排序。
- 查询侧：查询改写、同义词扩展、实体链接。

### 2.4 检索

| 能力 | 最低要求 |
|---|---|
| 召回 | Top-K + 分数阈值；空结果明确返回 |
| 多库融合 | 并发查询、按分数合并、限制总量 |
| 上下文预算 | 单片段截断、总长度受控 |
| 降级 | 外部检索失败不影响对话主流程 |
| 评测 | 固定问题集、召回率/准确率、回归基线 |

### 2.5 权限

- 知识库级：租户 + `visibility`（tenant/private）+ 启用状态。
- 文档级：某文档只对指定用户/部门可见；段落级：敏感片段过滤（企业合规场景）。
- **硬性要求**：权限条件必须进入检索 SQL；不能先检索再按权限删除结果，否则会泄露"存在性/数量"。

### 2.6 溯源与治理

- 引用：文档标题、页码/章节/段落、分块 ID、原始链接。
- 生命周期：文档版本、更新、下架、删除传播；可信度：来源标记、人工复核状态、抽取置信度。
- 评测与运营：检索日志、命中率、无结果率、点击回流。

### 2.7 知识图谱

- 抽取：实体/关系三元组，带类型、描述、置信度、来源分块；同名实体归一化合并，同源同目标同类型关系去重。
- 复核：待确认/已采纳状态；未采纳数据不进入检索。
- 检索：实体链接 + 多跳子图遍历，结果可回到来源分块。
- 融合：与向量/关键词检索结果统一排序（长期目标）。

| 大文件工具 | `file_info`、`file_grep`、`file_query`（DuckDB SELECT）、`read_pdf`；`read_file` 1 MB 守卫与字符分页 |

| 工具结果文件 | 超过 50,000 字符时保存到 `tool-results/{uuid}.txt`，返回预览与读取入口 |

### 3.2 部分

| 能力 | 现状 | 缺口 |
|---|---|---|
| 统一检索抽象 | `knowledge_retrieval`、`graph_retrieval`、文档工具各自实现 | 没有统一 `SearchBackend` 接口；新增检索源需要改工具与 handler |
| 检索质量 | RAGFlow 外部召回；图谱按实体名相似度召回 | 无自研混合检索、rerank、查询改写；无评测集与指标 |
| 切分可控性 | 图谱自建切分；RAGFlow 切分在外部系统 | 平台无法统一控制 RAGFlow 的分块策略与索引参数 |
| 权限粒度 | 知识库级租户 + visibility；图谱文档继承知识库 | 无文档级/段落级 ACL；检索前过滤只到知识库级 |
| 溯源 | 图谱实体/关系保存 `source_chunk_id`；文档工具返回位置 | 图谱检索输出未带来源分块；RAGFlow 引用展示不完整；无统一 citation 契约 |
| 图谱抽取 | 异步任务、状态机、失败重试、同名实体合并 | 每次对全库分块重跑，不能按文档选择；上传后不自动触发；无增量抽取 |
| 扫描件 | 图谱上传支持 MinerU OCR 路径，需 `MINERU_API_TOKEN` | 未配置时明确报错 |
| 大文件分析 | `file_info` 有进程内分析缓存；`file_grep`/`file_query` 可用 | 无 `file_summarize`/`file_slice`；缓存不持久化；上传后不自动入库 |
| 文档治理 | 图谱文档可删除、删除后不参与抽取/检索 | RAGFlow 数据集无文档生命周期管理；无版本、失效下架、增量同步 |

### 3.3 缺失

- 文档级/段落级权限过滤。
- 混合检索与 rerank；`SearchBackend` 可替换抽象。
- 检索质量评测（黄金集、召回率/准确率、回归门禁）。
- RAGFlow 文档增量同步、删除传播、索引版本管理。
- 统一引用契约与前端可点击溯源；跨知识库结果去重与稳定融合排序。
- 知识来源可信度与内容审核流程。

## 4. 关键设计

### 4.1 数据模型

**RAGFlow 知识库**

- `knowledge_bases`：`tenant_id`、`name`、`dataset_id`、`description`、`is_active`、`created_by`、`visibility`。
- `agent_knowledge_bases`：`(agent_id, knowledge_base_id)` 复合主键；删除知识库时解除绑定。

**图谱知识库**

- `graph_knowledge_bases`：同知识库归属字段；无 `model_id`，当前使用租户默认模型。
- `graph_documents` / `graph_chunks`：文档原文与分块（`seq`、`content`、`chunk_count`）。
- `graph_entities`：`name`、`name_norm`（去空白小写）、`type`、`description`、`properties`、`source_chunk_id`、`status`；`(knowledge_base_id, name_norm)` 唯一。
- `graph_relationships`：`source_entity_id`、`target_entity_id`、`relation_type`、`confidence`、`source_chunk_id`、`status`。
- `graph_extraction_jobs`：`status`、`total_chunks`、`processed_chunks`、`entities_found`、`relationships_found`、`error`。
- `agent_graph_knowledge_bases`：Agent 与图谱知识库绑定。

### 4.2 RAGFlow 检索流程

1. Agent 绑定知识库后，`filter_tools_by_agent` 自动注入 `knowledge_retrieval`。
2. Handler 从 ContextVar 取 `agent_id`，用 `resolve_execution_tenant` 得到执行租户。
3. 查询绑定且启用的知识库，条件包含 `tenant_id`、`visibility=tenant` 或 `created_by=当前用户`。
4. 读取 `system_config` 中的 RAGFlow 地址与密钥；缺失时返回明确错误。
5. 对每个 `dataset_id` 并发 POST `/api/v1/dify/retrieval`，单库异常被忽略。
6. 合并记录、按 `score` 降序、截取 `top_k`；失败或空结果返回可读文本，由 Agent 决定继续回答或告知用户。

### 4.3 图谱构建与检索流程

**构建**：
1. 文档粘贴或上传；`.md/.txt/.html/.pdf/.docx` 直接解析，扫描 PDF 走 MinerU OCR 任务。
2. 按 Markdown 标题分段，每段按 800 字符切分、80 字符重叠。
3. 管理员触发抽取任务；同一知识库同时只允许一个 pending/running 任务，逐分块调用默认模型并要求 JSON 实体/关系，非法 JSON 计入失败分块。
4. 实体按 `name_norm` 去重；关系按 `(source, target, relation_type)` 去重；新数据默认 `pending`。
5. 管理员采纳后状态变为 `approved`；全部失败时任务标记 `failed`，可重试。

**检索**：
1. 查询绑定、启用、可见的图谱知识库。
2. 对查询分词，用 pg_trgm 相似度 + 子串匹配取 Top-5 实体作为种子。
3. 从种子出发用递归 CTE 扩展，默认 2 跳、最多 5 跳、最多 200 条边；只取 `approved`，序列化为实体清单 + 三元组清单返回 Agent。

### 4.4 文档与大文件访问

- 文档解析在沙箱 worker 中执行；路径必须位于当前工作区，拒绝越界与符号链接。
- 返回 `coverage`、`next_page`、`next_offset`，要求模型分批读取，不能把局部当全文。
- `read_file` 对超过 1 MB 的文件要求分页参数；超长工具结果转为工作区文件。
- `file_query` 只允许 SELECT，使用 DuckDB 直接查询 CSV/JSON/JSONL，禁止 DDL/DML/PRAGMA。

### 4.5 失败模式

| 场景 | 后果 | 当前处理 |
|---|---|---|
| RAGFlow 不可达 | 检索工具报错 | 返回错误文本，对话继续；无自动切换其他后端 |
| 单个 dataset 失败 | 少召回 | 忽略异常，其余结果照常合并 |
| 知识库被禁用/删除 | 不再召回 | 查询条件过滤；删除时解除绑定 |
| 图谱抽取全部失败 | 无新实体 | 任务 `failed` 并记录原因，可重试 |
| 部分分块失败 | 图谱不完整 | 任务仍 `done`，失败数只写日志，未在任务上展示 |
| 未采纳实体 | 不参与检索 | 检索只取 `approved` |
| 文档路径越界/符号链接 | 安全风险 | worker 拒绝 |
| 大文件直接读 | 上下文爆炸 | 1 MB 守卫 + 分页 + 工具结果文件 |

## 5. 实施建议

### P0（交付阻断）

1. **统一检索契约**：定义 `SearchBackend` 接口（`search(query, scopes, top_k) -> [Hit]`），RAGFlow、图谱、文档检索都实现它；工具层只依赖接口。
2. **统一引用结构**：`Hit` 必须包含 `source_type`、资源 ID、文档标题、位置（页码/章节/分块）、片段 ID；前端提供可点击溯源。
3. **知识库级权限收口**：把 `tenant_id + visibility + is_active + created_by` 的过滤抽成统一函数，禁止各 handler 各写一份。
4. **上传即可检索**：工作区上传文档后提供显式"加入知识库"动作，落到 RAGFlow 或图谱，不让用户手工复制 dataset ID。

### P1

5. **检索质量基线**：建立 30–50 条固定问答集，记录召回率、无结果率、引用正确率；每次改检索逻辑跑回归。
6. **图谱增量抽取**：按文档选择抽取、仅处理新增/变更分块；抽取失败分块在任务详情可见。
7. **混合检索**：关键词 + 向量 + 图谱结果融合排序；先做 RRF 等简单融合，再做 rerank。
8. **文档生命周期**：文档版本、更新、下架、删除传播；RAGFlow 侧至少提供手动重建入口。

### P2

9. 文档级/段落级 ACL。
10. 查询改写、同义词/术语表、知识来源可信度与内容过期提醒。
11. pgvector 语义实体链接与图谱/向量融合。

## 6. 验收标准

- [ ] Agent 未绑定知识库时，工具列表不出现 `knowledge_retrieval` / `graph_retrieval`。
- [ ] 绑定多个 RAGFlow 知识库时并发检索，单库失败不影响其他库结果。
- [ ] 检索条件在 SQL 层包含租户与可见性，普通用户无法召回其他租户或他人 private 知识库内容。
- [ ] 知识库禁用后立即不再参与检索；删除后 Agent 绑定同步解除。
- [ ] RAGFlow 未配置时返回明确错误，不抛出未处理异常。
- [ ] 图谱检索只返回已采纳实体/关系，未采纳数据不可见。
- [ ] 图谱 2 跳查询能召回"A 依赖 B、B 依赖 C"的间接关系，结果可追溯到来源分块。
- [ ] 扫描 PDF 未配置 MinerU 时给出明确错误；配置后可完成 OCR 入库。
- [ ] 上传 500 MB 文件成功入库；超过配额返回 413；文件可被 `file_info`/`file_grep`/`file_query` 访问；超过 1 MB 的 `read_file` 未带分页参数时被拒绝。
- [ ] 文档工具的返回包含页码/章节/单元格位置，分页游标可继续读取。
- [ ] 检索结果带统一引用字段，前端可点击回到原文。
