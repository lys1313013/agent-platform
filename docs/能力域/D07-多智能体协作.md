# D07 多智能体协作

> **解决什么问题**：复杂任务需要分工，但多智能体一旦失控，权限、成本与故障会沿调用链放大。本域负责"谁能调用谁、调用时继承什么、失败如何隔离、结果如何还原"。
> **适用读者**：后端、平台架构、交付实施、安全评审。
> **关联文档**：[D02 智能体运行时](D02-智能体运行时.md) · [D04 工具与外部集成](D04-工具与外部集成.md) · [D08 交互与人机协同](D08-交互与人机协同.md) · [D10 安全合规与审计](D10-安全合规与审计.md) · [能力全景 §5 D7](../企业级Agentic平台能力全景.md)
> **状态基准**：2026-11 代码。状态只用 `已具备 / 部分 / 缺失`，设计稿不等于已实现。

---

## 1. 边界

**本文负责**：协作模式、智能体层级关系、委派与群聊执行、权限与预算传播、并发与终止、协作可观测、跨平台协作协议。

**本文不负责**：单智能体 ReAct 循环与上下文压缩（D02）、工具自身的安全校验（D04）、租户与用户隔离模型（D01）、成本计量口径（D12）。本域只定义这些能力在"多智能体"场景下的传播规则。

**核心判断**：协作的第一性问题不是"编排得多花哨"，而是**边界是否可收敛**——子智能体不能拿到父级没有的权限，子任务不能突破父任务的预算，任何一层都能被单独终止和还原。

## 2. 能力清单

### 2.1 协作模式

| 模式 | 要求 | 本项目状态 |
|---|---|---|
| 父→子委派 | 父智能体按需调用已关联子智能体，返回结构化结果 | 已具备 |
| 动态临时子智能体 | 运行时按角色描述生成临时专家，不落库 | 已具备（`DynamicSubAgent`） |
| 层级关系 | 多父多子 DAG、防环、限深 | 已具备 |
| 群聊协作 | 多智能体入群、用户点名、顺序发言、共享上下文 | 已具备（MVP） |
| 主编排 / 路由分发 | 按能力或负载选择执行者 | 缺失（由 LLM 自主选择替代） |
| 辩论 / 交叉评审 | 多角色互评、收敛结论 | 部分（聊天室支持人工组织的交叉评审，无自动辩论） |
| 自动讨论 | 多轮自主发言、主持人调度 | 缺失（明确不在 MVP） |

### 2.2 权限继承

- 子智能体工具集必须是父级授权集合的**子集**，不能通过委派提权。
- 子智能体沿用父级的用户、租户、工作区与信任级别，不因委派获得新资源。
- 前端执行类工具（`ui_*`）默认不授予子智能体，避免子智能体直接操作用户浏览器。
- 委派本身要求父级显式持有 `delegate_task` 授权。

### 2.3 预算传播

- 子任务应共享父任务的 token / 时间 / 费用预算，超支即停。
- 需要能回答"这棵调用树一共花了多少、每个子任务花了多少"。
- 本项目当前只有**迭代次数与深度**约束，没有统一预算对象在父子间传递。

### 2.4 并发与顺序

- 同一轮的多个 `delegate_task` 并行执行，总耗时取决于最慢者。
- 部分失败不影响其他分支，失败结果以工具错误回注父级，由 LLM 决策。
- 群聊按用户点名顺序串行执行，后发言成员可读取前序公开消息。
- 需要可取消：停止父任务时，子任务与等待中的确认一起收敛。

### 2.5 可观测

- 每次委派记录父会话、父子智能体、深度、任务、状态、耗时、结果与错误。
- 前端能还原"哪个结论来自哪个子智能体"，包括子智能体内部的思考与工具调用。
- 能按会话查询委派历史，支撑审计与复盘。

### 2.6 协议兼容

- 跨平台协作应支持 A2A 等标准；工具侧复用 MCP。
- 本项目只实现了平台内部的函数调用式委派，未实现 A2A、跨租户或跨平台智能体互操作。

## 3. 本项目现状

### 3.1 已具备

- **DAG 层级**：`agent_relationships(parent_id, child_id)` 多对多；创建/更新时 BFS 检测环路；删除智能体清理双向关系；提供子级、树形查询接口。
- **委派执行**：`delegate_task` 直接处理器，支持"已有子智能体"与"动态临时子智能体"两种模式；子智能体独立 `AgentLoop`，无对话历史，复用父级 `session_id` 与 workspace。
- **并行与事件**：同一轮多个委派以 `asyncio.Task` 并发启动，`asyncio.gather` 收口；子智能体事件经 `event_queue` 转成 `delegation_*` 推给父级 SSE；心跳事件防止长任务被误判。
- **权限收敛**：子工具集与父级 `allowed_tools` 取交集；`delegate_task` 仅在深度未超限时注入；`ui_*` 前端工具硬排除；执行前校验租户、用户与父子关系。
- **深度防护**：工具过滤、handler 深度检查、配置上限（默认 3，上限 10）三层。
- **记录与展示**：`delegations` 表记录深度、状态、耗时、结果、错误；`/api/delegations` 支持按会话/单条查询；前端 `DelegationCard` 展示思考、工具调用与结果。
- **聊天室**：房间与成员、默认回答成员、`@` 点名/全体、串行执行、引用追问、共享上下文（摘要 + 近期消息）、确认、停止、失败重试、请求幂等、跨 worker 心跳，均有后端实现与前端页面。

### 3.2 部分具备

- **权限继承**：工具白名单是运行时过滤，不是显式的"能力清单"；知识检索与再委派由绑定关系自动注入，父级授权语义需靠交集兜底。
- **可观测**：`delegations.token_usage` 字段存在但委派链路未写入；耗时与状态完整，token 与费用不完整；前端以卡片呈现，缺全局调用树视图。
- **超时**：配置项 `delegation_timeout` 存在，但 handler 未用 `wait_for` 包裹子循环，实际超时控制不明确（需确认上游是否统一取消）；工具元数据 `timeout=300` 未被执行器强制。
- **群聊总结**：房间有上下文自动摘要，但需求中的"用户点击总结讨论、输出共识/分歧/待确认/下一步"未实现。
- **失败隔离**：委派异常转为错误结果回注父级，但无重试、无熔断、无失败分支的预算回收。

### 3.3 缺失

- 统一预算传播（token / 时间 / 费用）与超支终止。
- A2A 协议、跨租户/跨平台智能体协作。
- 协作质量评估、子智能体结果可信度校验。
- 自动主持、有限轮次自动讨论、成员并行执行（聊天室明确排除）。
- 委派结果缓存与编排策略配置。

## 4. 关键设计

### 4.1 数据模型

- `agent_relationships(parent_id, child_id, created_at)`：多对多 DAG，无外键，应用层维护；环路由 BFS 向上遍历检测。
- `delegations`：`parent_session_id / parent_agent_id / child_agent_id / user_id / depth / task / context / status / result / error / token_usage / duration_ms`。委派是"函数调用"而非独立会话，避免污染用户会话列表。
- `chat_rooms`、`chat_room_members`、`chat_room_runs`、`chat_room_tasks`、`chat_room_messages`：房间、成员、一次运行、成员任务、公开消息。`chat_room_runs` 用部分唯一索引保证同一房间同时只有一个活跃运行。

### 4.2 委派执行流程

1. 父级 LLM 产出 `delegate_task(child_agent_id | role_name/role_description, task, context)`。
2. AgentLoop 识别委派调用，为每个调用创建后台任务；普通工具与委派并发推进。
3. Handler 校验 `delegate_task` 授权、深度、租户与父子关系；创建 `Delegation(status=running)`。
4. 构建子智能体：工具集取交集并过滤 `ui_*`；系统提示注入角色、记忆、技能与用户画像；模型按子级→父级→默认回退；信任级别沿用父级。
5. 子 `AgentLoop` 使用父级 `session_id` 与 workspace 执行，事件转 `delegation_*` 推给父级 SSE。
6. 结果回注为父级工具结果；失败/异常同样回注为错误文本，父级继续推理。
7. 更新委派记录并推送 `delegation_end`。

### 4.3 聊天室执行

- 用户提交一次运行：根据点名规则冻结目标成员与顺序，写 `chat_room_runs` 与 `chat_room_tasks`。
- `rooms/runtime.py` 由后台任务逐成员串行执行；每成员构造独立 `AgentLoop`，禁用 `delegate_task` 与前端工具。
- 成员输入包含房间目标、成员职责、历史摘要、近期公开消息、本次问题与引用。
- 运行监控协程每 0.5s 检查停止请求与跨 worker 确认回包，每 5s 续租；进程中断时把未完成任务标记为 `stopped/failed`，不静默重跑。
- 同一 `request_id` 幂等，多标签页不能绕过"单房间单运行"约束。

### 4.4 失败模式

| 失败 | 当前行为 | 风险 / 缺口 |
|---|---|---|
| 子智能体不可用 | 返回错误文本给父级 | 父级可能反复重试，无熔断 |
| 委派超时 | 依赖外部取消或工具超时，handler 未强制 | 长任务可能占住父级迭代 |
| 子级越权调用工具 | 交集过滤后不可见 | 自动注入工具绕过手工白名单的语义需持续审计 |
| 并行分支部分失败 | 失败分支单独回注，其他继续 | 无结果汇总者，成本仍已发生 |
| 聊天室成员失败 | 保留失败原因，其他成员继续 | 无自动补偿；重试需用户发起 |
| 服务重启 | 运行标记中断，不自动续跑 | 已发生的工具副作用不回滚 |
| 深度/环 | 三层防护拒绝 | 动态临时子智能体不产生关系边，环路概念不适用 |

## 5. 实施建议

### P0（先补边界，避免协作失控）

1. **统一预算对象**：在 `DelegationContext` 中携带剩余 token/时间预算，子循环每轮扣减，超限终止并回注"预算耗尽"。
2. **强制单次委派超时**：handler 用 `asyncio.timeout(settings.agent.delegation_timeout)` 包裹子循环，超时写 `status=timeout`。
3. **补齐委派 token 用量**：从子循环 usage 汇总写入 `delegations.token_usage`，再并入用户日用量。
4. **权限清单显式化**：委派时生成"父级授权 ∩ 子级配置"的最终能力清单并记录，便于审计。

### P1（可观测与群聊闭环）

5. 前端增加会话级调用树视图，至少能展开/定位每个委派及其子委派。
6. 实现聊天室"总结讨论"：指定成员输出共识、分歧、待确认事项、下一步与缺失意见。
7. 委派失败增加有限重试与熔断，避免 LLM 在同一失败分支反复消耗。
8. 增加跨 worker 的任务注册与取消广播，替代进程内登记（聊天室已有心跳与邮箱，可复用）。

### P2（协议与生态）

9. 评估 A2A 协议适配层，先做平台内智能体的标准描述与发现。
10. 委派结果缓存与按能力路由，作为成本优化项，不改变默认自主委派行为。
11. 协作质量评估：对子智能体输出做结构化校验（引用、产物、工具证据）。

## 6. 验收标准

- [ ] 父智能体无 `delegate_task` 授权时，调用被拒绝且不产生子任务。
- [ ] 子智能体工具集严格是父级授权的子集，`ui_*` 永不下放。
- [ ] 超过 `max_delegation_depth` 时，工具列表移除委派工具且 handler 二次拒绝。
- [ ] 同一轮两个委派并行执行，总耗时接近较慢者而非两者之和。
- [ ] 一个委派失败/超时不影响同轮其他委派，父级收到可读错误。
- [ ] 子智能体与父级共享 workspace，可读取父级创建的文件。
- [ ] 委派记录可按会话查询，包含父子名称、深度、状态、耗时与结果。
- [ ] 父任务停止后，子任务与等待中的确认随之收敛，不残留"运行中"。
- [ ] 聊天室同一时间只允许一个运行，重复请求不重复创建运行。
- [ ] 聊天室点名顺序与实际执行顺序一致，未点名成员不执行。
- [ ] 聊天室成员不能通过 `delegate_task` 扩大本次执行范围。
- [ ] 进程重启后，中断的运行明确标记，不永久显示执行中、不静默重跑。
- [ ] 委派链路可回答"这次协作总共消耗多少 token"（当前未满足）。
