# D03 模型接入与治理

> **解决什么问题**：模型是平台唯一不可控的外部依赖。企业要求模型可替换、可降级、可审计、可算账，而不是把供应商密钥硬编码在代码里。
> **适用读者**：后端、SRE、平台管理员、交付实施、安全合规。
> **关联文档**：[D02 智能体运行时](../D02-智能体运行时/README.md) · [D11 可观测性与运营](../D11-可观测性与运营/README.md) · [D12 成本与配额](../D12-成本与配额/README.md) · [能力全景 §5 D3](../../00-平台总览/README.md)
> **状态基准**：2026-11 代码。状态只用 `已具备 / 部分 / 缺失`；与旧文档冲突处以代码为准。

---

## 1. 边界

**本文负责**：供应商接入、模型目录、模型选择与降级、密钥保管、调用超时/重试/限流、LLM 调用留痕、模型侧合规元数据。

**本文不负责**：提示词工程与上下文压缩（D02）、工具契约（D04）、计费与配额（D12）、平台级监控大盘（D11）、供应商商务合同。

**核心原则**：

1. **模型目录是唯一事实源**。运行时不得依赖环境变量里的模型名或代码内默认值。
2. **租户隔离先于便利**。模型、供应商、密钥都必须按租户解析，禁止跨租户回退。
3. **降级必须显式**。切换模型/供应商要可解释、可审计，不能静默换成更贵或能力更弱的模型。
4. **密钥不进日志、不进提示词、不进接口响应**。
5. **每次调用都有账**：模型、参数、token、耗时、错误码、重试次数。

| 能力域 | 企业级要求 | 本项目对应 |
|---|---|---|

## 3. 本项目现状

### 3.1 已具备

| 能力 | 实现事实 |
|---|---|
| 供应商/模型后台管理 | 供应商与模型由管理后台维护，支持增删改查、启用/停用、设置租户默认模型 |
| 租户隔离 | 所有管理查询按租户过滤；模型解析同样按租户过滤 |
| 模型发现 | 调用供应商的模型列表接口拉取可用模型，支持批量导入、去重、首个模型自动设为默认 |
| 两类供应商适配 | 供应商类型限定为 OpenAI 兼容与 Anthropic 原生；OpenAI 兼容端点通过自定义基础地址接入 |
| 模型能力字段 | 以多模态标记决定是否允许图片输入，替代按模型名猜测 |
| 模型选择 | 智能体绑定模型（启用且同租户）→ 租户默认模型 → 明确报错 |
| 多模态校验 | 构建调用时检查模型与执行租户一致；任务与后台执行复用同一工厂 |
| 超时与重试 | 客户端超时 120 秒（连接 10 秒）；瞬时错误最多重试 3 次，指数退避 1/2/4 秒；智能体可关闭重试 |
| 错误归一 | 错误归一为超时、连接、限流、服务端、无效请求、未知等类别 |
| 工具 Schema 降级 | 供应商拒绝某个工具 Schema 时，移除该工具后重试，避免整次调用失败 |
| 调用留痕 | 调用日志记录模型、供应商、token、缓存 token、首字延迟、耗时、吞吐、重试、状态、错误、停止原因、温度、最大输出、工具数 |
| 可观测接口 | 管理员可查询概览、Trace、聚合、工具排行与质量指标 |
| Langfuse（可选） | 可选的 Langfuse 接入；未配置密钥时自动禁用 |

### 3.2 部分具备（设计存在，落地不完整）

| 事项 | 代码事实 | 影响 |
|---|---|---|
| 密钥加密 | 字段名为“加密密钥”，但创建/更新直接存明文，代码留有加密待办 | 数据库泄露即密钥泄露 |
| 供应商覆盖 | 只有 OpenAI/Anthropic 适配器；Azure、Bedrock 的原生鉴权/部署名未实现 | 企业多云接入需改代码 |
| 模型目录 | 没有上下文窗口、价格、最大输出、工具调用能力、限流、健康状态字段 | 路由与配额缺少依据 |
| 路由/降级 | 仅“指定模型不可用 → 租户默认模型”；供应商故障不会切备用模型 | 主模型故障只能失败 |
| 调用治理 | 无供应商级/模型级限流、并发上限、熔断；重试次数固定为 3 | 高峰期可能放大故障 |
| 上下文观测 | 调用日志有上下文窗口与利用率字段，但客户端未写入 | 上下文利用率报表失真或为空 |
| 配置项 | 存在超时与最大输出配置项，但运行时未生效，客户端使用硬编码超时 | 配置不生效 |
| 成本留痕 | 调用日志没有费用字段；每日 token 统计中的费用恒为 0 | 无法按模型算钱 |
| 合规 | 无数据出境、训练使用、供应商 DPA、数据驻留标记 | 企业采购无法核对 |
| 供应商启用校验 | 解析模型时只校验模型启用状态，未校验供应商启用状态 | 已停用供应商仍可能被调用 |

### 3.3 缺失

- 按任务类型/成本/延迟的主动路由与故障转移。
- 熔断、限流、并发隔离、幂等键。
- KMS/密钥轮换与密钥使用审计。
- 模型价格表与费用计算（见 D12）。
- 模型灰度、A/B、按部门/租户的模型白名单。
- 供应商 SLA 看板、健康探测与自动摘除。
- 数据出境/训练使用等合规元数据。

## 4. 关键设计

### 4.1 数据模型

**现状**：

- 供应商记录：所属租户、名称、类型、基础地址、加密密钥占位、启用状态。
- 模型记录：所属租户、所属供应商、名称、底层模型标识、多模态、默认、启用状态。

**目标模型（未实现）**：模型目录增加——

- 上下文窗口、最大输出 token。
- 能力标签：工具调用 / 视觉 / 结构化输出 / 推理。
- 输入与输出单价、限流阈值。
- 健康状态（健康 / 降级 / 不可用）。
- 数据驻留区域与“不用于训练”标记。

价格与合规字段是 D12 与 D10 的输入，必须与模型目录同源，不能分散在环境变量。

### 4.2 模型解析与调用流程

1. 优先使用智能体绑定模型：必须同租户且启用。
2. 否则使用租户默认模型：必须启用。
3. 都没有则明确报错，不跨租户回退。
4. 解析后校验模型所属租户与执行租户一致。
5. 构建供应商调用；工具 Schema 被拒时逐个移除并重试。
6. 仅瞬时错误做退避重试；成功与失败都记录调用。

**设计约束**：模型不可用必须有明确错误；默认模型回退只解决“未配置”，不能掩盖“供应商故障”。目标方案是增加路由策略与健康探测，按优先级列表尝试，而不是单点回退。

### 4.3 调用治理

| 机制 | 现状 | 目标 |
|---|---|---|
| 超时 | 硬编码 120 秒，连接 10 秒 | 模型级可配置，读取配置项 |
| 重试 | 3 次，1/2/4 秒，仅瞬时错误 | 可配置次数/基数；尊重供应商返回的重试等待时间 |
| 限流 | 无 | 供应商/租户级每分钟请求与 token 限额，令牌桶 |
| 并发 | 无模型级上限 | 信号量/队列，防止打爆供应商 |
| 熔断 | 无 | 连续失败自动摘除，半开探测 |
| 幂等 | 无 | 外部调用可传幂等键 |

### 4.4 观测与留痕

- 调用日志是事实源，包含链路、会话、用户、租户、智能体、模型与调用次序，可按人、按智能体、按模型下钻。
- 追踪记录做汇总，每日指标做预聚合。
- **不存输入输出正文**，只存大小与 token，降低泄露面。
- 已知缺口：上下文窗口与利用率未写入；费用恒为 0；无指标导出与告警。

### 4.5 失败模式

| 场景 | 当前行为 | 风险 | 目标 |
|---|---|---|---|
| 主供应商宕机 | 重试 3 次后失败 | 对话不可用 | 健康探测 + 备用模型切换 |
| 触发限流 | 退避重试后失败 | 高峰期雪崩 | 令牌桶排队 + 尊重重试等待 |
| 模型被停用/删除 | 静默回退租户默认模型 | 可能换成更贵/更弱模型 | 显式降级事件与审计 |
| 工具 Schema 被拒 | 移除该工具后重试 | 能力静默缺失 | 记录被移除工具并告警 |
| 上下文超长 | 归为“无效请求”错误 | 归因不准 | 单独错误类型 + 压缩/截断提示 |
| 密钥泄露 | 明文存库 | 直接产生费用与数据风险 | KMS 加密 + 轮换 + 使用审计 |
| 跨租户模型引用 | 拒绝并报错 | 无 | 保持 |
| 供应商停用但仍被解析 | 可能继续调用 | 违反管理意图 | 解析时校验供应商状态 |

## 5. 实施建议

### P0（上线阻断）

1. **密钥加密**：用 KMS/信封加密替换明文存储；接口只返回“是否已配置密钥”；补密钥轮换与最后使用时间。
2. **模型目录补关键字段**：上下文窗口、最大输出、能力标签、价格；采集侧写入上下文利用率。
3. **解析校验供应商状态**：解析模型时同时校验供应商是否启用。
4. **超时配置生效**：读取超时配置项，支持按模型覆盖。
5. **显式降级事件**：默认模型回退、Schema 移除工具都要写结构化日志并可在观测页看到。

### P1（生产运营）

6. 供应商/模型级限流与并发上限；优先在网关层做。
7. 熔断与健康探测：连续失败摘除，半开恢复。
8. 备用模型路由：按优先级列表 + 成本/能力约束；禁止跨租户。
9. 模型价格表接入 D12，调用级费用落库。
10. 供应商 SLA 看板：可用率、P95、错误率、限流次数。

### P2（企业增强）

11. Azure/Bedrock/本地推理适配器。
12. 按部门/项目的模型白名单与预算联动。
13. 合规元数据与数据出境标记，接入 D10 审计。
14. 模型灰度与影子流量对比。
