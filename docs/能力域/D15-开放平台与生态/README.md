# D15 开放平台与生态

> **解决什么问题**：平台价值 = 自身能力 × 可被集成程度。本篇回答外部系统如何调用智能体、平台如何主动推送事件、第三方如何扩展能力，以及当前开放面与生态缺口在哪里。
> **适用读者**：平台架构师、集成/生态开发者、解决方案与交付团队、安全评审。
> **关联文档**：D01（身份与权限）、D02（运行时）、D04（工具与外部集成）、D08（人机协同）、D09（智能体生命周期）、D10（安全合规）。
> **状态基准**：2026-11 主干版本。状态仅用「已具备 / 部分 / 缺失」，规划能力不计为已实现。

## 1. 边界

**本篇覆盖**
- 开放 API：智能体执行、会话创建、流式对话、消息与反馈、版本发布、API 文档元数据。
- 鉴权与租户：外部调用者身份、执行租户、已发布配置快照。
- 事件与 Webhook：生命周期事件、签名、重试、失败语义。
- 扩展机制：MCP、自定义 HTTP 工具、技能包、Hook、渠道适配器、斜杠命令。
- 标准化：MCP、A2A、OpenAI 兼容接口的现状与差距。
- 开发者体验：开放接口规范、SDK、文档、沙箱环境、变更日志、市场。

**本篇不覆盖**
- 内部工具执行与沙箱安全细节（D04）。
- 智能体版本质量、评测、灰度与回滚（D09）。
- 渠道内部的会话映射、消息去重与重试（D08）。
- 平台自身管理端 API 的完整清单（D01/D08）。
- 计费、配额执行与成本分摊（D12）。

**关键边界判断**
- “开放 API 可用”不等于“开放平台成立”。当前 API 面向登录用户令牌，缺少服务身份、SDK 与开发者门户，属于可集成但未产品化。
- Hook 是平台主动推送的雏形，但事件配置、日志查询和订阅管理尚未开放，不能等同于对外 Webhook 产品。
- MCP 目前是平台作为客户端接入外部工具；平台自身尚未作为 MCP Server 对外暴露能力。

## 2. 能力清单

### 2.1 开放 API

| 能力 | 说明 | 当前状态 |
|---|---|---|
| 同步一次性执行 | 发送一条消息并同步等待完整回答 | 已具备 |
| 创建外部会话 | 为外部系统创建独立会话 | 已具备 |
| SSE 流式对话 | 以服务端推送事件逐段返回回答 | 已具备 |
| 会话历史 | 获取会话内的消息记录 | 已具备 |
| 清空会话 | 清空上下文并生成新的会话上下文 | 已具备 |
| 删除会话 | 删除外部会话 | 已具备 |
| 消息反馈 | 对指定回答提交正/负反馈 | 已具备 |
| 版本列表/发布 | 发布需管理员/所有者权限 | 已具备 |
| API 文档元数据 | 返回调用方式与版本信息 | 已具备 |
| 服务账号 / API Key | 无 | 缺失 |
| 每调用方限流与配额 | 无 | 缺失 |
| 请求幂等键 | 无 | 缺失 |

**执行前置条件**：智能体必须存在已生效的发布版本；执行使用版本快照中的模型、提示词、工具与知识库配置，而不是实时配置。未发布时拒绝执行。

### 2.2 事件与 Webhook

| 事件 | 触发点 | 负载要点 | 当前状态 |
|---|---|---|---|
| 会话开始 | Agent 开始执行 | 用户输入（截断）、模型、迭代上限 | 已具备（引擎） |
| 会话结束 | 完成/超迭代/异常 | 状态、耗时、迭代数、token | 已具备（引擎） |
| 工具执行前 | 工具执行前 | 工具名、参数（脱敏）、执行类型 | 已具备（引擎） |
| 工具执行后 | 工具执行后 | 成功与否、错误类型、耗时、输出摘要 | 已具备（引擎） |
| 上下文压缩前/后 | 压缩前后 | 压缩前后 token、节省量 | 已具备（引擎） |
| 异常通知 | 权限拒绝、上下文告警、超迭代、工具失败 | 级别、分类、说明 | 已具备（引擎） |
| Hook 配置管理 API | 无 | 无 | 缺失 |
| Hook 触发日志查询 API | 无 | 无 | 缺失 |
| 对外事件订阅/重放 | 无 | 无 | 缺失 |

**投递语义**：进程内有界队列 + 执行单元，异步非阻塞；队列满丢弃并告警；动作失败静默，只写执行日志；Webhook 支持签名、自定义请求头、超时与有限重试；沙箱命令通过固定负载文件接收事件数据。

### 2.3 扩展机制

| 扩展点 | 形态 | 管理方式 | 当前状态 |
|---|---|---|---|
| MCP | 外部 MCP Server 工具 | 管理员配置，租户级 | 已具备 |
| 自定义 HTTP 工具 | REST 映射为函数调用 | 管理员配置，当前全局 | 已具备 |
| 技能包 | 声明文件 + 文件的压缩包，版本化存对象存储 | 用户级创建/更新/部署 | 已具备 |
| Hook | 生命周期事件 → Webhook / 沙箱命令 | 数据库配置，无管理端 | 部分 |
| 渠道适配器 | 飞书、企微、企微机器人 | 管理员配置绑定 | 已具备 |
| 斜杠命令 | 命令注册表 + 动态技能命令 | 前端命令菜单 | 已具备 |
| CLI | 本地对话入口 | 本地交互式命令行 | 部分（占位实现） |
| 嵌入组件 / SDK | 无 | 无 | 缺失 |
| 插件/工具市场 | 无 | 无 | 缺失 |

### 2.4 标准化

| 标准 | 现状 | 说明 |
|---|---|---|
| MCP | 已具备（客户端） | 支持 SSE / Streamable HTTP；未作为 Server 暴露平台能力 |
| A2A | 缺失 | 跨平台智能体互操作未实现 |
| OpenAI 兼容 | 部分 | 模型接入侧兼容，平台对外未提供 OpenAI 兼容的对话补全端点 |
| OpenAPI | 已具备 | 由框架自动生成；有契约测试；缺公开版本化与变更日志 |
| OAuth2 / OIDC | 部分 | 仅用于登录与模型接入；未提供面向 API 的客户端凭据模式 |

### 2.5 开发者体验

- 智能体界面内提供 API 文档页，展示版本、调用方式与示例。
- 提供 cURL / Python / JavaScript 示例与 Base URL、Agent ID、Token 占位符。
- 缺独立开发者门户、沙箱环境、SDK、公开变更日志、调用调试台与用量看板。
- 缺 API Key 自助创建、轮换、撤销与权限范围划分。

## 3. 本项目现状

### 3.1 已具备

- 对外 Agent API 闭环：版本发布 → 会话创建 → 流式对话 → 历史/清空/删除/反馈。
- 发布版本快照：执行时加载快照，保证对外行为稳定。
- 执行上下文与租户复核：执行身份固定服务端执行租户，流式订阅持续复查权限，失去权限时发送权限撤销事件并结束。
- SSE 契约：以命名事件推送文本增量、思考、工具调用、工具结果、完成与错误；持久化任务支持事件序号与断线回放。
- Hook 引擎：7 类事件、作用域匹配、异步队列、Webhook 签名/重试、沙箱命令、脱敏、递归防护、触发日志。
- 扩展面：MCP、自定义 HTTP 工具、技能包、渠道适配器、斜杠命令。
- MCP 管理：管理员增删改查、连接/刷新、工具列表、租户过滤。
- OpenAPI 契约测试：重复路由、响应语义、媒体类型、响应结构、部分更新空值语义。

### 3.2 部分具备

- 身份：外部调用仅支持用户登录令牌，没有 API Key、服务账号或 OAuth 客户端凭据；无法区分“哪个系统”在调用。
- Hook：引擎与数据表已具备，但没有 Hook 配置与执行日志的 REST API，也没有前端管理页；配置目前只能直接写库。
- 事件：只有内部生命周期 Hook，没有面向第三方的任务完成、确认请求、成本阈值等订阅产品，也没有事件重放与投递保证。
- OpenAPI：规范由框架生成，但缺少对外版本号、弃用策略、公开变更日志与 SDK 生成。
- 限流：仅有截图、聊天批次等局部节流；没有按 API Key/租户/端点的通用限流。
- CLI：命令行入口存在，但对话循环尚未连接智能体运行时，属于占位实现。
- 错误码：仅部分端点返回稳定业务错误码，未形成完整、稳定的错误码表。
- 生态隔离：远程工具配置没有租户归属，是全局共享配置；对多租户开放前需先收敛归属。

### 3.3 缺失

- API Key / 服务账号、权限范围、密钥轮换与吊销。
- Python / JavaScript SDK 与开发者门户。
- Web 嵌入组件、iframe、移动端 SDK。
- 智能体模板、技能、工具、连接器市场。
- A2A 协议与跨平台互操作性。
- 开发者沙箱环境与公开变更日志。
- 对外 Webhook 订阅管理、事件重放与投递日志产品化。
- 平台作为 MCP Server 对外暴露工具/资源。
- 调用方级配额、账单与用量门户。

## 4. 关键设计

### 4.1 API 契约与版本

- **版本化方式**：不是路径前缀版本，而是“发布快照 + 生效版本”。同步执行与外部对话必须存在生效版本，行为以快照为准。
- **响应结构**：同步执行返回统一业务码、Markdown 回答与会话标识；流式接口使用命名事件加结构化数据。
- **会话语义**：会话标识可复用已有会话；会话必须属于目标智能体与执行用户；清空会话会创建新的上下文。
- **契约测试**：覆盖重复路由、响应语义、媒体类型、响应结构与部分更新空值语义。
- **风险**：快照保证行为稳定，但平台没有 API 语义版本号；新增事件或字段时应明确兼容规则。

### 4.2 鉴权与租户

- 所有对外端点要求登录令牌；执行身份由服务端固定执行租户，不跟随界面切换。
- 发布版本要求管理员或智能体所有者；普通调用要求智能体可见且有成员资格。
- 状态、回放、续跑、停止均复查来源对象；流式订阅失去权限时发送权限撤销事件并结束。
- 缺口：登录令牌代表“人”，不能代表“系统”。第三方集成需要 API Key / 服务账号，且应有独立权限范围、限流与审计。

### 4.3 事件投递语义

- 匹配：全局 + 租户 + 智能体三级作用域全部触发，互不覆盖。
- 异步：事件投递只入队，Agent 主循环零阻塞；执行单元并发默认 4。
- 可靠性：有界队列，满则丢弃并告警；动作超时/失败只记日志；重试次数默认 1，指数退避。
- 安全：Webhook 默认拒绝私网，可选域名白名单；请求签名；负载入队前脱敏。
- 递归防护：Hook 动作触发的嵌套 Agent 执行不再触发 Hook。
- 缺口：没有对外订阅管理 API、投递日志查询、事件重放和至少一次投递保证。

### 4.4 扩展契约

| 扩展点 | 契约 | 版本/演进 |
|---|---|---|
| MCP | 标准协议；平台作为客户端 | 跟随 MCP 协议与 SDK；工具前缀解决冲突 |
| 远程工具 | 管理员配置结构化映射；地址/查询/请求体模板 + 字段提取 | 配置即契约；无工具版本 |
| 技能包 | 声明文件（元数据 + 说明）+ 附加文件，压缩包版本化 | 每次更新生成新版本；对象存储键含版本 |
| Hook | 事件 + 动作类型 + 配置数据 | 事件注册表集中声明；动作类型可扩展 |
| 渠道 | 统一适配器契约：发送文本/Markdown/文件/定向消息 | 每种渠道独立适配器与配置 |

### 4.5 设计判断

- 开放平台的第一道门槛是“机器身份”。在补齐 API Key / 服务账号之前，Agent API 更适合内部系统用登录令牌临时集成，不适合作为对外商业 API。
- Hook 已有可靠的执行内核，但缺少管理面，导致能力“存在但不可运营”。优先补 REST API 与日志查询，比新增事件类型更有价值。
- 市场与嵌入应建立在稳定的 API/事件契约和 SDK 之上；顺序应是 API Key → SDK/文档 → 事件订阅 → 嵌入/市场。

## 5. 实施建议

### P0（开放底线）
- 增加 API Key / 服务账号：创建、轮换、吊销、按执行、会话写入、反馈等操作划分权限范围。
- 按调用方与端点限流，返回标准限流响应与重试等待提示；补齐稳定错误码表。
- 为同步执行与会话清空增加幂等键，避免网络重试造成重复执行。
- 完成 Hook 管理 REST API：事件字典、增删改查、测试触发、执行日志查询与筛选。
- 给远程工具配置增加租户归属与可见性，避免多租户共享全局配置。

### P1（开发者体验）
- 发布 Python / JavaScript SDK，覆盖同步执行、流式会话、版本与反馈。
- OpenAPI 增加对外版本号、弃用标记、变更日志；提供可下载规范。
- 对外 Webhook 订阅 API：订阅任务完成、失败、确认请求等事件，提供签名、重试与投递日志。
- 技能包与连接器的发布规范：元数据、版本、权限声明、依赖检查。
- 开发者沙箱环境与调用调试台。

### P2（生态）
- Web 嵌入组件 / iframe / 移动端 SDK。
- 智能体模板、技能、工具、连接器市场。
- A2A 协议与跨平台智能体互操作。
- 平台作为 MCP Server 暴露工具与资源。
- 调用方用量、账单与配额门户。
