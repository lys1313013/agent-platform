# D15 开放平台与生态

> **解决什么问题**：平台价值 = 自身能力 × 可被集成程度。本篇回答外部系统如何调用智能体、平台如何主动推送事件、第三方如何扩展能力，以及当前开放面与生态缺口在哪里。
> **适用读者**：平台架构师、集成/生态开发者、解决方案与交付团队、安全评审。
> **关联文档**：D01（身份与权限）、D02（运行时）、D04（工具与外部集成）、D08（人机协同）、D09（智能体生命周期）、D10（安全合规）；旧文档 `docs/05-智能体管理/03-API文档.md`、`docs/06-MCP`、`docs/10-自定义远程工具`、`docs/20-hook机制`、`docs/35-执行与接口契约`。
> **状态基准**：2026-11 `main` 分支代码。状态仅用「已具备 / 部分 / 缺失」，规划能力不计为已实现。

## 1. 边界

**本篇覆盖**
- 开放 API：智能体执行、会话创建、SSE 对话、消息与反馈、版本发布、API 文档元数据。
- 鉴权与租户：外部调用者身份、执行租户、已发布配置快照。
- 事件与 Webhook：生命周期事件、签名、重试、失败语义。
- 扩展机制：MCP、自定义 HTTP 工具、技能包、Hook、渠道适配器、斜杠命令。
- 标准化：MCP、A2A、OpenAI 兼容接口的现状与差距。
- 开发者体验：OpenAPI、SDK、文档、沙箱环境、变更日志、市场。

**本篇不覆盖**
- 内部工具执行与沙箱安全细节（D04）。
- 智能体版本质量、评测、灰度与回滚（D09）。
- 渠道内部的会话映射、消息去重与重试（D08）。
- 平台自身管理端 API 的完整清单（D01/D08）。
- 计费、配额执行与成本分摊（D12）。

**关键边界判断**
- “开放 API 可用”不等于“开放平台成立”。当前 API 面向登录用户 JWT，缺少服务身份、SDK 与开发者门户，属于可集成但未产品化。
- Hook 是平台主动推送的雏形，但事件配置、日志查询和订阅管理尚未开放，不能等同于对外 Webhook 产品。
- MCP 目前是平台作为客户端接入外部工具；平台自身尚未作为 MCP Server 对外暴露能力。

### 2.2 事件与 Webhook

| 事件 | 触发点 | 负载要点 | 当前状态 |
|---|---|---|---|
| `SessionStart` | Agent 开始执行 | 用户输入（截断）、模型、迭代上限 | 已具备（引擎） |

| `PostToolUse` | 工具执行后 | 成功与否、错误类型、耗时、输出摘要 | 已具备（引擎） |
| `PreCompact` / `PostCompact` | 上下文压缩前后 | 压缩前后 token、节省量 | 已具备（引擎） |
| `Notification` | 权限拒绝、上下文告警、超迭代、工具失败 | 级别、分类、说明 | 已具备（引擎） |
| Hook 配置管理 API | 无 | 无 | 缺失 |
| Hook 触发日志查询 API | 无 | 无 | 缺失 |
| 对外事件订阅/重放 | 无 | 无 | 缺失 |

**投递语义**：进程内有界队列 + worker，异步非阻塞；队列满丢弃并告警；动作失败静默，只写 `hook_executions`；Webhook 支持 HMAC-SHA256、自定义 Header、超时与有限重试；沙箱命令通过 `/tmp/hook_payload.json` 接收负载。

### 2.5 开发者体验

- 智能体界面内提供 API 文档页（`AgentApiPage`），展示版本、调用方式与示例。
- 提供 cURL / Python / JavaScript 示例与 Base URL、Agent ID、Token 占位符。
- 缺独立开发者门户、沙箱环境、SDK、公开变更日志、调用调试台与用量看板。
- 缺 API Key 自助创建、轮换、撤销与权限范围（scope）。

## 3. 本项目现状

### 3.1 已具备

- 对外 Agent API 闭环：版本发布 → 会话创建 → SSE 对话 → 历史/清空/删除/反馈。
- 发布版本快照：`AgentVersion.config_snapshot`，执行时加载快照，保证对外行为稳定。
- 执行上下文与租户复核：`ExecutionUser` 固定服务端执行租户，SSE 持续复查权限，失去权限发送 `access_revoked`。
- SSE 契约：`text_delta`、`thinking`、`tool_call`、`tool_result`、`done`、`error`；持久化任务支持 `sequence` / `replay`。
- Hook 引擎：7 类事件、作用域匹配、异步队列、Webhook 签名/重试、沙箱命令、脱敏、递归防护、触发日志。
- 扩展面：MCP、自定义 HTTP 工具、技能包、渠道适配器、斜杠命令。
- MCP 管理：管理员 CRUD、连接/刷新、工具列表、租户过滤。
- OpenAPI 契约测试：重复路由、状态码、媒体类型、响应 Schema、PATCH 空值语义。

### 3.2 部分具备

- 身份：外部调用仅支持用户 JWT，没有 API Key、服务账号或 OAuth Client Credentials；无法区分“哪个系统”在调用。
- Hook：引擎与数据表已具备，但没有 `hooks` / `hook-executions` REST API，也没有前端管理页；配置目前只能直接写库。
- 事件：只有内部生命周期 Hook，没有面向第三方的任务完成、确认请求、成本阈值等订阅产品，也没有事件重放与投递保证。
- OpenAPI：规范由框架生成，但缺少对外版本号、弃用策略、公开变更日志与 SDK 生成。
- 限流：仅有截图、聊天批次等局部节流；没有按 API Key/租户/端点的通用限流。
- CLI：`aio-agent` 脚本存在，但 REPL 尚未连接 AgentLoop，属于占位实现。
- 错误码：仅部分端点返回业务错误码（如 `40001`、`40401`），未形成完整、稳定的错误码表。
- 生态隔离：远程工具无 `tenant_id`，是全局配置；对多租户开放前需先收敛归属。

### 3.3 缺失

- API Key / 服务账号、scope、密钥轮换与吊销。
- Python / JavaScript SDK 与开发者门户。
- Web 嵌入组件、iframe、移动端 SDK。
- 智能体模板、技能、工具、连接器市场。
- A2A 协议与跨平台互操作。
- 开发者沙箱环境与公开变更日志。
- 对外 Webhook 订阅管理、事件重放与投递日志产品化。
- 平台作为 MCP Server 对外暴露工具/资源。
- 调用方级配额、账单与用量门户。

## 4. 关键设计

### 4.1 API 契约与版本

- **版本化方式**：不是 URL 版本（`/v1`），而是“发布快照 + 生效版本”。`execute` 与外部 `chat` 必须存在 active 版本，行为以快照为准。
- **响应结构**：同步执行返回 `code / data.markdown_response / data.session_rid`；SSE 使用命名事件 + JSON data。
- **会话语义**：`session_rid` 可复用已有会话；会话必须属于目标智能体与执行用户；清空会话创建新上下文。
- **契约测试**：`test_api_contracts.py` 检查重复路由、HTTP 状态码、媒体类型、响应 Schema 和 PATCH 空值语义。
- **风险**：快照保证行为稳定，但平台没有 API 语义版本号；新增事件或字段时应明确兼容规则。

### 4.2 鉴权与租户

- 所有对外端点要求 JWT；执行使用 `ExecutionUser`，执行租户由服务端固定，不跟随界面切换。
- 发布版本要求管理员或智能体所有者；普通调用要求智能体可见且有成员资格。
- 状态、回放、续跑、停止均复查来源对象；SSE 失去权限时发送 `access_revoked` 并结束。
- 缺口：JWT 代表“人”，不能代表“系统”。第三方集成需要 API Key / 服务账号，且应有独立 scope、限流与审计。

### 4.3 事件投递语义

- 匹配：global + tenant + agent 三级作用域全部触发，互不覆盖。
- 异步：`fire` / `fire_nowait` 只入队，Agent 主循环零阻塞；worker 并发默认 4。
- 可靠性：有界队列，满则丢弃并告警；动作超时/失败只记日志；重试次数默认 1，指数退避。
- 安全：Webhook 默认拒绝私网，可选域名白名单；HMAC 签名；负载入队前脱敏。
- 递归防护：Hook 动作触发的嵌套 Agent 执行不再触发 Hook。
- 缺口：没有对外订阅管理 API、投递日志查询、事件重放和至少一次投递保证。

### 4.4 扩展契约

| 扩展点 | 契约 | 版本/演进 |
|---|---|---|
| MCP | 标准协议；平台作为客户端 | 跟随 MCP 协议与 SDK；工具前缀解决冲突 |
| 远程工具 | 管理员配置 JSON；URL/Query/Body 模板 + JSONPath | 配置即契约；无工具版本 |
| 技能包 | `SKILL.md`（YAML frontmatter + Markdown）+ 附加文件，zip 版本化 | 每次更新生成新版本；MinIO 对象键含版本 |
| Hook | 事件 + 动作类型 + config JSON | 事件注册表集中声明；动作类型可扩展 |
| 渠道 | `ChannelAdapter` 基类：send / send_markdown / send_file / send_to_user | 每种渠道独立适配器与配置 |

### 4.5 设计判断

- 开放平台的第一道门槛是“机器身份”。在补齐 API Key / 服务账号之前，Agent API 更适合内部系统用用户 JWT 临时集成，不适合作为对外商业 API。
- Hook 已有可靠的执行内核，但缺少管理面，导致能力“存在但不可运营”。优先补 REST API 与日志查询，比新增事件类型更有价值。
- 市场与嵌入应建立在稳定的 API/事件契约和 SDK 之上；顺序应是 API Key → SDK/文档 → 事件订阅 → 嵌入/市场。

## 5. 实施建议

### P0（开放底线）
- 增加 API Key / 服务账号：创建、轮换、吊销、scope（agents:execute、sessions:write、feedback:write）。
- 按调用方与端点限流，返回标准 `429` 与 `Retry-After`；补齐稳定错误码表。
- 为 `execute` 与 `clear` 增加幂等键，避免网络重试造成重复执行。
- 完成 Hook 管理 REST API：事件字典、CRUD、测试触发、执行日志查询与筛选。
- 给 `remote_tools` 增加 `tenant_id` 与可见性，避免多租户共享全局配置。

### P1（开发者体验）
- 发布 Python / JavaScript SDK，覆盖同步执行、SSE 会话、版本与反馈。
- OpenAPI 增加对外版本号、弃用标记、变更日志；提供可下载规范。
- 对外 Webhook 订阅 API：订阅任务完成、失败、确认请求等事件，提供签名、重试与投递日志。
- 技能包与连接器的发布规范：元数据、版本、权限声明、依赖检查。
- 开发者沙箱环境与调用调试台。

### P2（生态）
- Web 嵌入组件 / iframe / 移动端 SDK。
- 智能体模板、技能、工具、连接器市场。
- A2A 协议与跨平台智能体互操作。
- 平台作为 MCP Server 暴露工具与资源。
- 调用方用量、账单与配额门户。

## 6. 验收标准

- [ ] 第三方可用 API Key 调用已发布智能体，无需用户 JWT；Key 可轮换、吊销并按 scope 限制端点。
- [ ] 未发布版本的智能体无法被外部调用，返回稳定错误码；发布快照变更不影响进行中的会话。
- [ ] 外部调用只能访问授权租户与可见智能体；切换界面租户不改变执行租户。
- [ ] SSE 断线可重连并按 `sequence` / `replay` 恢复；失去权限时收到 `access_revoked`。
- [ ] `execute` 的重复请求在相同幂等键下不重复执行。
- [ ] Hook 可通过 API 配置、启停、测试；触发日志可按租户、事件、Hook、状态筛选。
- [ ] Webhook 具备 HMAC 签名、私网拦截、超时与重试；失败不影响对话。
- [ ] 对外 API 有稳定版本号、变更日志与可下载 OpenAPI；SDK 示例可直接运行。
- [ ] 远程工具与 MCP 配置有明确租户归属，不能跨租户读取或修改。
- [ ] 每次外部调用可按调用方、智能体、租户检索用量与错误。
