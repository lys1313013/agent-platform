# 本地浏览器远程控制 — 部署与验收

> 重建说明：原部署与验收文件未纳入 git，删除后无法恢复。本文依据 `docker-compose.browser.yml`、`browser/` 代码与现有测试重建。

## 1. 部署形态

浏览器远程控制是**可选叠加**，默认不启用：

```bash
docker compose -f docker-compose.yml -f docker-compose.browser.yml up -d
```

组成：

| 组件 | 作用 |
|---|---|
| `backend` | 启用 `BROWSER_ENABLED=true`，提供配对/授权/会话 API |
| `browser-gateway` | 独立进程，`aio_agent_platform.browser.app:app`，监听 8101 |
| `BrowserSkill` 扩展 | 用户本地 Chrome 安装，出站连接 Gateway |
| 反向代理 | 对外暴露 `wss://.../extension`，TLS 终止 |

## 2. 必填配置

| 变量 | 要求 |
|---|---|
| `BROWSER_SECRET_KEY` | 至少 32 字符，独立随机；不得与 JWT / 存储密钥复用 |
| `BROWSER_GATEWAY_SETTINGS_KEY` | Gateway 独立设置密钥；不得与平台 JWT 复用 |
| `BROWSER_PUBLIC_WSS_URL` | 扩展可访问的 `wss://` 地址，路径 `/extension` |
| `BROWSER_GATEWAY_PORT` | 默认 8101；overlay 只绑定 `127.0.0.1`，由代理对外 |
| `BROWSER_ALLOW_LOOPBACK_WS` | 仅本地开发设为 true |

**网络边界**：
- Gateway 不应直接暴露公网 HTTP，只通过 TLS 代理暴露 WSS。
- 扩展来源只接受 `chrome-extension://`，代理不得改写 Origin。
- 多副本部署时 Gateway 需单 worker（当前命令固定 `--workers 1`）或改用共享状态。

## 3. 安装步骤

1. 配置上述环境变量，启动叠加 Compose。
2. 在反向代理配置 `wss://<域名>/extension` → `127.0.0.1:8101`，开启 WebSocket Upgrade。
3. 在用户 Chrome 安装 BrowserSkill 扩展，填写 `BROWSER_PUBLIC_WSS_URL`。
4. 管理端创建设备配对，用户完成配对。
5. 在会话中授予 origin 与单轮/持续授权，再调用 `local_browser_*` 工具。

## 4. 验收清单

### 配对与设备
- [ ] 配对码过期后无法使用。
- [ ] 配对成功后设备出现在设备列表，显示在线状态。
- [ ] 吊销设备后，扩展连接被拒绝，在途会话终止。
- [ ] 设备凭证轮换后旧凭证失效。

### 授权
- [ ] 未授予 grant 时，`local_browser_*` 调用被拒绝。
- [ ] grant 只对绑定的智能体、会话与运行生效。
- [ ] 运行结束或用户停止后，grant 立即失效。
- [ ] 导航到未授权 origin 被拒绝。
- [ ] 持续授权可由用户随时关闭，关闭后在途命令停止。
- [ ] 登录、验证码、支付由模型调用时被拒绝，并提示使用 `request_help`。

### 会话与命令
- [ ] 同一设备不能同时存在两个 occupied 会话。
- [ ] 命令按 `request_id` 幂等，重复投递不重复执行。
- [ ] 审批参数变化后，原审批失效。
- [ ] 扩展断线后，心跳超时会释放占用，不残留 occupied 会话。
- [ ] 断线重连时旧 `connection_epoch` 不能恢复会话。
- [ ] 用户停止后，在途命令被取消并写入明确终态。

### 隔离
- [ ] 用户 A 无法读取用户 B 的设备、grant、会话与观察结果。
- [ ] 跨租户调用被拒绝。
- [ ] 私有聊天不触发 Hook、不写入共享上下文。
- [ ] 截图与观察结果不包含设备 ID、凭证或未授权 origin 的内容。
