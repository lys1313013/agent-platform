# 无状态沙箱 — 需求

> 让智能体的代码执行环境可以随时销毁、重建和在多节点间迁移，同时保证文件持久、用户隔离与安全边界。技术实现见 [设计](02-设计.md)。

## 1. 背景与问题

智能体需要执行用户代码、跑脚本、处理文件，这要求一个隔离的执行环境。早期实现把工作区挂在宿主机磁盘卷上，带来四个结构性问题：

- 卷绑定单台机器，平台无法多节点部署。
- 同一用户的所有会话共享一个卷，不同项目的文件互相干扰。
- 每个会话一个独立容器，资源浪费，且新容器要从零安装依赖。
- 没有面向用户的文件上传、下载与浏览能力，文件只能由智能体在容器里操作。

核心矛盾是：代码执行需要文件持久化和隔离，而持久化卷又把执行绑定在单台机器上。用户期望的是"文件一直在、环境一直在"，而不是"容器一直在"。

## 2. 目标

- 执行环境无状态：容器可随时销毁与重建，文件持久化在对象存储，扩容节点不需要迁移数据。
- 每用户一个长期容器，按智能体和会话划分工作目录，跨智能体共享公共环境，避免重复安装依赖。
- 容器懒创建、空闲回收，用户再次使用时可无感知恢复。
- 默认安全：网络关闭、非 root、只读根文件系统、权限剥夺、资源限额。
- 依赖不可用时降级运行，不拖垮整个平台，也不静默丢失用户文件。

## 3. 范围

**纳入**：

- 每用户容器的创建、复用、空闲回收与恢复。
- 工作区按智能体、会话、共享目录三类划分与隔离。
- 工作区文件与对象存储之间的注入、定期同步、回收前同步和删除传播。
- 工作区文件的浏览、上传、下载、删除与统计，容器未运行也可用。
- 并发控制、多后端进程接管、重启恢复、初始化失败保护。
- Docker 与对象存储不可用时的降级行为。

**不纳入**：

- 跨用户共享容器或容器池化调度。
- 沙箱内直接访问外网。
- 多节点同时持有同一用户容器（依靠无状态重建，不做分布式协同）。
- 工作区文件的版本历史、回收站与跨用户共享。
- 执行审计、计量与配额计费（属于安全合规与计量域）。

## 4. 功能需求

### 4.1 执行隔离与目录布局

- 每用户一个长期存活容器，同一用户的沙箱工具调用复用该容器。
- 容器内工作区分三类：跨智能体共享目录、按智能体划分的目录、无智能体会话的独立目录。
- 有智能体的会话在对应智能体目录下读写；无智能体的会话在自身会话目录下读写；委派出的子智能体沿用父智能体目录，可读写父智能体文件。
- 共享目录用于虚拟环境、依赖包和其他公共资源，是否使用由用户或智能体显式决定，不自动迁移已有文件。
- 智能体工具传入的路径一律相对于当前工作目录；只允许工作区内的路径，路径穿越必须被拒绝，工作区内部子目录不做额外限制。

### 4.2 生命周期

- 懒创建：只有首次调用需要沙箱的工具时才创建容器；纯文本对话不创建。
- 复用：同一用户后续工具调用直接复用容器，并刷新活跃时间。
- 空闲回收：默认空闲约 1 小时回收，后台约每 5 分钟检查一次；正在执行或近期活跃的容器跳过。
- 回收顺序不可颠倒：先同步全部已加载工作区，同步成功后才停止并删除容器；同步失败或对象存储不可用必须保留容器并告警。
- 恢复：容器重建后从对象存储注入该用户全部工作区文件；首次使用且无文件时跳过注入。
- 同一用户的创建、命令执行、同步和删除必须串行化，不得并发操作同一容器。
- 锁与工作区映射必须保存在容器之外，防止沙箱内命令篡改持久化目标；运行期间不得清除。
- 后端启动及后台维护要能发现本部署的容器：接管运行中且元数据完整、配置匹配的容器；清理尚未启动或已退出的容器；配置变化、元数据缺失或重复运行的容器保留并报错，不得直接删除用户文件。
- 正常关闭后端时先同步再保留运行容器，供其他进程或重启后的后端接管。
- 初始化失败或取消时，等待容器操作结束并移除本次新建容器，不得把初始化到一半的文件同步回对象存储。
- 进程被强杀后留下的容器，若缺少初始化元数据，保留并报错等待恢复，不得当作垃圾清理。

### 4.3 文件持久化与同步

- 容器创建时从对象存储恢复文件；运行期间按固定周期做增量同步，作为崩溃时的安全网。
- 回收前的同步要逐文件比对，正确处理新增、变更和删除，不能只上传不删除。
- 容器崩溃最多丢失一个同步周期内尚未同步的改动，这是可接受的已知取舍。
- 对象存储不可用时：不得初始化新工作区，避免用空目录覆盖已有文件；后台清理仍可运行，但只清理本部署已退出的容器。
- 旧版基于本地卷的容器不做批量删除；发现同项目、同用户仍有旧容器运行时，阻止另建新容器，先同步并处理旧容器。

### 4.4 工作区文件管理

- 用户可浏览、下载、上传、删除文件并查看统计，全部不要求容器运行。
- 提供浏览器直连对象存储的大文件上传下载通道，以及服务端中转的小文件通道。
- 上传文件写入对象存储后，若该用户有运行中的容器，分块写入正确的工作区；没有运行中的容器时不得为此新建容器，等下次初始化再载入。
- 文件操作以当前用户为边界，不得访问其他用户或其他部署的工作区。

### 4.5 降级行为

- Docker 不可用时后端照常启动；非沙箱工具与功能不受影响；沙箱请求返回明确失败并支持重试。
- 运行环境查询类只读工具不依赖沙箱即可使用；状态检查不得创建、启动或接管容器。
- 对象存储不可用时，已在运行的容器保留，后续同步重试；恢复失败时不得凭空创建空工作区覆盖远端文件。

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 安全 | 容器非 root 运行、根文件系统只读、放弃全部 Linux 权限、禁止提权、CPU 与内存受限、工作区与临时目录使用内存文件系统并受容量配额约束 |
| 网络 | 沙箱默认禁止出网，代码执行不能直接访问外部服务 |
| 隔离 | 用户之间以容器隔离，智能体与会话之间以子目录隔离；不同部署使用不同命名空间，禁止混用 |
| 可扩展 | 容器不依赖本地持久卷，可在任意节点重建；但共用同一 Docker 守护进程的所有后端进程必须能访问同一把共享文件锁，跨主机连接远程 Docker 也必须满足，否则该部署方式不受支持 |
| 性能与容量 | 工作区总量有上限（当前默认 500MB 量级），大工作区恢复存在延迟，靠增量同步降低恢复成本 |
| 成本 | 空闲回收控制常驻容器数量；共享环境目录减少重复安装 |
| 可运营 | 回收、同步、接管、清理的失败必须告警且可定位，不能静默 |

## 6. 验收标准

- [ ] 纯文本对话不创建容器；首次调用写文件或执行命令时才创建。
- [ ] 同一用户多次调用复用同一容器，文件连续可见。
- [ ] 两个智能体与一个无智能体会话分别写入各自目录，互不覆盖；委派子智能体能读写父智能体目录。
- [ ] 共享目录中安装的依赖对其他智能体可用。
- [ ] 空闲超过阈值后容器先同步再销毁；再次调用时工作区内容与销毁前一致。
- [ ] 容器被直接停止或删除后重建，文件能从对象存储恢复。
- [ ] 同步失败或对象存储不可用时容器不被销毁并产生告警；对象存储不可用时不初始化新工作区。
- [ ] Docker 不可用时后端正常启动，非沙箱功能可用，沙箱请求返回明确失败并可重试。
- [ ] 两个后端进程并发操作用户容器时不会同时创建或删除；重启后能接管运行容器并恢复工作区映射。
- [ ] 配置不匹配、元数据缺失或重复运行的容器不被删除，报错等待人工处理。
- [ ] 工作区文件可浏览、上传、下载、删除与统计，且不需要容器运行。
- [ ] 无运行容器时上传文件不会触发新建容器，下次初始化后文件可被智能体读取。
- [ ] 路径穿越、跨用户访问与其他部署的工作区访问被拒绝。
- [ ] 容器以非 root 运行、根文件系统只读、无外网、资源受限，均可从运行状态验证。
- [ ] 正常关闭后端后容器保留，重启或其他进程可继续接管，未同步文件不丢失。
