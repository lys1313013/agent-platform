# D04 工具与外部集成

> **解决什么问题**：智能体的能力来自可调用的工具，而工具层同时是平台最大的外部攻击面。本篇回答工具从哪里来、以什么契约暴露、如何授权与确认、凭证放在哪、出站边界怎么守、代码在哪里执行。
> **适用读者**：平台架构师、工具/集成开发者、安全评审、私有化交付工程师。
> **关联文档**：D01（身份与权限）、D02（运行时）、D08（人机协同）、D10（安全合规）、D15（开放平台）。
> **状态基准**：2026-11 `main` 分支代码。状态仅用「已具备 / 部分 / 缺失」，设计文档中的规划不计为已实现。

## 1. 边界

**本篇覆盖**
- 工具来源：内置工具、MCP、自定义 HTTP 工具、网页搜索/抓取、文档工具、页内操作、本地浏览器操作。
- 工具契约：参数结构定义、参数校验、输出截断、错误语义、超时、执行位置。
- 权限与确认：工具级权限、用户信任等级、智能体白名单、危险操作确认、浏览器独立授权。
- 凭证与出口：MCP 请求头、远程工具认证、Web 搜索密钥、沙箱网络、SSRF、出站白名单。
- 执行环境：Docker 无状态沙箱与工作区持久化。
- 工具治理：注册、发现、启停、调用日志与失败隔离。

**本篇不覆盖**
- 模型选择、路由、限流与费用（D03）。
- 知识检索与记忆的内部实现（D05 / D06）。
- 多智能体委派语义与预算传播（D07）。
- 完整审计、合规与数据分级（D10）。
- 对外 Agent API、事件开放与生态（D15）。
- 各页面动作注册表与虚拟光标的完整交互设计（D08）。

**关键边界判断**
- 工具“能发现”不等于“有权调用”。MCP 连接是进程级共享池，权限必须在每次执行时按执行租户、启用状态和成员资格复核。
- 技能是提示词与文件的打包，不是可执行工具；渠道是输入输出适配器，不进入工具契约。
- 页内操作在用户浏览器内执行，本地浏览器操作用户本地外部网站；二者都不在服务端沙箱内。

## 2. 能力清单

### 2.1 工具来源

| 来源 | 暴露方式 | 发现方式 | 默认执行位置 | 当前状态 |
|---|---|---|---|---|
| 内置工具 | 静态注册 | 代码定义 | 沙箱 / 宿主直调 / 前端 | 已具备 |
| 文档工具 | 内置工具子集 | 代码定义 | 沙箱 | 已具备 |
| MCP 工具 | 动态注册 | 工具发现（含分页） | 宿主 HTTP 连接 | 已具备 |
| 自定义 HTTP 工具 | 动态注册 | 管理员手工配置 | 宿主 HTTP 请求 | 已具备 |
| 网页搜索/抓取 | 内置工具 | 代码定义 + 运行时配置 | 宿主（沙箱默认禁网） | 已具备 |
| 页内自动化 | 六个页内操作工具 | 代码定义 | 用户浏览器 | 已具备 |
| 本地浏览器 | 八个本地浏览器工具 | 代码定义 | 用户本地浏览器 | 已具备 |
| Hook 动作 | 配置驱动，不作为模型工具 | 管理端配置 | Webhook / 沙箱命令 | 部分（引擎已具备，管理端缺失） |

### 2.2 工具契约

| 维度 | 要求 | 本项目实现 |
|---|---|---|
| 名称 | 全局唯一、符合函数名规范 | 内置/远程工具校验；MCP 前缀避冲突 |
| 描述 | LLM 可理解，说明何时调用与信任边界 | 必填；网页抓取明示外部内容不可信 |
| 参数 Schema | 标准参数结构定义，可被 OpenAI/Anthropic 接受 | 统一归一化与自检 |
| 参数边界 | 长度、枚举、数值范围、必填 | 各工具 Schema 声明；本地浏览器使用严格参数校验 |
| 输出 | 字符串或结构化文本；可截断；可落盘 | 统一截断上限 5 万字符，超限写工作区文件 |
| 错误 | 不打断 Agent 循环，作为 observation 返回 | MCP/远程/沙箱错误转为失败结果 |
| 超时 | 工具级和沙箱级双重限制 | 工具级超时；沙箱命令默认 60 秒 |
| 幂等 | 写操作需可识别、可重试边界清晰 | 未形成统一幂等标记，属缺失 |
| 执行位置 | 沙箱 / 宿主直调 / 前端 / 本地浏览器 | 工具元数据声明执行位置 |

### 2.3 权限与确认

- 工具级权限：只读、写入、危险三级。
- 用户信任等级：每次确认、仅危险工具确认、全部自动。
- 直接处理器必须声明权限；未声明按危险处理。
- 智能体的工具白名单在运行时再次校验，子智能体默认不继承父级全部工具。
- 用户确认流程由智能体循环直接拦截，不走工具执行器，避免确认死锁。
- 本地浏览器使用独立授权，不重复套用普通工具确认。

### 2.4 凭证

| 凭证 | 存储 | 是否进模型上下文 | 备注 |
|---|---|---|---|
| MCP 请求头 / 令牌 | 服务端配置 | 否 | 当前未加密存储 |
| 远程工具认证 | 服务端配置 | 否 | API 返回时脱敏，存储未加密 |
| Web 搜索密钥 | 环境配置 + 平台配置 | 否 | 管理接口只返回是否已配置 |
| 渠道应用密钥 | 加密字段 | 否 | 飞书/企微凭证加密 |
| 模型提供商密钥 | 加密字段 | 否 | 与 D03 共用 |
| 本地浏览器配对凭证 | 服务端封装/摘要 | 否 | 支持轮换与撤销 |

### 2.5 出口与网络边界

- 沙箱网络默认关闭，代码执行不能直接出网。
- 网页抓取在宿主执行，具备 SSRF 校验、DNS 解析后私网拦截、每次重定向复检、响应体上限、超时与输出截断。
- Hook Webhook 具备私网拦截、可选域名白名单、HMAC 签名和重试。
- MCP 与自定义 HTTP 工具当前没有统一的出站白名单或 SSRF 校验，是主要缺口。
- 本地浏览器通过用户本机出站 WSS 连接，访问范围由用户授权决定。

### 2.6 沙箱

- 每用户一个长期存活容器，工作区与临时目录使用内存文件系统，无持久化磁盘卷。
- 非 root 运行、只读根文件系统、放弃全部 Linux 权限、禁止提权、CPU/内存限额、网络默认关闭。
- 工作区按智能体/会话子目录隔离，文件同步到对象存储；容器空闲回收，再次使用时恢复。
- 同一用户的创建、执行、同步、删除使用进程内锁和共享文件锁互斥；不同部署必须使用不同命名空间。
- 空闲回收默认 3600 秒；并发上限有配置项（默认 10），但没有实际执行点。

## 3. 本项目现状

### 3.1 已具备

- 工具注册表与统一执行器：工具元数据、OpenAI function calling 导出、静态与动态注册。
- 40+ 内置工具：沙箱文件/命令/代码、记忆、技能、知识检索、委派、定时任务、画像、文档、网页、页内操作。
- MCP：SSE 与 Streamable HTTP 两种传输，连接生命周期由专用任务持有，工具分页发现，前缀去冲突，过期会话重连重试一次。
- 自定义远程 HTTP 工具：增删改查、认证类型、URL、查询参数与请求体模板、响应字段提取、测试调用。
- 网页搜索/抓取：DuckDuckGo / Brave / Tavily / SearXNG，Readability 正文提取，Firecrawl 兜底，TTL 缓存，运行时配置覆盖环境配置。
- 无状态沙箱：安全基线、工作区对象存储持久化、空闲回收、多 worker 文件锁、降级启动。
- 浏览器双通道：页内操作（快照引用、元素标注截图、危险操作三层闸门）与本地浏览器（配对、逐轮/持续授权、人工接管）。
- 权限策略：统一判定是否需确认，MCP/远程/直接处理器按能力分级；执行时复核 MCP 租户与成员资格。
- 调用观测：工具调用日志记录工具名、执行类型、耗时、错误分类、参数/输出规模、截断标记；Hook 提供工具调用前后事件。

### 3.2 部分具备

- 凭证保护：API 响应已脱敏，但 MCP 请求头与远程工具认证在数据库中是明文配置，未接密钥管理服务。
- 出站策略：网页抓取和 Hook 有 SSRF 防护，MCP/远程工具没有；策略分散，未形成统一出口网关。
- 工具治理：有注册、启停和调用日志，但没有工具版本、废弃流程、调用统计面板与失败率告警。
- MCP 能力面：只做工具，未接资源、提示模板、进度回调与流式工具结果。
- 本地浏览器：首期闭环已具备，但定时任务、渠道、开放 API、委派与协作房间不授予浏览器权限；上传下载不伪装支持。
- 跨租户隔离：MCP 有租户归属；远程工具没有租户字段，当前是全局配置。

### 3.3 缺失

- 统一工具市场/目录、工具包安装与租户级可见性。
- 凭证密钥管理与信封加密、自动轮换流程。
- OpenAPI/Swagger 一键导入远程工具。
- 工具级配额、成本计量、熔断与降级策略。
- MCP 工具可信度分级、来源签名与供应链校验。
- 工具输出提示词注入的内容级过滤（当前仅文档声明与模型侧提醒）。
- 统一幂等标记与副作用补偿。

## 4. 关键设计

### 4.1 工具生命周期

1. **注册**：内置工具在启动时静态注册；MCP 在连接成功后动态注册；远程工具从数据库加载后注册；浏览器工具由浏览器模块注册。
2. **可见**：工具列表接口汇总工具元数据；MCP 只返回当前租户启用服务的工具；智能体配置面板按工具白名单勾选。
3. **注入**：每轮模型调用前导出 function calling Schema；对 Schema 做归一化，非法定义从本次请求排除，不回写数据库。
4. **执行**：白名单校验 → 权限确认 → MCP/远程/内置路由 → 输出准备 → 调用日志 → Hook 事件。
5. **回收**：MCP 由共享连接池管理；远程工具更新后重新注册；沙箱按空闲时长回收且文件已同步。

### 4.2 权限与确认的判定顺序

1. 智能体工具白名单不通过 → 直接拒绝，不触发工具调用前事件。
2. 权限判定需要确认且未批准 → 返回错误，不执行。
3. MCP 工具：再次核验执行租户、服务启用状态、用户成员资格。
4. 远程工具：读请求视为只读；写方法默认危险。
5. 页内操作：危险元素三层闸门（前端标注 → 后端确认 → 执行前复检）。
6. 本地浏览器：独立授权、逐命令确认或用户主动开启的持续授权；登录、验证码、支付强制人工接管。

### 4.3 失败模式

| 场景 | 行为 | 用户/Agent 感知 |
|---|---|---|
| MCP 服务崩溃 | 只断开该连接，其他服务与主进程不受影响 | 工具调用返回 MCP 错误 |
| MCP 会话过期 | 可重连错误自动重连并重试一次 | 通常无感；失败则返回错误 |
| 远程 API 非成功响应 | 转为失败观察结果 | 错误含状态码与响应片段 |
| 网页抓取私网/超时/超大 | 失败关闭，返回明确错误 | 不静默返回空 |
| 沙箱 Docker 不可用 | 后端降级启动，沙箱请求失败并可重试 | 非沙箱工具不受影响 |
| Hook 失败/超时 | 只写触发日志，不影响对话 | 对话无感 |
| 本地浏览器结果未知 | 不自动重试，要求核对 | 明确提示结果未知 |
| 工具输出过大 | 截断并写入工作区文件 | 返回文件路径与截断标记 |

### 4.4 协议与版本

- MCP 支持 SSE 与 Streamable HTTP；使用 MCP Python SDK 1.x（需求文档记录 1.27.1，升级前需确认）。
- 协议版本覆盖 2024-11-05 与 2025-03-26；stdio 不支持。
- 工具 Schema 同时适配 OpenAI 兼容接口与 Anthropic 请求边界；流式与非流式入口一致处理。
- 浏览器扩展协议通过 WSS，仅接受浏览器扩展来源；配对链接短期有效，设备凭证可轮换。

### 4.5 设计判断

- 工具层的第一原则应是“默认拒绝 + 单点策略”。当前权限判定已集中，但出口策略仍分散在网页、Hook、浏览器三处，建议收敛为统一出口策略。
- MCP 与远程工具的凭证“脱敏展示”不等于“加密存储”；私有化交付前应优先补齐静态加密。
- 沙箱无状态化是正确的多节点方向，但共享锁目录是硬约束，必须在部署文档中显式声明。

## 5. 实施建议

### P0（安全与可运营底线）
- 远程工具与 MCP 增加统一出口校验：协议、私网/环回/云元数据拦截、重定向复检、域名白名单。
- 对 MCP 请求头与远程工具认证配置做静态加密，迁移旧数据，日志继续脱敏。
- 为远程工具增加租户归属与可见性，避免全局工具被跨租户修改。
- 增加工具健康与失败率视图：按工具/租户聚合调用日志，暴露最近错误。
- 明确工具幂等标记约定，至少覆盖写文件、发消息、支付类远程调用。

### P1（能力补齐）
- MCP 资源、提示模板、进度回调与流式工具结果。
- OpenAPI/Swagger 导入远程工具，生成参数 Schema 与测试用例。
- 工具版本与废弃流程：版本号、兼容窗口、下线告警。
- 工具级配额与并发上限，接入 D12 的计量口径。
- 工具输出提示词注入防护：信任边界标签、可配置内容过滤。

### P2（生态与成本）
- 工具市场/目录、租户内共享与安装。
- 凭证密钥管理与自动轮换。
- 工具调用熔断、降级与成本计量。
- 浏览器扩展能力扩展到无人值守场景的独立授权模型（需单独安全评审）。
