# 表格录入交互 — 需求

> 在对话中让用户以可编辑表格批量填写结构化数据，提交后作为工具结果回注智能体继续推理。技术实现见 [设计](02-设计.md)。

## 1. 背景与问题

现有确认机制支持单选、多选、自由输入和审批四种模式，适合少量离散选择，但不适合“一次填写多行结构化数据”：

- 用自由输入写多行数据，格式不稳定，模型解析容易出错。
- 用多轮提问逐项收集，交互次数多，用户重复劳动。
- 用户事先看不到字段结构、类型与必填约束，容易漏填或填错。
- 典型场景如报销明细、批量建单、参数清单、名单导入，天然是表格形态。

## 2. 目标

- 智能体可发起一个带列定义的可编辑表格，用户逐行填写后一次性提交。
- 提交结果是按列标识组织的结构化数据，智能体可直接使用。
- 复用既有暂停-恢复与确认通道，不改变现有对话流程和其他确认模式。
- 用户在提交前能看清并满足字段类型、必填与行数约束。

## 3. 范围

### 3.1 纳入

- 新增表格录入这一确认模式，与既有模式并存。
- 列定义：显示标题、唯一标识、类型（文本、数字、日期、下拉、布尔）、必填、默认值、下拉选项、占位提示、列宽。
- 表级控制：预填行、最少行数、最多行数、是否允许增行、是否允许删行。
- 前端可编辑表格的单元格编辑、增行、删行、提交与跳过。
- 提交前的必填校验与行数校验。
- 提交结果回注智能体，以及已确认、已拒绝、超时状态。
- 页面刷新后恢复未决表格。

### 3.2 不纳入

- 表格数据的落库与审计留痕（本次沿用内存中的确认请求）。
- 已提交表格在历史消息中的只读回显（可选，不作为验收项）。
- 后端重启后恢复未决表格（已知约束）。
- 表格内的公式、列间联动、排序筛选、导入导出、附件单元格。
- 渠道侧（IM）的表格录入载体。
- 对现有四种确认模式的改造或重新设计。

## 4. 功能需求

### 4.1 发起与列定义

- 智能体发起表格录入时提供问题描述与列集合，每列至少包含唯一标识与显示标题。
- 列类型支持文本、数字、日期、下拉、布尔，下拉列必须给出可选项；列可标记必填，可设置默认值、占位提示与列宽。
- 表级可指定预填行、最少行数（默认 1 行）、最多行数（未设置则不限）、是否允许增删行（默认允许）。

### 4.2 初始数据

- 提供预填行时，以其作为草稿展示，用户可直接修改。
- 未提供预填行时，按最少行数生成空行；新增行的单元格使用对应列默认值填充。

### 4.3 编辑

- 单元格按列类型渲染匹配的输入控件，占位提示按列定义展示。
- 允许增行时行数达到上限禁用增行；允许删行时行数降到下限禁用删行。
- 不允许增删时，用户只能在既有行上编辑。

### 4.4 校验与提交

- 必填列为空或行数低于最少行数时，禁止提交并给出提示。
- 提交以“通过”状态携带全部行数据，每行按列标识组成一条结构化记录。
- 用户可跳过，以拒绝状态结束，不等同于提交空表。
- 提交只接受一次有效响应，重复提交不产生第二次结果。

### 4.5 结果回注

- 提交后，表格按列标题渲染为可读文本，作为工具结果提供给智能体。
- 按列标识取值，列标题只用于展示；空表或拒绝时给出对应提示，不伪造数据、不补默认行。

### 4.6 生命周期

- 确认请求创建后暂停对话执行，等待用户响应；响应到达后恢复原对话继续输出。
- 超时后按确认机制的统一策略回注超时状态，由智能体决定后续动作。
- 页面刷新后，通过待确认查询恢复包含列定义的未决表格，用户可重新填写。
- 提交后卡片进入已确认状态，展示结果摘要，不再接受编辑。

## 5. 非功能需求

### 5.1 兼容

- 新模式与既有模式共用同一暂停-恢复、事件推送与上行回传通道，既有模式行为不变。
- 新增参数对不使用表格模式的确认请求无影响，旧请求可正常解析。

### 5.2 一致性

- 用户提交走独立的上行请求唤醒运行中的对话，原对话流不中断、不重放、不重复生成内容。
- 前端校验与后端格式化使用同一份列定义：标题取列定义，按列标识取值。
- 后端对空表与拒绝状态有兜底处理，不把歧义数据当作有效表格喂给模型。

### 5.3 可用性

- 校验失败提示应定位到具体列或行数约束，而不是笼统报错。
- 表格在窄屏下仍可编辑和提交，保持响应式基础可用。

### 5.4 已知约束

- 确认请求仅存于内存，后端重启会丢失未决表格，与既有模式一致；不承诺跨重启恢复。
- 渠道会话不提供表格录入载体，不在此形态下承诺该能力。

## 6. 验收标准

- [ ] 智能体发起表格录入后，对话中出现带表头的可编辑表格
- [ ] 文本、数字、日期、下拉、布尔各类型渲染对应输入控件
- [ ] 预填行按原值展示且可修改
- [ ] 无预填行时按最少行数生成，新增行单元格填入列默认值
- [ ] 达到最多行数时增行不可用；达到最少行数时删行不可用
- [ ] 不允许增删时，用户无法增加或删除行
- [ ] 必填列为空时提交被禁用并提示具体列
- [ ] 行数低于最少行数时提交被禁用并提示
- [ ] 提交后智能体收到按列标识组织的结构化数据，并据此继续推理
- [ ] 提交后的卡片显示已确认状态与结果摘要，不能再编辑
- [ ] 用户跳过后智能体收到拒绝状态，不被当作空表提交
- [ ] 超时后智能体收到超时状态并按自身策略继续
- [ ] 页面刷新后未决表格恢复，列定义完整，用户可重新填写并提交
- [ ] 重复提交同一确认请求只产生一次有效结果
- [ ] 既有单选、多选、自由输入、审批模式无行为回归
- [ ] 后端收到空表或拒绝响应时不生成伪造的表格结果
