# D08 交互与人机协同

> **解决什么问题**：企业场景不是"一个聊天框解决一切"。同一个智能体要能出现在管理端、用户门户、IM、开放 API 和嵌入组件里；执行过程中要能暂停问人、能被中断、能看见进度、能把产物交付出去。
> **适用读者**：前端、后端、渠道集成、产品、交付实施。
> **关联文档**：[D02 智能体运行时](../D02-智能体运行时/README.md) · [D04 工具与外部集成](../D04-工具与外部集成/README.md) · [D07 多智能体协作](../D07-多智能体协作/README.md) · [D10 安全合规与审计](../D10-安全合规与审计/README.md) · [能力全景 §5 D8](../../00-平台总览/README.md)
> **状态基准**：2026-11 实现。状态只用「已具备 / 部分 / 缺失」。

---

## 1. 边界

**本文负责**：交互形态、流式体验、结构化确认与工具审批、任务可视与后台执行、产物交付、渠道接入与治理、页内界面操作、多语言与无障碍。

**本文不负责**：单智能体推理循环（D02）、工具安全策略本身（D04）、身份与租户模型（D01）、产物存储的底层实现（对象存储/沙箱）。本文只定义"用户如何触达智能体、智能体如何把控制权交还给人"。

**核心判断**：交互形态决定触达范围，人机协同决定可控性。确认要在关键动作前把执行权交回用户；渠道要治理身份、会话、幂等与失败。

## 2. 能力清单

### 2.1 交互形态

| 形态 | 要求 | 本项目状态 |
|---|---|---|
| 管理端 Web | 配置、调试、运营与对话一体 | 已具备（30+ 页面） |
| 用户端门户 | 普通用户只对话、会话管理，配置脱敏 | 已具备 |
| IM 渠道 | 飞书 / 企微 / 钉钉 / Slack / Teams，身份绑定、会话映射 | 部分（飞书、企微应用、企微机器人） |
| 开放 API | 机器调用、API Key、版本化 | 已具备 |
| CLI | 本地对话与运维命令 | 已具备 |
| 嵌入组件 / SDK | 第三方页面嵌入、访客访问 | 缺失 |
| 移动端 | 窄屏可用、确认卡片可操作 | 部分（响应式门户，无独立 App） |

### 2.2 流式体验

- 首字延迟可控；思考过程可折叠；工具执行有进度；错误可读；随时可中断。
- 后台任务脱离请求生命周期，断线可重连并恢复事件。
- 渠道没有原生事件流，需用流式卡片或占位消息加节流更新模拟。
- 本项目 Web 与 CLI 已具备；渠道侧飞书使用流式卡片，企微按能力降级。

### 2.3 人机协同

- 结构化提问：单选、多选、自由输入、审批、表格录入。
- 工具执行前确认：按风险级别与信任级别触发，确认内容包含实际参数。
- 运行模式：任务级 Ask / Plan / Agent 与 Agent 全自动档的选择与切换由交互层承载，定义见 [D02 运行模式](../D02-智能体运行时/运行模式/01-需求.md)。
- 超时策略：不同场景不同超时与超时行为。
- 确认记录：可恢复、可审计、可绑定到具体会话/成员/任务。
- 多智能体场景：子智能体确认冒泡并标注来源。

### 2.4 任务可视

- 长任务进度、后台运行、断线恢复、完成通知；用户不在线时还需要通知与待办。
- 本项目有后台运行记录、事件持久化、重连、停止、宠物任务条事件与定时任务通知。

### 2.5 产物交付

- 文件下载、网页产物、图表、图片、消息卡片。
- 产物权限与过期：不能凭地址越权访问，历史卡片不能因签名过期失效。
- 本项目有文件变更记录、网页产物令牌访问、图片附件、渠道文件发送。

### 2.6 渠道治理

- 渠道配置、凭证校验、启停、连接状态与最近错误。
- 用户身份绑定、会话映射、消息去重、串行排队、失败重试。
- 工具黑名单、敏感词、静默策略。
- 本项目配置与凭证、身份绑定与会话映射、工具黑名单已具备；失败重试与敏感词/静默治理仍不完整。

### 2.7 多语言与无障碍

- 企业全球化需要界面多语言；无障碍需要键盘操作、屏幕阅读器与颜色之外的语义。本项目当前均缺失。

## 3. 本项目现状

### 3.1 已具备

- **多入口**：管理端对话页、用户门户、飞书、企微应用、企微机器人、命令行、开放 API。门户只暴露脱敏后的智能体字段（标识、名称、描述、图标、欢迎语、快捷提问）。
- **统一流式处理**：管理端各对话页面的事件处理收敛为同一实现，门户复用。
- **五种确认模式**：单选、多选、自由输入、审批、表格录入；前端有对应卡片、倒计时、已确认态、预览与可编辑表格。
- **暂停-恢复协议**：结构化提问在运行循环内拦截（不进工具执行器），经事件队列推送确认请求，以阻塞等待挂起，上行回包唤醒；超时受控；页面刷新可通过待确认查询恢复。
- **工具审批**：按信任级别与工具权限决定是否走审批；始终询问、仅危险操作询问、全部自动三档。
- **命令系统**：Web 与渠道共用命令注册表，覆盖帮助、会话管理、上下文与用量、停止、模型、批准/拒绝、定时任务等；Web 有命令候选菜单。
- **后台任务与重连**：运行记录、事件持久化与共享任务注册；前端可重连回放、显式停止。
- **任务可视**：宠物任务条事件（快照、开始、工具、结束），支持渠道任务即时展示与断线快照恢复。
- **定时任务通知**：结构化结果上报；投递状态区分已发送、主动静默、未请求、失败与未知，静默与发送失败可追溯。
- **产物交付**：工作区文件变更自动检测并附着消息；网页产物生成后以独立源加短时令牌访问；图片附件与渠道文件发送。
- **页内界面操作**：前端执行类工具、虚拟光标、聚光灯、危险动作二次确认、回包超时、断线取消、失败熔断。
- **宠物交互形态**：精灵图状态机联动、绑定智能体的气泡与闲聊、动作名称两级自定义、宠物动作控制、零 token 降级。
- **渠道治理基础**：渠道增删改查、凭证校验、长连接与回调双模式、身份绑定码、会话映射、事件去重、会话级串行队列、停止与撤回即停、工具黑名单、流式节流。

### 3.2 部分具备

- **确认记录**：确认请求仅保存在内存，进程重启即丢失；只有聊天室把确认绑定到成员任务持久化，普通会话没有审计记录。
- **信任级别联动**：信任级别控制工具审批，但不控制模型主动发起的结构化提问；全部自动模式下模型仍可弹确认卡片。
- **子智能体确认冒泡**：子运行时复用父级事件队列，事件可冒泡；来源标注依赖上下文注入，未形成统一字段契约。
- **渠道确认能力**：渠道会话直接过滤结构化提问，避免死等；批准/拒绝命令在渠道只能返回文本，没有可交互确认载体。
- **产物权限**：网页产物用短时令牌加归属校验，文件用工作区权限；缺统一的产物级访问控制、过期策略与访问审计。
- **渠道失败重试与治理**：出站发送失败有记录与部分降级，但没有统一重试队列；多 worker 下撤回/停止是进程内尽力而为。有工具黑名单，缺敏感词过滤、静默策略配置、渠道级配额。
- **门户**：门户已上线且脱敏，但移动端只是响应式基础可用，未做移动端专项。

### 3.3 缺失

- 钉钉 / Slack / Teams 渠道；嵌入组件 / SDK、访客访问、分享链接。
- 多语言与无障碍（键盘、播报、色盲友好仅零散存在，未系统化）。
- 外部审批流 / 工单系统集成；用户离线时的确认与通知策略（如邮件/推送、超时后转人工待办）。
- 统一的产物权限模型与访问审计。
- 任务级运行模式的选择与切换（Ask / Plan / Agent）；当前只有动作级信任级别。

## 4. 关键设计

### 4.1 确认请求生命周期

1. 模型发起结构化提问，携带问题、交互模式、选项、上下文与表格列定义。
2. 运行时在当前迭代内直接拦截，创建仅内存保存的待确认请求，包含阻塞事件、超时时间与租户信息。
3. 向事件队列推送确认请求，并让事件流先排空队列。
4. 前端渲染确认卡片；用户提交走独立的上行接口。
5. 上行接口解析回包并唤醒运行循环。
6. 运行循环推送已确认事件，把结果格式化为工具结果注入消息，继续推理。
7. 超时或连接关闭时以超时状态回注，模型自行决定后续。

**设计要点**：事件流只下行，回包走上行；确认不进工具执行器，否则阻塞会卡死事件队列排空。

### 4.2 表格录入

- 复用同一暂停-恢复协议，仅新增表格录入模式与列定义。
- 列定义包含类型、必填、默认值、选项、占位提示与列宽；表级包含初始行、最少/最多行、是否可增删。
- 前端以可编辑表格渲染，提交前校验必填与行数。
- 提交结果以结构化表格回注模型；页面刷新可恢复未决表格。
- 已知约束：确认请求仅存内存，后端重启会丢失未决表格。

### 4.3 渠道入站治理

- 传输层归一化为统一入站事件，下游管线与渠道类型解耦。
- 去重：事件标识在内存中保留一小时，重复事件直接确认。
- 串行：每个会话键一个队列与消费者，逐条驱动，避免同一会话并发运行多个智能体。
- 身份：按租户与外部用户标识绑定平台用户；未绑定只回绑定引导，不创建账号。
- 会话：按渠道、会话与外部用户标识映射平台会话；新会话命令使旧映射失效。
- 中断：停止命令取消在跑任务并清空队列；撤回事件按消息标识反查并取消；秒撤回用短时集合兜底。
- 出站：飞书优先流式卡片；不支持时降级为完成后一次性发送；超长分片。
- 工具面：渠道会话强制过滤结构化提问、委派与前端工具，再叠加渠道黑名单。

### 4.4 任务可视与后台执行

- Web 聊天任务：持久化运行状态与事件，前端断线后按运行回放，避免重复提交。
- 渠道任务：任务注册写入共享缓存并发布事件，按用户分发到事件流，连接建立先发快照再发增量。
- 定时任务：执行与投递状态分离；发送前先记为未知，成功记已发送，静默记主动静默并保留原因。
- 停止语义：已完成动作不回滚；无法立即取消的外部操作显示真实状态，不谎报已撤销。

### 4.5 产物交付

- 文件变更：平台在写入型工具执行前后比较工作区文件清单，生成创建、修改、删除，按轮合并后附着助手消息；预览与下载复用工作区权限。
- 网页产物：生成后保存并返回短小的访问地址与标题；访问时校验归属与短时令牌；建议独立源与内嵌框架沙箱双重隔离。
- 图片与附件：Web 上传、渠道下载后进入工作区；视觉模型可直接喂图，非视觉模型降级为路径引用。渠道文件支持把工作区文件作为渠道消息发送，各渠道能力存在差异。

### 4.6 页内界面操作

详细需求与技术方案见 [D04 浏览器页面自动化](../D04-工具与外部集成/浏览器页面自动化/01-需求.md)。

- 后端工具标记为前端执行，运行循环拦截后推送页内操作请求，前端注册表执行，上行回包唤醒。
- 前端只执行注册表内处理器，不执行任意脚本；导航限平台路由白名单。
- 危险动作先走确认流程；回包超时默认 60 秒；断线或刷新时取消全部或回页面已刷新。
- 虚拟光标从宠物位置出发，聚光灯高亮目标，动作队列串行；宠物状态随执行切换工作、庆祝、沮丧。

### 4.7 失败模式

| 失败 | 当前行为 | 风险 / 缺口 |
|---|---|---|
| 确认无人响应 | 超时回注超时状态，模型自决 | 高风险场景可能被模型"自行决定" |
| 确认进程重启 | 内存丢失，前端待确认列表为空 | 用户无法恢复，任务悬挂至超时 |
| 渠道重复投递 | 事件标识去重 | 多 worker 下内存去重不共享，需共享缓存 |
| 渠道发送失败 | 记录失败或未知，部分降级 | 无统一重试队列，可能丢回复 |
| 渠道确认 | 结构化提问被过滤 | IM 用户无法完成需要确认的任务 |
| 网页产物令牌 | 短时令牌加归属校验 | 令牌泄露窗口、无访问审计 |
| 页内操作页面刷新 | 前端回页面已刷新，智能体继续 | 动作已执行但结果未知，可能重复操作 |
| 长任务断线 | 运行回放或快照恢复 | 渠道侧多 worker 下停止是尽力而为 |

## 5. 实施建议

### P0（可控性与一致性）

1. **确认审计持久化**：新增确认记录（会话、用户、智能体、模式、问题、选项、响应、状态、时间），响应时写入；刷新恢复从持久化记录读，而不是只靠内存。
2. **渠道确认载体**：为飞书/企微实现交互卡片确认，或明确"渠道不支持确认"的产品降级（如禁止危险工具），不要静默过滤后让任务失败。
3. **渠道去重与取消跨 worker**：把事件去重、在跑任务登记、停止广播迁到共享缓存，消除多副本不一致。
4. **产物访问统一**：网页令牌、工作区文件、渠道文件统一走"归属校验 + 过期 + 审计"，禁止只靠不可猜地址。

### P1（覆盖更多场景）

5. 增加钉钉 / Slack / Teams 适配器，复用渠道类型描述与入站管线。
6. 离线通知：用户不在线时，确认请求与任务完成通过渠道或邮件触达，并保留待办。
7. 渠道失败重试队列与死信，发送失败可重放且不重复。
8. 敏感词与静默策略配置化，区分"不发送"与"发送但脱敏"。
9. 门户移动端专项与嵌入组件 MVP（访客令牌、限流、会话来源扩展）。

### P2（体验与合规）

10. 多语言（界面文案与系统提示模板分离）。
11. 无障碍：键盘全流程、播报区域、风险等级不依赖颜色。
12. 外部审批流/工单集成，把高风险确认接到企业既有流程。
13. 产物版本、分享与访问审计看板。
