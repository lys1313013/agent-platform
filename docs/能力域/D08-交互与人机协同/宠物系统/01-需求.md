# 宠物系统 — 需求与设计

> 合并说明：本文由 3 份原始文档合并，内容保持原样，仅调整标题层级。

## 宠物系统需求文档

> 日期：2026-08-02
> 目的：参考 OpenAI Codex Pets（2026-05 上线）为平台增加桌宠/陪伴宠物系统，将 Agent 运行状态可视化，提供情绪价值与轻度养成玩法。**硬性要求：宠物资源包直接兼容 Codex 宠物文件格式**，社区已有宠物（petdex 生态）可零改造导入使用。

### 1. 背景与目标

Codex Pets 的核心价值不是"养宠物"，而是**给 Agent 装上"在场感"**：宠物作为一个常驻悬浮窗，把 Agent 的运行状态（忙/闲/完成/出错）以动画形式表达出来，用户切走页面也能感知任务进度。本平台是 Web 应用，没有桌面客户端，宠物载体改为**Web 端全局悬浮组件**。

目标：

- 宠物常驻聊天页（可全局开启），动画状态与 Agent SSE 事件实时联动。
- 兼容 Codex 宠物包格式（`pet.json` 清单 + 精灵图），支持导入 petdex 社区宠物。
- **用户可自助上传宠物包，默认仅自己可见**；可见性按租户隔离可调（仅自己 / 本租户 / 全平台公开），管理员可上架官方宠物包。
- 纯前端渲染 + 确定性状态机，**宠物本身不调用 LLM，零 token 消耗**。

### 2. 参考对象分析（Codex Pets）

| 维度 | Codex Pets | 本平台对应方案 |
|---|---|---|
| 载体 | 桌面 App 悬浮窗（类灵动岛） | Web 页面右下角悬浮组件，全局可拖拽 |
| 唤醒/收起 | `/pet` 命令、Cmd+K | `/pet` 斜杠命令 + 侧边栏开关 + 悬浮球本身 |
| 内置宠物 | 8 款 | 首期内置 4 款，其余走导入 |
| 自定义宠物 | `/hatch` AI 生成 / `npx petdex install` / 放 `~/.codex/pets/` 目录 | 用户自助上传宠物包（zip），格式与 Codex 一致；管理员另可发布官方包 |
| 状态联动 | 运行中忙碌、等待输入待机、完成庆祝 | 复用 SSE 事件流：reasoning/tool_call → 工作态，等待输入 → 待机，任务完成 → 庆祝，出错 → 沮丧 |
| 能力边界 | 纯陪伴，不能执行代码或聊天 | 同样纯展示，不进 Agent 工具循环 |
| 养成 | 无（仅外观收集） | 无经验/等级，纯陪伴展示 + 情绪反馈 |

### 3. 角色与范围

| 角色 | 能力 |
|---|---|
| 普通用户 | 开启/关闭宠物、选择已激活宠物、互动、**上传自己的宠物包并设置可见性（默认私有，可随时改成仅自己可见 / 租户内 / 公开）**、从宠物市场领养可见的宠物 |
| 管理员 | 拥有普通用户全部能力，另可：发布官方宠物包、强制下架任何公开/租户内宠物包、查看全平台宠物使用数据 |

可见性模型（四档，创建人可随时调整，**包括随时改回只有自己可见**）：

| 可见性 | 谁能看到 / 领养 | 谁能设置 |
|---|---|---|
| `private`（私有，默认） | 仅创建人本人 | 创建人 |
| `tenant`（租户内） | 与包同租户的全部用户（出现在其市场） | 创建人 |
| `public`（公开） | 全平台所有租户用户 | 创建人；管理员可强制下架 |
| `official`（官方） | 全平台用户（市场置顶标识） | 仅管理员 |

隔离规则：

- 包归属一个租户（`tenant_id`，上传时取创建人的当前租户），`tenant` 可见性即"该包 `tenant_id` 下的用户可见"。
- 创建人改可见性即时生效；从 `tenant`/`public` 收回为 `private` 后，**已领养的其他用户保留已领养宠物**，仅新用户不可再领养、不再出现在任何市场列表。
- 跨租户绝对隔离：A 租户用户对市场、搜索、包 ID 直查、资源 URL 均无法触达 B 租户的 `private`/`tenant` 包（接口返回 404，不暴露存在性）。
- 用户属于多个租户（`tenant_memberships`）时，市场展示"当前激活租户"可见的包；上传的包归属上传时的激活租户，不随用户切换租户而漂移。

不在本期范围：宠物对话（LLM 驱动）、宠物间社交、移动端 App、飞书渠道宠物。

### 4. 功能需求

#### 4.1 宠物悬浮组件（核心）

- 聊天页右下角常驻悬浮宠物，可拖拽换位，位置记忆（localStorage）。
- 位置锚定：不记绝对像素，而记「距最近两条边的距离」（如：右边 24px + 底边 24px）。窗口缩放、外接显示器拔除后宠物保持对同一边角的相对距离，来回拉伸窗口位置可还原；窗口缩得过小时自动贴边，绝不渲染到视口外。收起/展开导致尺寸变化时同样按边距重算。旧版绝对像素格式的本地数据在加载时自动换算为锚定坐标。
- 全局开关：用户设置里"显示宠物"关闭后所有页面不渲染。
- 收起态：缩为一个 32px 小球，点击展开。
- 动画渲染：Canvas 或 CSS sprite 播放精灵图帧动画，帧率按宠物包清单定义；页面不可见时暂停渲染（`document.visibilitychange`）。

#### 4.2 状态联动（状态机）

宠物状态由当前会话的 Agent 运行状态驱动，映射规则：

| Agent 状态（来源） | 宠物动画 | 说明 |
|---|---|---|
| 无会话 / 会话空闲 | `idle` | 眨眼、呼吸、随机小动作 |
| LLM streaming 中（`reasoning:` / `text_delta:`） | `think` | 思考动画 |
| 工具执行中（`tool_call:` 发出未返回） | `work` | 工作/忙碌动画 |
| 等待用户确认（AskUserQuestion 卡片挂起） | `wait` | 指向屏幕/期待动画 |
| 任务完成（AgentLoop 结束，无 tool_calls） | `celebrate` | 播放一次庆祝动画后回 idle |
| 执行出错 / 用户 `/stop` | `sad` | 沮丧动画，5 秒后回 idle |
| 用户 30 分钟无交互 | `sleep` | 睡觉动画 |

并发会话时以"最近活跃的会话"为准。状态机在前端 `chatStore` 派生，不改后端 SSE 协议。

#### 4.3 互动

- 点击宠物：播放 `happy` 动画 + 随机气泡文案（本地文案库，不走 LLM）。
- 拖拽甩动：松手播放 `dizzy` 动画（彩蛋）。
- 右键/长按：快捷菜单（收起、换宠物、去设置）。

#### 4.5 宠物管理与市场

- 新增"宠物"设置页（路由 `/settings/pets` 或独立 `/pets`），分三个区块：
  - 我的宠物：已领养/已上传的宠物列表，缩略图、当前激活标记、启用/禁用开关。
  - 我的上传：自己上传的宠物包，显示可见性标识（私有/租户内/公开），可修改可见性、删除（见 4.6）。
  - 宠物市场：当前用户可见的全部宠物包（`official` + `public` + 本租户 `tenant` 包，official 置顶带标识），卡片式展示（预览动画直接播放精灵图），点击"领养"后即可激活。
- 每个用户同时只激活 1 只宠物；切换即时生效。

#### 4.6 宠物包上传与权限

- **用户上传**：宠物页提供"上传宠物包"入口，两种方式——直接选择 **zip 文件**，或**选择整个文件夹**（前端用 `webkitdirectory` 遍历目录、保留目录结构打包成 zip 后走同一接口）。上传后默认为 `private` 且归属创建人当前租户。
- **可见性调整**：创建人可在 私有 / 租户内 / 公开 间随时切换（含随时改回仅自己可见）；管理员另可设 `official`。收窄可见性（公开→租户内→私有）后：
  - 已领养该包的其他用户**保留已领养宠物**，但不可见范围内的新用户无法再领养；
  - 创建人删除包时同理：已领养的用户保留使用权，仅包本身从所有市场消失。
- **管理员**：可上传官方包（`official`）、强制下架任何公开/租户内包（下架 = 转回私有效果）、删除违规包。
- 上传时后端统一校验（用户与管理员同一链路）：解压 → 校验 `pet.json` schema → 校验精灵图尺寸与清单声明一致 → 资源转存对象存储（MinIO，按 `pets/{tenant_id}/{owner_id}/{package_id}/` 前缀隔离存放）→ 写库。
- 校验失败给出具体错误（缺字段 / 帧尺寸不符 / 图片过大），不静默降级。
- **行映射**：上传对话框展示精灵图每行预览（播放动画），用户把各行拖给平台状态（idle 必选，其余可留空降级）；默认 row0=idle。映射存 `row_mapping`，不改原 pet.json。
- 配额限制：普通用户最多上传 20 个包，单包解压后 ≤ 10MB，防对象存储被刷。

### 4.9 工作区隔离

- 宠物闲聊会话属于当前工作区：按“用户 + 宠物 + 工作区”复用，切换工作区不会复用其他工作区的宠物会话。
- 新建宠物会话时写入当前工作区；会话中的文件、产物与上下文只在对应工作区内可见。
- 宠物任务条只展示当前工作区的在跑任务；切换工作区时清空已显示任务，再按新工作区重新拉取快照。
- 渠道触发的任务在创建时记录所属工作区；没有工作区归属的历史任务不进入任何工作区的任务条。
- 工作区不存在或不属于当前用户时，宠物会话创建返回明确错误，不落库。

### 5. Codex 宠物包格式兼容（硬性需求）

#### 5.1 兼容目标

**从 petdex 生态下载的宠物包（zip 或目录）可不经修改直接导入本平台运行。** 用户的 Codex 本地宠物目录 `~/.codex/pets/<pet>/` 可直接通过"选择文件夹上传"导入（前端打包成 zip，目录名成为 zip 内一级目录，后端按前缀定位 `pet.json`）。

#### 5.2 包结构（已用真实包校准，2026-08-02）

> 以下格式基于对本机 `~/.codex/pets/` 下 5 个真实宠物包（doraemon / iikun / kun-like / noir-webling / vv）的逆向分析，**以此为准**。

```
<pet-name>/
├── pet.json            # 清单（必需，极简）
└── spritesheet.webp    # 精灵图（必需，文件名由清单指定）
```

真实 `pet.json` 全部字段（无任何动画/帧元数据）：

```json
{
  "id": "doraemon",
  "displayName": "Doraemon",
  "description": "A compact blue robot-cat Codex pet ...",
  "spritesheetPath": "spritesheet.webp",
  "spriteVersionNumber": 2,   // 可选，精灵图版本号
  "kind": "object"            // 可选，缺省为角色型宠物
}
```

精灵图约定（实测）：

- **RGBA WebP**，透明背景（非绿幕——图中绿色是生成残留，alpha 通道才是真背景）。
- **规则网格均分**：实测包均为 **192×208 px/帧、8 列**；行数不等（doraemon 9 行 72 帧，vv 11 行 88 帧）。上传时不硬编码帧尺寸，按"整除检测"推断：宽能被 8 整除且高能被行数整除，取 `192×208` 为首选假设，失败则尝试其他均分并让用户在上传预览中确认。
- **每行 = 一个动画，列 = 帧序列**（行间帧数可不满，尾部空帧 alpha 全 0，播放时跳过）。
- **Codex 有标准 9 行索引语义（2026-08-02 用 4 个本地官方包 + spec 校准）**：`pet.json` 确实不含动画字段，但 Codex 通过**固定的 9 行精灵图布局**隐含行序语义，行帧数实测 `[6,8,8,4,5,8,6,6,6]` 与官方约定逐行吻合：

  | 行 | 动画 | 帧数 | 平台状态 |
  |---|---|---|---|
  | 0 | idle 待机 | 6 | `idle` |
  | 1 | running-right | 8 | — |
  | 2 | running-left | 8 | — |
  | 3 | waving 挥手 | 4 | `happy` |
  | 4 | jumping 跳跃 | 5 | `celebrate` |
  | 5 | failed 失败 | 8 | `sad` |
  | 6 | waiting 等待 | 6 | `wait` |
  | 7 | running 工作中 | 6 | `work` |
  | 8 | review 思考 | 6 | `think` |

  `sleep` 无对应行 → 降级 `idle`。

- **自动映射**：≥9 行的包上传时按上表自动生成完整 `row_mapping`（存入平台侧字段，不改动原 pet.json），**无需手动配置**；用户显式传入的映射覆盖默认值，仍可在上传后通过弹窗调整。不足 9 行的自定义包不猜测，仅保证 `row0=idle`，其余需手动指定。

#### 5.3 完整映射链路（单一权威参考）

三层映射串起来：**Agent 运行事件 → 平台状态 → Codex 精灵图行**。标准 9 行包全部自动映射；未映射的状态在运行时降级 `idle`。

| 平台状态 | 触发（Agent 事件） | Codex 行 | 行动画 | 帧数 | 默认自动映射 |
|---|---|---|---|---|---|
| `idle` | 会话空闲 / 默认 | 0 | idle 待机 | 6 | ✅ |
| `think` | LLM streaming（`reasoning:` / `text_delta:`） | 8 | review 思考 | 6 | ✅ |
| `work` | 工具执行中（`tool_call:` 未返回） | 7 | running 工作中 | 6 | ✅ |
| `wait` | AskUserQuestion 卡片挂起 | 6 | waiting 等待 | 6 | ✅ |
| `celebrate` | 任务完成（AgentLoop 正常结束） | 4 | jumping 跳跃 | 5 | ✅ |
| `sad` | 执行出错 / `/stop` | 5 | failed 失败 | 8 | ✅ |
| `happy` | 用户互动（点击/右键动作） | 3 | waving 挥手 | 4 | ✅ |
| `sleep` | 30 分钟无交互 | — | 无对应行 | — | ❌ → 降级 `idle` |
| — | running-right / running-left | 1 / 2 | 左右移动 | 8 | 平台未使用（保留给桌面端） |

**互动播放**（右键菜单「播放动画」/ 左键点击）：**直接按精灵图行操作**，不走 `row_mapping`。菜单列出精灵图的每一行，行名优先取动画映射里该行对应的状态名（待机/开心/工作…），否则取 Codex 标准行名（挥手/跳跃/思考…），都没有则显示「动画 N」。点击任一行即播放该行动画，并向后端上报一次 interact（仅校验归属并刷新实例数据，无经验奖励）。

> 映射存于 `pet_packages.row_mapping`（JSONB，平台侧字段），不改动原 `pet.json`。运行时 `resolveRow(state) = row_mapping[state] ?? row_mapping.idle ?? 0`；互动播放行由前端直接指定 `row`，不经此函数。

#### 5.4 兼容规则

1. **原包零修改**：上传的 zip/目录原样保存，pet.json 原文存入 manifest JSONB；平台附加数据（行映射、可见性）存平台字段，保证包可双向流通（导出回 Codex 逐字节一致）。
2. **未知字段原样保留**：`kind`、`spriteVersionNumber` 及未来新增字段不丢弃。
3. **状态动画缺失降级**：必需映射只有 `idle`；`think/work/wait/celebrate/sad/sleep/happy` 未映射的行一律降级为 `idle`（celebrate 降级时加速播放一遍再回 idle）。
4. **资源限制**：单张精灵图 ≤ 4096×4096、解压后单包 ≤ 10MB、帧数 ≤ 512，超限拒绝上传（防恶意大图撑爆浏览器内存）。
5. **Codex 特有行为不实现**：依赖桌面端的能力（窗口跟随、多屏游走）忽略，仅保证动画正确渲染。
6. **导出**：平台内上传的包支持重新下载，下载产物与原包逐字节一致。

> 数据模型、接口与前端设计见 [02-设计.md](02-设计.md)。

### 6. 非功能需求

- **零 token**：宠物所有行为不经过 LLM，气泡文案为本地静态文案库。
- **性能**：悬浮组件空闲时 CPU 占用可忽略（requestAnimationFrame + 页面不可见暂停）；精灵图懒加载，未激活宠物不下载。
- **隔离**：宠物接口 5xx、气泡生成失败均不影响聊天主流程，前端组件崩溃不带出白屏（ErrorBoundary 局部降级为不显示宠物）。
- **安全**：上传 zip 服务端解压校验（防 zip slip、限制总大小 10MB、限制文件数）；图片仅允许 png/webp/gif。
- **多租户与权限**：宠物包按租户 + 创建人双重维度隔离——`private` 仅创建人可见，`tenant` 仅同租户可见，跨租户用户对市场、搜索、直接访问包 ID / 资源 URL 均不可触达（接口返回 404 而非 403，不暴露存在性）；RLS 使用 `app.current_tenant_id` + `app.current_user_id` 双重上下文；`user_pets` / `pet_exp_logs` 按 `user_id` 隔离。

### 7. 分期计划

| 阶段 | 内容 |
|---|---|
| P0（本期） | 悬浮组件 + 状态机联动、内置 4 款宠物（官方包）、**用户上传 Codex 格式包 + 私有/租户内/公开三档可见性 + 租户隔离**、市场领养激活、真实 petdex 包格式校验与 schema 校准 |
| P1 | 互动动画与气泡、气泡配额、绑定智能体闲聊 |
| P2（待定） | 宠物导出回 Codex 格式、飞书消息卡片内宠物状态展示、官方包运营位 |

### 8. 验收标准

1. 从 petdex 下载的宠物包 zip 上传后无需修改即可预览并被激活使用。
2. 用户上传的包默认私有：其他用户（含同租户）在市场看不到、按包 ID 访问接口返回 404、资源签名 URL 无法签发。
3. 创建人将包改为「租户内可见」后，同租户用户可领养，其他租户用户仍不可见；改为「公开」后全平台可领养。
4. 创建人随时可将包改回「只有自己可见」：此后新用户（含同租户）不可再领养、市场不再展示，已领养用户数据与使用权不受影响。
5. Agent 执行任务全过程中，宠物动画按 4.2 映射表正确切换，任务结束播放庆祝动画。
6. 宠物接口全部不可用（断网/500）时，聊天功能无任何影响。

## 宠物绑定智能体需求文档

> 日期：2026-08-03
> 前置文档：《需求》第一部分（宠物系统基础）
> 目的：让宠物从"本地动画 + 静态文案"升级为"有灵魂的伙伴"——为宠物绑定一个平台智能体（Agent），点击互动、闲聊、任务反馈由该 Agent 以宠物人设生成，气泡文案不再写死。绑定为可选项，未绑定时维持现有零 token 行为。

### 1. 背景与动机

现状（P0/P1 已上线）：

- 宠物气泡文案是前端写死的本地文案库（`PetWidget.tsx` 的 `BUBBLES`），随机抽取，内容与宠物形象、上下文完全无关。
- 原需求明确"宠物本身不调用 LLM，零 token 消耗"，宠物对话被列为"不在本期范围"。

问题：

- 静态文案玩几次就腻，互动没有记忆点；绑定 Agent 后宠物才拥有性格与陪伴感。
- 平台已有完整的 Agent 体系（人设 prompt、模型配置、工具、记忆），宠物是 Agent 人设最自然的具象化载体——**宠物 = Agent 的皮**。

目标：

- 用户可给自己的宠物绑定一个 Agent（自己的或租户内可见的），互动气泡、闲聊对话由该 Agent 以宠物人设实时生成。
- 宠物包作者可为包配置"推荐人设 Agent"，领养者未绑定时自动继承（如官方哆啦A梦包配一个蓝胖子人设 Agent）。
- 不绑定/Agent 调用失败时无缝降级回本地静态文案，**聊天主流程与宠物渲染永远不受 LLM 故障影响**。
- 成本可控：互动走独立配额与参数约束，不影响主对话 token 预算。

### 2. 核心概念

#### 2.1 绑定模型（两级，实例优先）

| 层级 | 字段 | 谁设置 | 作用 |
|---|---|---|---|
| 宠物包级（默认人设） | `pet_packages.default_agent_id`（可空） | 包创建人 / 管理员（官方包） | 包的"出厂人设"，领养者未绑定时生效 |
| 宠物实例级（我的绑定） | `user_pets.agent_id`（可空） | 宠物拥有者 | 个人绑定，**优先级高于包级默认** |

解析顺序：`user_pets.agent_id` → `pet_packages.default_agent_id` → 无（本地静态文案）。

- 绑定关系随宠物走：切换激活宠物即切换互动人设；同一包被不同用户领养，各自绑定互不干扰。
- 解绑（置空）即时生效，回退到下一级。
- 包被删除/下架不影响已领养用户的绑定关系（沿用 4.6 既有规则：领养数据保留）。

#### 2.2 可绑定的 Agent 范围

- 包级默认：包创建人可见的 Agent（自己创建的 + 本租户 `tenant` 可见的）。注意**可见性错配**场景：`private` Agent 设为公开包的默认人设时，其他领养者不可见该 Agent——此时包级默认对该用户视为不存在，降级处理（不越权暴露 Agent 内容）。
- 实例级：当前用户可见的 Agent（同会话页选择范围：`agents` 列表接口已有可见性过滤）。
- 校验时机：设置时校验；使用时每次解析**实时校验可见性**（Agent 后续可能被改私有/删除），不可见即降级，不报错。

#### 2.3 宠物人设的合成

绑定 Agent 不等于直接裸用其 system_prompt——Agent 可能是"数据分析师"人设，与宠物形象冲突。互动时系统提示词按模板合成：

```
{agent.system_prompt}

---
你现在是用户的桌面宠物「{pet.display_name}」（{pet.kind ?? '角色型'}）。
当前状态：{mood}（idle/think/work/wait/celebrate/sad/sleep/happy）。
以宠物口吻说话：简短、口语化、有性格，单次回复不超过 {N} 字。
不要用列表、代码块、markdown；不要暴露你是 AI 助手或提到"系统提示词"。
{context_section}  // 可选：刚完成的任务摘要、出错信息、时间段等
```

- 模板为平台内置常量，用户不可改（防止注入绕过"简短回复"约束）；Agent 自己的 system_prompt 在前，保证人设主体来自用户配置。
- `max_tokens` 强制收紧（见 5.2），人设约束与参数约束双保险。

### 3. 功能需求

#### 3.1 绑定管理（P0）

- 宠物页「我的宠物」每张卡片增加"绑定智能体"入口：下拉选择当前用户可见的 Agent，或"跟随宠物包默认"/"不绑定"。
- 宠物包管理（我的上传）：可为包设置"默认人设 Agent"，下拉范围同创建人可见 Agent；未设置时显示"无（静态文案）"。
- PetWidget 右键菜单增加当前绑定状态展示（如"人设：哆啦A梦助手"），点击跳转宠物页设置。
- 绑定变更即时生效，无需重新激活宠物。

#### 3.2 智能互动气泡（P0）

- 触发点沿用现有交互：左键点击、右键"播放动画"各行。
- 已绑定 Agent 时：气泡文案改为调用 Agent 生成一句话（流式，逐字上屏），同时播放对应动画、向后端上报一次互动（无经验奖励）。
- 生成输入：合成人设 prompt + 触发上下文（触发的动画状态、点击还是菜单动作、当前时间）。**不带历史对话**——气泡是单轮，避免上下文累积成本。
- 未绑定 / Agent 不可见 / 调用失败 / 超时（前端 3s）：静默回退本地静态文案库，不打断动画。
- 流式期间气泡跟随文字增长，上限 60 字截断展示。

#### 3.3 宠物闲聊（P0）

- 右键菜单新增「和 TA 聊聊」（仅已绑定时可用，未绑定置灰提示"先绑定智能体"）。
- 点击后在 PetWidget 旁弹出轻量聊天面板（非全屏对话页）：类似客服浮窗，支持多轮对话、流式渲染、关闭即结束。
- 实现路径：**复用现有会话基础设施**——后端为该宠物会话创建/复用一个 `conversations` 记录（`agent_id` = 解析后的绑定 Agent，`source = 'pet'`，标题自动生成为"与{display_name}的闲聊"），SSE 协议零改动。
- 系统提示词合成同 2.3，但放宽字数限制（闲聊允许多轮正常回复，仍注入宠物口吻约束）。
- 宠物状态联动保持有效：闲聊中 Agent 流式输出时宠物播 `think`、工具调用播 `work`（chatStore 派生逻辑天然复用）。
- 闲聊消息计入会话历史，用户可在聊天页找到该会话继续聊（`source='pet'` 会话在会话列表正常展示）。
- 记忆提取：沿用 Agent 的 `enable_memory_extraction` 配置，宠物闲聊同样沉淀长期记忆——这是"宠物记得你"的差异化体验。

#### 3.4 任务完成播报（P1，可选开关）

- Agent 任务自然结束（celebrate）或出错（sad）时，宠物除播放动画外，可用一句话播报结果："搞定了！帮你查到了 3 条数据" / "呜呜，这个任务出错了…"。
- 输入：任务最后一条 assistant 消息的摘要（截断 200 字）+ 完成/失败状态。
- 默认关闭，宠物页提供开关；仅绑定 Agent 且主会话 Agent 与宠物绑定 Agent 为同一个时生成（避免串人设）。
- 防打扰：每次任务结束最多一条，生成失败静默跳过。

### 4. 成本与配额控制

绑定 Agent 意味着互动开始消耗 token，必须设闸：

| 控制项 | 策略 |
|---|---|
| 互动气泡配额 | 每用户每日 LLM 气泡上限 30 次（可进系统配置页调整）；超限自动回退静态文案，界面不报错 |
| 闲聊模型 | 用绑定 Agent 配置的模型，但 `max_iterations` 限 3（闲聊不需要复杂 ReAct） |
| 气泡生成参数 | 强制 `max_tokens ≤ 80`、`temperature` 沿用 Agent 配置；单轮无历史，输入 tokens 恒定 ≈ 人设 prompt 长度 |
| 工具裁剪 | **气泡模式禁用一切工具**（不注册 tool_executor）；闲聊模式仅保留记忆类 direct handler（memory recall/write），禁用沙箱、网页抓取等高成本工具 |
| 计费归属 | 复用 `token_usage_daily`，`source` 标记 `pet_bubble` / `pet_chat`，数据报表可单独查看宠物消耗 |
| 全局开关 | 系统配置页增加"宠物智能互动"总开关，管理员可全站关闭（降级为静态文案），便于成本控制 |

> 数据表变更、接口、执行链路与降级矩阵见 [02-设计.md](02-设计.md)。

### 5. 非功能需求

- **延迟**：气泡首 token ≤ 2s（P90）；超过即失去"互动感"，故选模型时建议绑定轻量模型，文档/引导中提示用户。
- **隔离**：宠物 LLM 链路任何异常不得影响主会话与宠物渲染；气泡/闲聊接口失败前端静默降级。
- **多租户**：绑定校验全部实时进行，跨租户 Agent 不可绑定不可解析；包级默认人设对不可见领养者自动失效。
- **成本**：默认配置下，单用户每日宠物 LLM 消耗上限 ≈ 30 次气泡（≈ 30 × 500 input tokens）+ 闲聊（自驱，迭代上限 3），可在报表中按 `pet_bubble` / `pet_chat` 单独核算。
- **安全**：人设合成模板平台内置不可改；用户输入（闲聊消息）经 sanitize 后才进库（沿用 `db/sanitize.py`）；气泡模式无工具面，无注入执行风险。

### 6. 分期计划

| 阶段 | 内容 |
|---|---|
| P0 | 两级绑定数据模型与接口、智能气泡（含配额/降级）、宠物闲聊面板（复用会话基础设施）、前端绑定管理 |
| P1 | 任务完成播报、报表宠物消耗拆分、闲聊中记忆沉淀验证 |
| P2（待定） | 官方包配套官方人设 Agent 运营位、宠物主动搭话（空闲提醒/早晚安，cron 触发）、多渠道（飞书）宠物人设回复 |

### 7. 验收标准

1. 用户为激活宠物绑定 Agent 后，点击宠物气泡内容为该 Agent 人设生成的一句话，每次内容不同；解绑后恢复静态文案库。
2. 包设置默认人设 Agent 后，未做实例绑定的领养者互动走包级人设；实例绑定后覆盖包级。
3. 绑定 Agent 被改为私有（其他用户不可见）后，其互动自动降级，接口不报错、不暴露 Agent 内容。
4. 「和 TA 聊聊」打开的会话出现在会话列表（带宠物角标），可全屏继续；闲聊中宠物动画随 SSE 状态正常切换。
5. 每日气泡超配额后自动回退静态文案；管理端关闭全站开关后所有智能互动降级，绑定数据保留。
6. LLM 服务全挂时：宠物照常渲染、可点击出静态气泡，聊天主流程无任何异常。
7. token 报表可按 `pet_bubble` / `pet_chat` 维度查询消耗。

## 宠物动作与智能体控制需求文档

> 日期：2026-08-04
> 前置：《需求》第一部分（宠物系统基础）、《需求》第二部分（绑定模型与人设合成）
> 状态：需求定义 v1（2026-08-04 与产品对齐；技术方案待本需求确认后细化）
> 说明：本文档是需求定义（What），不展开实现细节（How）。实现方案在需求确认后另行补充。

### 1. 背景与目标

现状（P0 已上线 / 已规划）：

- 宠物动作 = 精灵图的一行（一个动画），通过状态映射（状态→行）驱动状态机；互动播放直接按行号操作。
- 动作没有独立的名字，展示名是前端推导的（状态名 → Codex 标准行名 → 「动画 N」），**只读、不可改、分散在前端**。
- 《需求》第二部分 绑定智能体后，智能体只生成**气泡文本**，动作仍由前端写死（点击固定播开心行）。**智能体动嘴不动手。**

目标（用户确认的两个动作控制时机）：

1. **用户点击宠物** → 智能气泡：智能体生成一句话的同时，自己挑一个动作让宠物演出来。
2. **右键 → 和 TA 聊聊** → 宠物对话：智能体在对话过程中**主动**触发宠物动作（表达情绪，不限于回复时）。

并且把"动作"从"精灵图行号"升级为**有名字、可自定义的一等实体**：

- 动作有名称：作为展示名 + 智能体触发动作的词汇。
- **上传者**（包创建人/管理员）可修改**包级**动作名称与状态映射，影响所有未自定义的领养者。
- **领养者**（宠物拥有者）可修改**实例级**动作名称与状态映射，只影响自己的宠物，可恢复包级默认。

### 2. 角色与范围

| 角色 | 能做什么 |
|---|---|
| 上传者（包创建人/管理员） | 配置包默认智能体；修改**包级**动作名称、状态映射 |
| 领养者（宠物用户） | 绑定/解绑智能体；修改**实例级**动作名称、状态映射 |
| 智能体（配置在宠物背后） | 在交互中生成内容，并**控制宠物动作**（按动作名称寻址） |

不在本期范围：新增/删除精灵图动画行、修改精灵图本身、宠物间社交、移动端/飞书渠道宠物动作（沿用 《需求》第一部分 范围）。

### 3. 核心概念

#### 3.1 动作 = 精灵图的一行（一个动画）

每个动作有三个属性：

| 属性 | 说明 | 可变性 |
|---|---|---|
| 行号 `row` | 精灵图物理行 | **不可变**，动作的唯一身份（改名/改映射不影响身份） |
| 名称 `name` | 展示名 + 智能体触发词 | 两级可自定义 |
| 状态 `state` | 动作与平台状态的绑定（idle/work/think/...） | 两级可自定义 |

**身份用行号、不用名称**：改名/换映射不破坏状态机与既有数据，实例级自定义在包级变更后依然锚定同一行。

#### 3.2 两级自定义（实例优先）

| 层级 | 内容 | 谁设置 | 作用 |
|---|---|---|---|
| 包级 | 动作名称 + 状态映射 | 上传者/管理员 | 包的"出厂配置"，上传时自动生成，创建人可改 |
| 实例级 | 动作名称 + 状态映射 | 宠物拥有者 | 个人自定义，**优先级高于包级** |

解析顺序：实例级 → 包级 → 系统默认（9 行包自动映射 / 仅 idle 兜底）。

#### 3.3 动作名称 = 智能体的触发词

绑定智能体后，智能体**只能从宠物现有动作中选择**，不能发明动作。选择方式用**名称**：

- 名称即智能体触发动作的词；给动作改名 = 给智能体换触发词。
- 没起名（占位「动画 N」）的动作不作为智能体触发词。
- 智能体触发词列表 = 当前宠物解析出的、有实际名称的动作（上限 12 个，控制成本）。
- 触发目标始终落在"宠物已有动作"范围内，不改动精灵图。

### 4. 功能需求

#### 4.1 宠物绑定智能体（沿用 《需求》第二部分，要点复述）

- 两级绑定：`用户实例绑定` → `包默认智能体` → `不绑定`（零 token 现状）。
- 绑定可选；未绑定时所有交互行为与现状完全一致。

#### 4.2 智能体控制宠物动作

**时机一：点击宠物（智能气泡）**

- 用户点击宠物，智能体生成一句话，并挑选一个动作让宠物播放。
- 文本与动作情绪匹配（开心→开心类动作，出错→沮丧类动作）。
- 智能体未指定动作 / 指定无效 → 宠物播默认动作（现状的开心行），文本照常展示，不打断交互。

**时机二：右键 → 和 TA 聊聊（宠物对话）**

- 对话中智能体可**主动**触发宠物动作：表达情绪、应景表演，不限于每轮回复时。
- 主动触发是"一次性情绪动作"，播放完回到对话状态机驱动的状态（思考/工作等联动不变）。
- 智能体用**动作名称**触发；触发无效名称 → 智能体收到纠正引导，对话不中断。

**通用规则**

- 智能体只能触发宠物已有动作（名称寻址，命中行号），不能发明/改图。
- 触发动作不产生额外成本开销（见 §6）。

#### 4.3 动作有名称

- 每个动作（每行）有一个名称。
- 默认名自动生成：状态名（该行配给某状态时）→ Codex 标准行名 → 「动画 N」。
- 名称用途：右键菜单展示、气泡展示、智能体触发词。
- 名称可被上传者（包级）、领养者（实例级）修改。

#### 4.4 上传者可修改（包级）

- 修改动作名称：影响所有未自定义的领养者（未做实例覆盖时生效）。
- 修改状态映射：把某行动画配给不同平台状态（idle/think/work/wait/celebrate/sad/happy），影响宠物在各状态下的表现。

#### 4.5 领养者可修改（实例级）

- 覆盖动作名称：只影响自己的宠物；可一键恢复包级默认。
- 覆盖状态映射：只影响自己的宠物；可一键恢复包级默认。
- 改名/改映射**即时生效**：右键菜单、智能体触发词、状态动画同步更新，无需重新激活宠物。

### 5. 规则与边界

- **未绑定**：点击 → 静态气泡 + 默认动作（现状）；对话交互不可用（提示先绑定智能体）。
- **降级**：LLM/智能体不可用、配额超限 → 静默回退静态文案 + 默认动作，界面不报错。
- **不改精灵图**：动作 = 行，不增删行、不改图；行号是身份，改名/改映射不影响身份与已领养用户。
- **映射兜底**：某状态未配行 → 降级 idle；`idle` 必须有行可播（沿用现状）。
- **名称校验**：非空、长度受限、同一目录内唯一（否则智能体寻址歧义）；越界行号拒绝。
- **隔离**：包级改动不回收领养数据；实例级改动与他人无关；跨租户不可见、不可触发。
- **安全**：智能体只能触发本宠物动作；动作名只作寻址，无注入执行面。

### 6. 成本与性能要求（约束条件）

- 智能体控制动作**不新增 LLM 往返**：点击场景随气泡单轮顺带决定；对话场景为本地动作指令（无模型调用）。
- 气泡生成成本沿用 《需求》第二部分 约束（`max_tokens ≤ 80`、单轮无历史），触发词列表注入量小。
- 名称/映射解析为纯内存计算，不引入 DB 查询热点。
- 全站仍可一键关闭"宠物智能互动"降级为静态文案（沿用 《需求》第二部分 4 全局开关）。

### 8. 验收标准

1. 绑定智能体后点击宠物：气泡为智能体生成的一句话，且播放与文本匹配的动作动画；智能体未指定动作时播默认开心动画。
2. 绑定智能体后右键「和 TA 聊聊」：对话中智能体可主动让宠物播放指定动作（按名称触发）；触发无效名称不报错、智能体被纠正。
3. 上传者修改包级动作名称与状态映射后：未自定义的领养者的菜单名称、状态动画同步更新。
4. 领养者修改实例动作名称与状态映射后：只影响自己的宠物，菜单与智能体触发词即时生效；重置恢复包级默认。
5. 保存时动作名非空/不重复/行号不越界校验通过；删除/下架包不影响已领养用户的动作数据。
6. 未绑定 / LLM 全挂 / 配额超限：点击出静态气泡 + 默认动作，聊天主流程无任何异常（回归 《需求》第二部分 验收 6）。
