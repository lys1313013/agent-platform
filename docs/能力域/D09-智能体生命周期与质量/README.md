# D09 智能体生命周期与质量

> **解决什么问题**：持续运营几十上百个智能体时，谁改了提示词、线上是哪个版本、改坏了多久能回滚、上线前有没有回归、线上效果如何。
> **适用读者**：产品/运营、后端、平台管理员、交付实施、质量负责人。
> **关联文档**：[D02 智能体运行时](../D02-智能体运行时/README.md) · [D03 模型接入与治理](../D03-模型接入与治理/README.md) · [D11 可观测性与运营](../D11-可观测性与运营/README.md) · [D15 开放平台与生态](../D15-开放平台与生态/README.md) · [能力全景 §5 D9](../../00-平台总览/README.md)
> **状态基准**：2026-11 实现。状态只用「已具备 / 部分 / 缺失」；旧文档中的权限矩阵与当前实现不一致处，以当前实现为准。

## 1. 边界

**本文负责**：智能体定义、配置管理、版本快照、发布与回滚、模板与复用、评测、线上质量反馈、A/B、归档下线；以及作为可复用资产的技能生命周期。

**本文不负责**：运行时循环与上下文（D02）、模型选择策略（D03）、工具契约（D04）、知识库检索（D05）、可观测数据底座（D11）、对外协议与生态（D15）。

**核心原则**：

1. **草稿与线上分离**。编辑中的配置不得直接影响已发布的对外 API。
2. **版本必须可复现**。同一版本号应冻结提示词、模型、工具、技能、子智能体等全部运行时输入。
3. **发布必须有门禁**。至少经过配置校验；企业场景还需要审批、灰度与回滚。
4. **质量要闭环**。线上反馈与调用追踪要能回流成评测用例，而不是停留在点赞/点踩。
5. **下线要有依赖检查**。删除前确认无子智能体、渠道、定时任务、外部调用方依赖。

## 3. 本项目现状

### 3.1 已具备

| 能力 | 实现事实 |
|---|---|
| 智能体增删改查 | 配置包含名称、图标、描述、系统提示词、模型、温度、最大迭代、工具、MCP、记忆提取、自动重试、自动标题、欢迎语、快捷提问与启用状态 |
| 归属与可见性 | 记录所属租户、创建人与租户内/私有可见性；列表与读取按租户和可见性过滤 |
| 配置侧边栏 | 前端提供概览、提示词与模型、工具、MCP、知识库、图谱知识库、技能、子智能体、会话历史等面板 |
| 版本快照与发布 | 发布时保存版本号、变更说明、完整配置快照、发布人、发布时间与生效标记；发布时停用旧版本，仅保留一个生效版本；快照覆盖模型、温度、迭代、重试、提示词、工具、MCP、技能标识、知识库标识、子智能体标识与欢迎语等 |
| 对外 API | 支持一次性执行、创建外部会话、流式聊天、消息列表/清空/删除/反馈；执行基于已发布快照 |
| API 文档面板 | 展示版本信息、多语言调用示例、流式事件与会话管理接口 |
| 技能版本与包 | 技能有独立版本记录；更新自动归档旧版本，并防止并发更新互相覆盖；技能包包含说明、脚本、参考资料与素材，支持压缩包导入导出与附件上传 |
| 技能市场与质量 | 支持外部技能市场搜索、解析与批量导入，并补充代码托管平台元信息；记录使用次数、成功次数、最近使用、执行日志与验证状态；结果上报要求证据校验，验证失败会停用技能 |
| 运行时质量数据 | 调用追踪加质量接口，提供成功/失败/中断、平均耗时、平均 token、每轮调用数与上下文压缩率 |

### 3.2 部分

| 事项 | 实现事实 | 影响 |
|---|---|---|
| 版本快照完整性 | 快照记录技能与子智能体标识，但执行时仍从实时配置加载技能与子智能体；工具配置为空会启用全部非前端工具 | 旧版本不可完全复现；无法发布"明确不启用工具"的版本 |
| 权限模型 | 编辑/删除仅创建者，管理员不能代为操作；发布仅管理员与超级管理员可用，所有者发布分支对非管理员不可达 | 与旧文档的"管理员可治理所有/所有者可发布"不一致 |
| 版本管理 | 只有发布与列表，没有差异对比、回滚、审批、灰度；版本号默认使用短随机标识 | 改坏后只能重新发布，无法一键回到旧版 |
| 线上反馈 | 仅外部 API 会话支持好评/差评，写入消息的附加信息；Web 聊天无入口，无聚合 | 反馈无法用于质量分析 |
| 智能体概览统计 | 统计接口只返回会话数、消息数、最后活跃时间 | 旧文档的"调用次数、平均耗时"未实现 |
| 模板与复用 | 提示词模板是前端静态常量；无智能体模板、复制、导入导出、市场 | 新建智能体仍需手工配置 |
| 技能治理 | 存在公开标记，但列表/搜索只按用户过滤，公共技能不会出现在他人结果中；自动提取未实现 | 平台公共技能不可发现；自学习闭环缺失 |
| 归档下线 | 只有启用标记与硬删除；无依赖检查、数据保留策略、调用方通知 | 删除可能破坏子智能体/渠道/定时任务 |

### 3.3 缺失

- 离线评测集、回归测试、评分维度、模型评审、人工抽检。
- 灰度发布、按租户/部门发布、发布审批与变更单。
- 版本差异对比与一键回滚。
- A/B 实验（提示词/模型/工具）。
- 线上质量看板（按智能体聚合反馈、失败归因、badcase 回流）。
- 智能体模板中心/市场、复制与导入导出。
- 下线依赖检查与调用方通知。
- 技能冷门降级、自动提取、平台公共技能治理。

## 4. 关键设计

### 4.1 定义模型

**现状**：智能体同时承担"草稿配置"和"运行时配置"两个角色；发布时复制一份配置快照到版本记录。

**目标**：明确三类对象。

- **智能体身份**：稳定标识，包含名称、图标、归属与可见性。
- **草稿配置**：可编辑，包含提示词、模型、工具、技能、知识库与子智能体。
- **版本快照**：不可变，包含配置、依赖版本与发布信息。

版本快照建议补充：版本状态、回滚来源版本、灰度比例、技能/知识库/子智能体的具体版本与内容摘要、审批人、审批时间与意见。

### 4.2 发布流程

**现状**：管理员点击发布后，停用旧生效版本，写入新快照，立即生效，对外 API 随即使用。没有审批、灰度、回滚与差异对比，属于"全量瞬时切换"。

**目标状态机**：草稿 → 校验 → 待审批 → 已发布（灰度比例）→ 生效 → 归档；任一已发布状态可回滚。

关键规则：

1. 发布前校验：模型存在且启用、工具存在、技能/知识库同租户、子智能体无环。
2. 快照冻结全部运行时输入，包括技能内容版本与子智能体版本，不能只存标识。
3. 全量切换前支持灰度：按租户/用户/百分比分流，指标达标再扩大。
4. 回滚只需把旧版本置为生效，禁止修改历史快照。
5. 所有发布/回滚写审计日志（谁、何时、从哪个版本到哪个版本、原因）。

### 4.3 评测体系

**当前为缺失，以下为目标设计。**

评测体系应包含：评测集（按租户与智能体组织）、评测用例（输入、期望、断言）、评测运行（绑定评测集、智能体版本与模型）、评测结果（得分、是否通过、评审方式）。

评分维度：正确性、工具使用、指令遵循、成本、延迟、安全性。门禁建议：

| 指标 | 门禁 |
|---|---|
| 通过率 | 不得低于上一版本 - 2pp |
| 平均 token | 不得高于上一版本 + 15% |
| P95 延迟 | 不得高于上一版本 + 20% |
| 工具错误率 | 不得高于 5% |
| 安全用例 | 必须 100% 通过 |

实现顺序：先固定用例与规则断言（关键词、工具调用、结构化输出），再引入模型评审与人工抽检。

### 4.4 线上质量闭环

目标链路：用户反馈 / 调用追踪异常 / 人工抽检 → 标记 badcase → 补充评测集 → 修复提示词/工具/模型 → 回归评测 → 灰度发布。

现状只有调用追踪汇总和外部 API 反馈，缺少 badcase 记录、归因字段与回流入口。建议新增独立的质量反馈记录，统一保存消息、智能体版本、评分、原因、标签与评审人，不要复用消息的附加用量信息。

### 4.5 技能资产生命周期

创建/导入（外部市场）→ 测试 → 使用 → 结果上报（带证据校验）→ 版本迭代（旧版本归档）→ 验证失败停用 → 废弃。

现状已覆盖版本、包、市场同步、结果上报与证据校验。缺口：自动提取、平台公共技能发现、技能质量看板、冷门技能降级策略。

### 4.6 权限矩阵（实现事实）

| 操作 | 旧文档 | 当前实现 |
|---|---|---|
| 创建 | 所有用户 | 所有登录用户 |
| 编辑 | 创建者；管理员可编辑所有 | **仅创建者**；管理员不能代为编辑 |
| 删除 | 创建者；管理员可删除所有 | **仅创建者**；管理员不能代为删除 |
| 发布版本 | 管理员或所有者 | **仅管理员/超级管理员**；所有者发布分支不可达 |
| 查看/对外调用 | 同租户可见或本人私有；已登录用户可调用 | 一致；对外调用额外要求会话所有者与已发布版本 |

这张表必须与 D01 的权限设计对齐；当前实现是"创建者自治 + 管理员只管模型与观测"，不是企业常见的"管理员可治理所有资源"。

### 4.7 失败模式

| 场景 | 当前行为 | 风险 | 目标 |
|---|---|---|---|
| 发布错误提示词 | 立即全量生效 | 线上效果骤降 | 评测门禁 + 灰度 + 回滚 |
| 修改技能后调用旧版本 | 实时加载新技能 | 版本不可复现 | 快照冻结技能版本 |
| 删除被依赖的智能体 | 硬删除并清理关系 | 子智能体/渠道/任务断裂 | 依赖检查 + 软归档 |
| 空工具配置 | 对外执行启用全部工具 | 权限放大 | 区分"未配置"与"明确为空" |
| 反馈丢失 | 有附加信息，无查询 | 无法闭环 | 独立记录 + 聚合 |

## 5. 实施建议

### P0（先让版本可信）

1. **冻结快照依赖**：技能内容版本、子智能体版本、知识库版本写入快照；执行只读快照。
2. **区分空工具语义**：空列表表示明确不启用工具；未配置表示继承或全部启用。
3. **权限对齐**：明确管理员是否可治理他人智能体；当前实现与文档二选一并统一。
4. **版本不可变与回滚**：租户内版本号唯一；禁止修改历史快照；提供回滚能力并写审计。

### P1（质量门禁）

5. 评测集与回归运行：先规则断言，后模型评审。
6. 发布前自动跑评测，未达标阻断。
7. badcase 记录与回流入口；Web 聊天也支持反馈。
8. 按智能体的质量看板：成功率、平均耗时与 token、反馈分布、版本对比与配置差异。

### P2（规模化运营）

9. 灰度发布与 A/B 分流。
10. 智能体模板/复制/导入导出/市场。
11. 下线依赖检查、数据保留与调用方通知。
12. 技能自动提取与公共技能治理、冷门降级；发布审批流与变更单集成。
