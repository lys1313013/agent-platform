# D11 可观测性与运营

> **解决什么问题**：Agent 的行为是概率性的，"看起来正常"不等于正常。没有日志、指标和调用链，就无法回答"Token 花在哪、哪里慢、哪里出错、昨天为什么变差"。
> **适用读者**：后端研发、SRE/运维、平台管理员、质量与运营。
> **关联文档**：[D12 成本与配额](../D12-成本与配额/README.md) · [D14 部署交付与运维](../D14-部署交付与运维/README.md) · [能力全景 §5 D11](../../00-平台总览/README.md)
> **状态基准**：2026-11 实现。状态只用 `已具备 / 部分 / 缺失`；设计目标不写成已实现。

---

## 1. 边界

**本文负责**：结构化日志、指标、调用链追踪；模型/工具/智能体/会话/租户各层指标口径；告警规则与通知；会话级复盘；SLO 与错误预算。

**本文不负责**：成本计价、配额执行与账单（D12）；安全审计与合规留存（D10）；熔断、限流、队列等可靠性机制本身（D13）；回答质量评测与智能体评级（D09）。

**核心原则**：

1. **观测不能拖慢主链路**：采集异步化、失败只记日志、队列满丢数据保业务。
2. **明细是事实源，预聚合只是加速**：任何报表口径都要能回到明细复算。
3. **维度统一**：租户、用户、会话、智能体、模型、链路、时间保持一致，保证任意下钻。
4. **告警要可执行**：每条告警必须对应明确的排查入口和负责人，否则只是噪音。

## 2. 能力清单

### 2.1 日志

- 结构化日志（JSON 或键值对），带链路、会话、租户标识。
- 分级与采样：错误全量、调试可开关、高频事件采样。
- 采集与保留：标准输出 → 日志采集器（Loki/ELK）→ 按天/容量轮转。
- 关键事件：模型失败、工具失败、队列溢出、迁移、启动阶段耗时。

### 2.2 指标

- **业务**：活跃用户、会话数、消息数、任务完成率、渠道调用量。
- **质量**：模型失败率、工具错误率、重试率、空回答率、压缩触发率。
- **性能**：首 token 延迟 P50/P95、端到端延迟 P95、工具耗时 P95、上下文利用率 P95。
- **容量**：沙箱并发占用、队列长度、写入滞后。

### 2.3 追踪

- 一次 Agent 执行一个链路标识，内部按调用顺序串联模型调用与工具调用。
- 追踪要能回答：每一轮用了哪个模型、多少 token、耗时、首 token 延迟；每次工具做了什么、输出多大、是否截断；是否触发压缩、压缩前后 token。
- 与日志、指标通过链路标识互相关联。

### 2.4 关键指标口径

| 指标 | 口径 |
|---|---|
| 模型失败率 | 窗口内失败调用数 / 总调用数 |
| 工具错误率 | 窗口内失败工具调用数 / 总工具调用数 |
| 延迟 P95 | 窗口内调用耗时的 95 分位 |
| 缓存命中率 | 缓存读 token / 输入 token |
| 上下文利用率 | 输入 token / 模型上下文窗口 |
| 压缩触发率 | 触发压缩的执行数 / 执行总数 |
| 对话平均 token | 执行累计 token 总和 / 执行数 |
| 首响延迟 | 用户消息到首个 token 回流的时间 |

### 2.5 告警

| 告警 | 建议条件 | 级别 |
|---|---|---|
| 模型失败率突增 | 10 分钟失败率 > 5% 且较前一周期翻倍 | P1 |
| 工具错误率超标 | 单工具 10 分钟错误率 > 20% | P2 |
| 延迟劣化 | 模型延迟 P95 > 30s 持续 5 分钟 | P2 |
| 上下文接近满 | 利用率 P95 > 90% | P3 |
| 压缩频繁 | 压缩触发率 > 30% | P3 |
| 采集异常 | 队列溢出、写入失败持续出现 | P2 |
| 沙箱/渠道断线 | 沙箱启动失败率、渠道回调失败率超阈值 | P2 |

### 2.6 复盘

- 按会话或链路一键还原完整执行轨迹（模型 → 工具 → 下一轮）。
- 支持标注 badcase、记录根因、关联到提示词/工具/模型变更。
- 复盘结论可回流为测试用例或优化项。

### 2.7 SLO

- 可用性：API 成功率、流式建连成功率。
- 延迟：首 token 延迟 P95、端到端 P95。
- 质量：对话成功率（完成数 / 全部执行数）、工具成功率。
- 每个 SLO 配错误预算与燃尽告警，超预算时冻结非必要变更。

## 3. 本项目现状

### 3.1 已具备

| 能力 | 实现 |
|---|---|
| 调用明细 | 记录每次模型调用的模型、供应商、token、缓存 token、首 token 延迟、耗时、吞吐、重试、状态、错误类型、停止原因、温度、工具数 |
| 工具明细 | 记录工具名、执行类型、耗时、错误、参数/输出体量、估算注入 token、截断、并发标记 |
| 执行明细 | 记录状态、轮数、工具数、token、耗时、压缩字段、是否顶到最大迭代 |
| 异步采集 | 有界队列约两万条；每 2 秒或每 500 条批量写入，失败只记日志 |
| 预聚合 | 用户×日×模型、用户×日×工具、租户×日性能三张日聚合 |
| Langfuse | 对话链路每轮创建根观察节点，模型与工具作为子观察节点 |
| 管理观测接口 | 管理员专属的概览、执行明细、分布统计、工具排行、单工具趋势、质量查询 |
| 用量报表接口 | 个人/全局用量汇总、趋势、分布、明细查询 |
| 前端 | 管理端观测页五个页签：实时监控、执行明细、聚合报表、工具排行、对话质量；另有用量页支持个人/全局视图 |
| 采集隔离 | 全部采集异步投递；队列满丢弃新记录，溢出日志限频（每 5 分钟一次） |

### 3.2 部分具备

- **追踪只覆盖 Web 对话**：只有 Web 对话创建根观察节点；定时任务、渠道、宠物、聊天室没有根节点，跨入口追踪不完整。
- **错误链路缺执行明细**：执行明细只在正常完成或顶到最大迭代时写入；模型抛异常、用户取消没有兜底，错误汇总能力未接入，执行错误率会偏低。
- **压缩字段未落库**：执行明细有压缩相关字段，但实际未写入，因此质量页的压缩指标恒为 0；压缩信息只出现在流式事件和回调数据里。
- **上下文利用率未采集**：模型调用明细虽有上下文窗口与利用率字段，但没有写入点，概览页的上下文利用率 P95 恒为空。
- **状态枚举不完整**：执行明细实际只写完成/超时/错误，没有"中断"；用户中止与异常都归到错误或直接丢失。
- **指标无实时出口**：没有实时指标端点，没有 Prometheus/Alertmanager；"实时监控板"实际是查明细表的分桶聚合，按窗口轮询刷新。
- **权限只到全局管理员**：观测接口与全局报表只校验管理员角色，查询未按租户过滤，跨租户可见。
- **日志是控制台文本**：日志库默认输出，未配置 JSON、链路注入、采集器或轮转；日志级别只传给 Web 服务。
- **明细永久保留但无分区**：设计建议按月分区，当前三张明细表为普通表，只有常规索引。

### 3.3 缺失

- 告警规则引擎、通知通道（企业微信/飞书 webhook）、告警历史与静默。
- SLO 定义、错误预算、燃尽率。
- 会话级"一键复盘"入口与 badcase 标注回流。
- 质量指标：回答采纳率、人工介入率、重复提问率、无效/重复工具调用率。
- CSV 导出（设计有，接口与前端均未实现）。
- 异常检测、指标采样、明细表分区与归档策略。
- 成本维度指标（费用字段恒为 0，见 D12）。

## 4. 关键设计

### 4.1 埋点模型

- 一次 Agent 执行生成一个链路标识，并随执行上下文传播；模型调用与工具调用自动补齐租户、用户、会话、智能体维度，调用顺序由执行上下文自增。
- 采集链路：有界异步队列 → 每 2 秒或每 500 条批量写入 → 同一事务内累计工具日聚合与性能日聚合。
- 写失败不重试；队列满时丢弃新到记录，并对溢出日志限频。
- 用户日聚合走独立链路，与明细采集不共享事务。

### 4.2 三层数据与查询路径

| 层 | 数据 | 用途 | 现状 |
|---|---|---|---|
| 明细 | 模型调用、工具调用、执行明细 | 精确聚合、链路下钻 | 已具备，无分区 |
| 预聚合 | 用户日、工具日、性能日 | 报表、排行 | 已具备，采集时同步累计 |
| 实时指标 | 指标端点 | 实时告警与 P95 | 缺失 |

查询策略：1 小时/24 小时按分钟/小时桶查明细；7 天以上查预聚合或按日桶聚合；链路下钻按链路标识查明细。P95 使用数据库分位函数。

### 4.3 指标口径注意事项

- 租户性能日聚合存的是累计值，平均值需查询时用总量/次数计算，不存均值，避免预聚合失真。
- 工具日聚合的维度是**用户**，不是租户；按租户出工具报表需要回查明细。
- 上下文利用率与压缩收益是"有列无数据"，展示前应先补写入点，否则会出现"功能在但永远为 0"的误导。
- 费用字段固定写 0，任何费用口径不可用。
- 所有时间桶按 UTC 截断；用户日聚合按服务器本地日期，两者跨时区可能相差一天。

### 4.4 告警与 SLO 落地方式

- 链路：模型/工具/队列埋点 → 指标系统 → 告警路由 → 企业微信/飞书，观测页与看板复用同一数据。
- 告警规则应版本化在仓库内，阈值可按租户覆盖。
- SLO 建议先落两条：对话成功率 ≥ 99%，首 token 延迟 P95 ≤ 5s；错误预算按周滚动。
- 告警去重与静默必须做，否则失败率抖动会淹没值班。

## 5. 实施建议

### P0（先让数据可信、告警可用）

1. 补齐执行错误/取消路径：在执行循环用兜底逻辑写执行明细，区分中断/错误/超时。
2. 写入压缩字段与上下文窗口/利用率，让质量页与上下文告警有真实数据。
3. 增加实时指标端点与最小告警集：模型失败率、工具错误率、延迟 P95、采集队列溢出、写入失败。
4. 修复观测与报表接口的租户过滤，避免租户管理员上线后跨租户泄露。
5. 采集写入失败与队列溢出纳入告警，并暴露队列长度、写入滞后指标。

### P1（运营闭环）

6. 告警规则可配置 + 告警历史 + 静默；接入飞书/企业微信。
7. 会话/链路一键复盘：从观测页跳转会话，展示完整输入输出与工具结果。
8. badcase 标注与回流，关联提示词/工具版本。
9. SLO 看板与错误预算燃尽告警。
10. CSV 导出（复用当前筛选条件）。

### P2（规模化与智能化）

11. 明细表按月分区、冷热分层与保留策略。
12. 高频事件采样与指标基数治理。
13. 质量指标：采纳率、人工介入率、重复提问率、无效工具调用率。
14. 异常检测（同比/环比突增、工具耗时漂移）与根因提示。
15. 结构化日志接入采集平台，统一链路标识检索。
