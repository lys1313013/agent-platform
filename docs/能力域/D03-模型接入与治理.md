# D03 模型接入与治理

> **解决什么问题**：模型是平台唯一不可控的外部依赖。企业要求模型可替换、可降级、可审计、可算账，而不是把供应商密钥硬编码在代码里。
> **适用读者**：后端、SRE、平台管理员、交付实施、安全合规。
> **关联文档**：[D02 智能体运行时](D02-智能体运行时.md) · [D11 可观测性与运营](D11-可观测性与运营.md) · [D12 成本与配额](D12-成本与配额.md) · [能力全景 §5 D3](../企业级Agentic平台能力全景.md)
> **状态基准**：2026-11 代码。状态只用 `已具备 / 部分 / 缺失`；与旧文档冲突处以代码为准。

---

## 1. 边界

**本文负责**：供应商接入、模型目录、模型选择与降级、密钥保管、调用超时/重试/限流、LLM 调用留痕、模型侧合规元数据。

**本文不负责**：提示词工程与上下文压缩（D02）、工具契约（D04）、计费与配额（D12）、平台级监控大盘（D11）、供应商商务合同。

**核心原则**：

1. **模型目录是唯一事实源**。运行时不得依赖 `.env` 里的模型名或代码里的默认值。
2. **租户隔离先于便利**。模型、供应商、密钥都必须按 `tenant_id` 解析，禁止跨租户回退。
3. **降级必须显式**。切换模型/供应商要可解释、可审计，不能静默换成更贵或能力更弱的模型。
4. **密钥不进日志、不进提示词、不进 API 响应**。
5. **每次调用都有账**：模型、参数、token、耗时、错误码、重试次数。

## 2. 能力清单

| 能力域 | 企业级要求 | 本项目对应 |
|---|---|---|
| 多供应商 | OpenAI 兼容、Anthropic、Azure、Bedrock、本地推理（vLLM/Ollama） | OpenAI SDK 兼容 + Anthropic 原生 |
| 模型目录 | 能力标签、上下文窗口、价格、限流、健康状态 | 仅名称、模型标识、多模态、默认/启用 |
| 路由与降级 | 按智能体、任务类型、成本、延迟选择；故障切换 | 智能体指定 → 租户默认 → 报错 |
| 密钥管理 | 租户级隔离、加密/KMS、轮换、脱敏 | 租户级隔离；列名加密但实际明文 |
| 调用治理 | 超时、指数退避、限流、并发上限、熔断、幂等 | 固定超时 + 3 次退避重试；无熔断/限流 |
| 留痕 | 每次调用的模型、参数、token、耗时、错误、费用 | 有调用明细；费用与上下文利用率缺失 |
| 合规 | 数据出境、是否用于训练、供应商 DPA | 无元数据与标记 |

## 3. 本项目现状

### 3.1 已具备

| 能力 | 实现事实 |
|---|---|
| 供应商/模型后台管理 | `llm_providers` / `llm_models` 表；管理端 CRUD、启用/停用、设置租户默认模型 |
| 租户隔离 | `admin_models.py` 所有查询都带 `tenant_id == admin.tenant_id`；模型解析同样按租户过滤 |
| 模型发现 | 调用供应商 `{base_url}/models` 拉取模型列表，支持批量导入、去重、首个模型自动设为默认 |
| 两类供应商适配 | `provider_type` 限定 `openai` / `anthropic`；OpenAI 兼容端点通过 `base_url` 接入 |
| 模型能力字段 | `is_multimodal` 决定是否允许图片输入，替代按模型名猜测 |
| 模型选择 | 智能体 `model_id`（启用且同租户）→ 租户默认模型 → `ModelUnavailableError` |
| 多模态校验 | `build_agent_provider` 检查模型与执行租户一致；任务/后台执行复用同一工厂 |
| 超时与重试 | 客户端超时 120s（连接 10s）；瞬时错误最多重试 3 次，指数退避 1s/2s/4s；智能体可关闭重试 |
| 错误归一 | `timeout / connection / rate_limit / server_error / invalid_request / unknown` |
| 工具 Schema 降级 | 供应商拒绝某个工具 Schema 时，移除该工具后重试，避免整次调用失败 |
| 调用留痕 | `llm_call_logs` 记录模型、供应商、token、缓存 token、TTFT、耗时、吞吐、重试、状态、错误、stop_reason、温度、max_tokens、工具数 |
| 可观测接口 | `/api/observability` 提供概览、Trace、聚合、工具排行、质量接口（管理员） |
| Langfuse（可选） | `observation/client.py` 初始化 Langfuse；未配置密钥时自动禁用 |

### 3.2 部分（设计存在，落地不完整）

| 事项 | 代码事实 | 影响 |
|---|---|---|
| 密钥加密 | `api_key_encrypted` 字段名暗示加密，但创建/更新直接存明文，代码标注 `TODO: encrypt` | 数据库泄露即密钥泄露 |
| 供应商覆盖 | 只有 OpenAI/Anthropic 适配器；Azure、Bedrock 的原生鉴权/部署名未实现 | 企业多云接入需改代码 |
| 模型目录 | 无 `context_window`、价格、最大输出、工具调用能力、限流、健康状态字段 | 路由与配额缺少依据 |
| 路由/降级 | 仅“指定模型不可用 → 租户默认模型”；供应商故障不会切备用模型 | 主模型故障只能失败 |
| 调用治理 | 无供应商级/模型级限流、并发上限、熔断；重试次数固定为 3 | 高峰期可能放大故障 |
| 上下文观测 | `llm_call_logs` 有 `context_window / context_utilization` 列，但客户端未写入 | 上下文利用率报表失真或为空 |
| 配置项 | `LLMProvidersSettings.timeout / max_tokens` 存在，但运行时未使用，客户端硬编码 120s | 配置不生效 |
| 成本留痕 | `llm_call_logs` 无费用字段；`token_usage_daily.cost_usd` 恒为 0 | 无法按模型算钱 |
| 合规 | 无数据出境、训练使用、供应商 DPA、数据驻留标记 | 企业采购无法核对 |
| 供应商启用校验 | 解析模型时只校验 `LLMModel.is_active`，未校验 `LLMProvider.is_active` | 已停用供应商仍可能被调用 |

### 3.3 缺失

- 按任务类型/成本/延迟的主动路由与故障转移。
- 熔断、限流、并发隔离、幂等键。
- KMS/密钥轮换与密钥使用审计。
- 模型价格表与费用计算（见 D12）。
- 模型灰度、A/B、按部门/租户的模型白名单。
- 供应商 SLA 看板、健康探测与自动摘除。
- 数据出境/训练使用等合规元数据。

## 4. 关键设计

### 4.1 数据模型

**现状**：

```
llm_providers(id, tenant_id, name, provider_type, base_url, api_key_encrypted, is_active)
llm_models(id, tenant_id, provider_id, name, model_name, is_multimodal, is_default, is_active)
```

**目标模型**（未实现）：在 `llm_models` 增加

```
context_window        Int
max_output_tokens     Int
capabilities          JSONB   -- tool_call / vision / json_schema / reasoning
input_price_per_1m    Numeric
output_price_per_1m   Numeric
rate_limit_rpm        Int
health_status         String  -- healthy / degraded / down
data_residency        String
training_opt_out      Bool
```

价格与合规字段是 D12 与 D10 的输入，必须与模型目录同源，不能分散在 `.env`。

### 4.2 模型解析与调用流程

```
请求进入
  → resolve_model(tenant_id, model_id?)
      1) 智能体绑定模型：同租户 + is_active
      2) 租户默认模型：is_default + is_active
      3) 都没有 → ModelUnavailableError（明确报错，不跨租户）
  → 校验 model.tenant_id == execution.tenant_id
  → create_provider(provider_type, model_name, base_url, api_key, temperature, enable_retry)
  → call_with_schema_fallback（工具 Schema 被拒时逐个移除）
  → _retry_with_backoff（仅瞬时错误，最多 3 次）
  → record_llm_call（成功/失败都记录）
```

**设计约束**：模型不可用必须有明确错误码；默认模型回退只解决“未配置”，不能掩盖“供应商故障”。目标方案是增加 `routing_policy` 与健康探测，按优先级列表尝试，而不是单点回退。

### 4.3 调用治理

| 机制 | 现状 | 目标 |
|---|---|---|
| 超时 | 硬编码 120s，连接 10s | 模型级可配置，读 `LLMProvidersSettings` |
| 重试 | 3 次，1/2/4s，仅瞬时错误 | 可配置次数/基数；尊重 `Retry-After` |
| 限流 | 无 | 供应商/租户 RPM/TPM，令牌桶 |
| 并发 | 无模型级上限 | 信号量/队列，防止打爆供应商 |
| 熔断 | 无 | 连续失败自动摘除，半开探测 |
| 幂等 | 无 | 外部调用可传 `Idempotency-Key` |

### 4.4 观测与留痕

- `llm_call_logs` 是事实源，包含 `trace_id / session_id / user_id / tenant_id / agent_id / model_id / call_order`，可按人、按智能体、按模型下钻。
- Trace 汇总在 `agent_trace_logs`；预聚合在 `performance_daily`。
- **不存输入输出正文**，只存大小与 token，降低泄露面。
- 已知缺口：`context_window / context_utilization` 未写入；费用恒为 0；无 `/metrics` 与告警。

### 4.5 失败模式

| 场景 | 当前行为 | 风险 | 目标 |
|---|---|---|---|
| 主供应商宕机 | 重试 3 次后失败 | 对话不可用 | 健康探测 + 备用模型切换 |
| 触发限流 | 退避重试后失败 | 高峰期雪崩 | 令牌桶排队 + `Retry-After` |
| 模型被停用/删除 | 静默回退租户默认模型 | 可能换成更贵/更弱模型 | 显式降级事件与审计 |
| 工具 Schema 被拒 | 移除该工具后重试 | 能力静默缺失 | 记录被移除工具并告警 |
| 上下文超长 | 归一为 `invalid_request` | 归因不准 | 单独错误类型 + 压缩/截断提示 |
| 密钥泄露 | 明文存库 | 直接产生费用与数据风险 | KMS 加密 + 轮换 + 使用审计 |
| 跨租户模型 ID | 拒绝并报错 | 无 | 保持 |
| 供应商停用但仍被解析 | 可能继续调用 | 违反管理意图 | 解析时校验 provider 状态 |

## 5. 实施建议

### P0（上线阻断）

1. **密钥加密**：用 KMS/信封加密替换明文存储；API 只返回 `has_api_key`；补密钥轮换与最后使用时间。
2. **模型目录补关键字段**：`context_window`、`max_output_tokens`、`capabilities`、价格；采集侧写入上下文利用率。
3. **解析校验供应商状态**：`resolve_model` 同时校验 `LLMProvider.is_active`。
4. **超时配置生效**：读取 `LLMProvidersSettings.timeout`，按模型覆盖。
5. **显式降级事件**：默认模型回退、Schema 移工具都要写结构化日志并可在观测页看到。

### P1（生产运营）

6. 供应商/模型级限流与并发上限；优先在网关层做。
7. 熔断与健康探测：连续失败摘除，半开恢复。
8. 备用模型路由：按优先级列表 + 成本/能力约束；禁止跨租户。
9. 模型价格表接入 D12，调用级费用落库。
10. 供应商 SLA 看板：可用率、P95、错误率、限流次数。

### P2（企业增强）

11. Azure/Bedrock/本地推理适配器。
12. 按部门/项目的模型白名单与预算联动。
13. 合规元数据与数据出境标记，接入 D10 审计。
14. 模型灰度与影子流量对比。

## 6. 验收标准

- [ ] 管理端新增供应商后，密钥不再以明文出现在数据库、日志、API 响应中。
- [ ] 停用供应商后，任何智能体都无法再解析到其模型。
- [ ] 模型绑定被停用/删除时，系统给出显式降级事件，而不是静默换模型。
- [ ] 主供应商连续失败时，能按配置切换到备用模型，并记录切换原因。
- [ ] 每次调用都能查到模型、token、耗时、错误类型、重试次数。
- [ ] 上下文窗口与利用率能在报表中正确展示，而不是空值。
- [ ] 超时、重试次数、限流阈值可通过配置调整，无需改代码。
- [ ] 跨租户模型 ID、跨租户供应商 ID 均被拒绝。
- [ ] 工具 Schema 被移除时有可检索记录，并能定位到具体工具与 Trace。
- [ ] 模型价格缺失时费用记为 `NULL` 并告警，不能记 0 掩盖。
