# D08 交互与人机协同

> **解决什么问题**：企业场景不是"一个聊天框解决一切"。同一个智能体要能出现在管理端、用户门户、IM、开放 API 和嵌入组件里；执行过程中要能暂停问人、能被中断、能看见进度、能把产物交付出去。
> **适用读者**：前端、后端、渠道集成、产品、交付实施。
> **关联文档**：[D02 智能体运行时](D02-智能体运行时.md) · [D04 工具与外部集成](D04-工具与外部集成.md) · [D07 多智能体协作](D07-多智能体协作.md) · [D10 安全合规与审计](D10-安全合规与审计.md) · [能力全景 §5 D8](../企业级Agentic平台能力全景.md)
> **状态基准**：2026-11 代码。状态只用 `已具备 / 部分 / 缺失`。

---

## 1. 边界

**本文负责**：交互形态、流式体验、结构化确认与工具审批、任务可视与后台执行、产物交付、渠道接入与治理、页内界面操作、多语言与无障碍。

**本文不负责**：单智能体推理循环（D02）、工具安全策略本身（D04）、身份与租户模型（D01）、产物存储的底层实现（对象存储/沙箱）。本文只定义"用户如何触达智能体、智能体如何把控制权交还给人"。

**核心判断**：交互形态决定**触达范围**，人机协同决定**可控性**。确认不是弹一个窗，而是把执行权在关键时刻交回用户；渠道不是转发消息，而是身份、会话、幂等与失败的完整治理。

## 2. 能力清单

### 2.1 交互形态

| 形态 | 要求 | 本项目状态 |
|---|---|---|
| 管理端 Web | 配置、调试、运营与对话一体 | 已具备（30+ 页面） |
| 用户端门户 | 普通用户只对话、会话管理，配置脱敏 | 已具备 |
| IM 渠道 | 飞书 / 企微 / 钉钉 / Slack / Teams，身份绑定、会话映射 | 部分（飞书、企微应用、企微机器人） |
| 开放 API | 机器调用、API Key、版本化 | 已具备（`agent_api.py`） |
| CLI | 本地对话与运维命令 | 已具备（`aio-cli`） |
| 嵌入组件 / SDK | 第三方页面嵌入、访客访问 | 缺失 |
| 移动端 | 窄屏可用、确认卡片可操作 | 部分（响应式门户，无独立 App） |

### 2.2 流式体验

- 首字延迟可控；思考过程可折叠；工具执行有进度；错误可读；随时可中断。
- 后台任务脱离请求生命周期，断线可重连并恢复事件。
- 渠道没有 SSE，需用原生流式卡片或占位消息 + 节流更新模拟。
- 本项目 Web/CLI 已具备；渠道侧飞书用 CardKit 流式卡片，企微按能力降级。

### 2.3 人机协同

- 结构化提问：单选、多选、自由输入、审批、表格录入。
- 工具执行前确认：按风险级别与信任级别触发，确认内容包含实际参数。
- 超时策略：不同场景不同超时与超时行为。
- 确认记录：可恢复、可审计、可绑定到具体会话/成员/任务。
- 多智能体场景：子智能体确认冒泡并标注来源。

### 2.4 任务可视

- 长任务进度、后台运行、断线恢复、完成通知。
- 用户不在线时的通知与待办。
- 本项目有后台 `ChatRun`、事件表、重连、停止、宠物任务条 SSE、定时任务通知。

### 2.5 产物交付

- 文件下载、网页产物、图表、图片、消息卡片。
- 产物权限与过期：不能凭 URL 越权访问，历史卡片不能因签名过期失效。
- 本项目有文件变更记录、网页产物 token 访问、图片附件、渠道文件发送。

### 2.6 渠道治理

- 渠道配置、凭证校验、启停、连接状态与最近错误。
- 用户身份绑定、会话映射、消息去重、串行排队、失败重试。
- 工具黑名单、敏感词、静默策略。
- 本项目前三项已具备；失败重试与敏感词治理仍不完整。

### 2.7 多语言与无障碍

- 企业全球化需要界面多语言；无障碍需要键盘操作、屏幕阅读器与颜色之外的语义。
- 本项目当前均缺失。

## 3. 本项目现状

### 3.1 已具备

- **多入口**：管理端 `AgentChatPage` / `ChatPage`、用户门户 `/portal`、飞书、企微应用、企微机器人、CLI、开放 API。门户只暴露脱敏后的 agent 字段（id/name/description/icon/welcome_message/starter_prompts）。
- **统一流式 hook**：`useChatStream` 收敛了管理端两份与旧页面一份的 SSE 事件 switch，门户复用同一实现。
- **五种确认模式**：`single_select`、`multi_select`、`free_input`、`approve`、`table_input`；前端有对应卡片、倒计时、已确认态、预览与可编辑表格。
- **暂停-恢复协议**：`AskUserQuestion` 在 AgentLoop 内拦截（不进工具执行器），经 `event_queue` 推 `confirmation_required`，`asyncio.Event` 阻塞，REST 回包唤醒；超时由 `asyncio.timeout` 控制；页面刷新可通过 `/pending` 恢复。
- **工具审批**：`requires_approval` 按 `trust_level` 与工具权限决定是否走审批；`auto_all` 跳过，`ask_always` 全量确认，`ask_dangerous` 默认。
- **命令系统**：Web 与渠道共用命令注册表，`/help`、`/new`、`/stop`、`/approve`、`/deny`、`/model`、`/cron` 等；Web 有 `/` 候选菜单。
- **后台任务与重连**：`ChatRun` + 事件持久化 + Redis 任务注册；前端可重连回放、显式停止。
- **任务可视**：宠物任务条 SSE（`pet_task_snapshot/started/tool/finished`），支持渠道任务即时展示与断线快照恢复。
- **定时任务通知**：`cron_respond` 结构化上报；`delivery_status` 区分 `sent/suppressed/not_requested/failed/unknown`，静默与发送失败可追溯。
- **产物交付**：工作区文件变更自动检测并附着消息；`create_webpage` 生成 HTML 产物，独立源 + 短时 token 访问；图片附件与渠道文件发送。
- **页内界面操作**：`ui_*` 前端工具、虚拟光标、聚光灯、危险动作二次确认、回包超时、断线 `cancel_all`、失败熔断。
- **宠物交互形态**：精灵图状态机联动、绑定智能体气泡与闲聊、动作名称两级自定义、`pet_action` 控制、零 token 降级。
- **渠道治理基础**：渠道 CRUD、凭证校验、WebSocket/Webhook 双模式、身份绑定码、会话映射、`event_id` 去重、chat 级串行队列、`/stop` 与撤回即停、工具黑名单、流式节流。

### 3.2 部分具备

- **确认记录**：确认请求纯内存，进程重启即丢失；只有聊天室把确认绑定到 `chat_room_tasks.confirmation` 落库，普通会话没有审计表。
- **信任级别联动**：`trust_level` 控制工具审批，但不控制 LLM 主动发起的 `AskUserQuestion`；`auto_all` 下模型仍可弹确认卡片。
- **子智能体确认冒泡**：子循环复用父级 `event_queue`，事件可冒泡；来源标注依赖上下文注入，未形成统一字段契约（需确认）。
- **渠道确认能力**：渠道会话直接过滤 `AskUserQuestion`，避免死等；`/approve`、`/deny` 在渠道只能返回文本，没有可交互确认载体。
- **产物权限**：网页产物用 token + 归属校验，文件用工作区权限；缺统一的产物级 ACL、过期策略与访问审计。
- **渠道失败重试**：出站发送失败有记录与部分降级，但没有统一重试队列；多 worker 下撤回/停止是进程内尽力而为。
- **渠道治理**：有工具黑名单，缺敏感词过滤、静默策略配置、渠道级配额。
- **门户**：门户已上线且脱敏，但移动端只是响应式基础可用，未做移动端专项。

### 3.3 缺失

- 钉钉 / Slack / Teams 渠道。
- 嵌入组件 / SDK、访客访问、分享链接。
- 多语言与无障碍（键盘、aria-live、色盲友好已零散存在，未系统化）。
- 外部审批流 / 工单系统集成。
- 用户离线时的确认与通知策略（如邮件/推送、超时后转人工待办）。
- 统一的产物权限模型与访问审计。

## 4. 关键设计

### 4.1 确认请求生命周期

1. LLM 调用 `AskUserQuestion(question, mode, options, context, table_schema)`。
2. AgentLoop 在当前迭代内直接拦截，创建内存 `PendingConfirmation`（含 `asyncio.Event`、超时、租户）。
3. 向 `event_queue` 推 `confirmation_required`，yield `confirmation_flow:{id}:waiting`，让 SSE generator 先 drain 队列。
4. 前端渲染确认卡片；用户提交走独立 REST `POST /api/confirmations/{id}/respond`。
5. REST 调 `resolve_confirmation`，`event.set()` 唤醒 AgentLoop。
6. AgentLoop 推 `confirmation_resolved`，把结果格式化为工具结果注入消息，继续 ReAct。
7. 超时或连接关闭时，以 `status=timeout` 回注，模型自行决定后续。

**设计要点**：SSE 只下行，回包走上行 REST；确认不进 `tool_executor`，否则阻塞会卡死事件队列 drain。

### 4.2 表格录入

- 复用同一暂停-恢复协议，仅新增 `table_input` 模式与 `table_schema`。
- 列定义包含 `key/title/type/required/default/options/placeholder/width`；表级包含初始行、最少/最多行、是否可增删。
- 前端 `TableInputCard` 用 antd Table 渲染可编辑单元格，提交前校验必填与行数。
- 提交结果以 markdown 表格回注 LLM；页面刷新可通过 `/pending` 恢复未决表格。
- 已知约束：确认纯内存，后端重启会丢失未决表格。

### 4.3 渠道入站治理

- Transport 归一化为 `InboundEvent`，下游管线与渠道类型解耦。
- 去重：`event_id` 内存 TTL 1h；重复事件直接 ACK。
- 串行：每个 `chat_key` 一个 `asyncio.Queue` + 消费者，逐条驱动，避免同一会话并发跑多个 AgentLoop。
- 身份：`(tenant_id, external_id)` 绑定平台用户；未绑定只回绑定引导，不创建账号。
- 会话：`(channel_id, chat_id, external_id)` 映射 session；`/new` 使旧映射失效。
- 中断：`/stop` 取消在跑子任务并清空队列；撤回事件按 `message_id` 反查并取消；秒撤回用 TTL 集合兜底。
- 出站：飞书优先 CardKit 流式卡片；不支持时降级为完成后一次性发送；超长分片。
- 工具面：渠道会话强制过滤 `AskUserQuestion`、`delegate_task` 与前端工具，再叠加渠道黑名单。

### 4.4 任务可视与后台执行

- Web 聊天任务：`ChatRun` 持久化运行状态与事件，前端断线后按 run 回放，避免重复提交。
- 渠道任务：`task_registry` 写 Redis 哈希并发布 `aio:pet_task_events`，`TaskEventBroker` 按 `user_id` 分发到 SSE，连接建立先发快照再发增量。
- 定时任务：执行与投递状态分离；发送前先落 `unknown`，成功记 `sent`，静默记 `suppressed` 并保留原因。
- 停止语义：已完成动作不回滚；无法立即取消的外部操作显示真实状态，不谎报已撤销。

### 4.5 产物交付

- 文件变更：写入型工具执行前后扫描 workspace manifest，生成 `created/modified/deleted`，按轮合并后附着助手消息；预览/下载复用工作区权限。
- 网页产物：HTML 存对象存储，返回短小 `{url,title}`；访问路由校验归属并校验短时 token；建议独立源 + iframe `sandbox` 双重隔离。
- 图片与附件：Web 上传、渠道下载后进工作区；视觉模型可直接 base64 喂入，非视觉模型降级为路径引用。
- 渠道文件：`channels/file_send.py` 支持把工作区文件作为渠道消息发送（需确认各渠道能力差异）。

### 4.6 页内界面操作

- 后端工具标记 `execution_location="frontend"`，AgentLoop 拦截后推 `ui_action_required`，前端注册表执行，REST 回包唤醒。
- 前端只执行注册表内 handler，不执行任意 JS；导航限平台路由白名单。
- `risk=dangerous` 的动作先走确认流程；回包超时默认 60s；断线/刷新调用 `cancel_all` 或回 `page_reloaded`。
- 虚拟光标从宠物位置出发，聚光灯高亮目标，动作队列串行；宠物状态随执行切换 `work/celebrate/sad`。

### 4.7 失败模式

| 失败 | 当前行为 | 风险 / 缺口 |
|---|---|---|
| 确认无人响应 | 超时回注 `timeout`，模型自决 | 高风险场景可能被模型"自行决定" |
| 确认进程重启 | 内存丢失，前端 pending 为空 | 用户无法恢复，任务悬挂至超时 |
| 渠道重复投递 | `event_id` 去重 | 多 worker 下内存去重不共享，需 Redis |
| 渠道发送失败 | 记录 `failed`/`unknown`，部分降级 | 无统一重试队列，可能丢回复 |
| 渠道确认 | `AskUserQuestion` 被过滤 | IM 用户无法完成需要确认的任务 |
| 网页产物 token | 短时 token + 归属校验 | token 泄露窗口、无访问审计 |
| 页内操作页面刷新 | 前端回 `page_reloaded`，Agent 继续 | 动作已执行但结果未知，可能重复操作 |
| 长任务断线 | run 回放 / 快照恢复 | 渠道侧多 worker 下停止是尽力而为 |

## 5. 实施建议

### P0（可控性与一致性）

1. **确认审计落库**：新增 `confirmation_logs`（会话、用户、智能体、模式、问题、选项、响应、状态、时间），响应时写入；刷新恢复从 DB 读，而不是只靠内存。
2. **渠道确认载体**：为飞书/企微实现交互卡片确认，或明确"渠道不支持确认"的产品降级（如禁止危险工具），不要静默过滤后让任务失败。
3. **渠道去重与取消跨 worker**：把 `event_id` 去重、在跑任务登记、`/stop` 广播迁到 Redis，消除多副本不一致。
4. **产物访问统一**：网页 token、工作区文件、渠道文件统一走"归属校验 + 过期 + 审计"，禁止只靠不可猜 URL。

### P1（覆盖更多场景）

5. 增加钉钉 / Slack / Teams 适配器，复用 `ChannelTypeSpec` 与入站管线。
6. 离线通知：用户不在线时，确认请求与任务完成通过渠道或邮件触达，并保留待办。
7. 渠道失败重试队列与死信，发送失败可重放且不重复。
8. 敏感词与静默策略配置化，区分"不发送"与"发送但脱敏"。
9. 门户移动端专项与嵌入组件 MVP（访客 token、限流、会话来源扩展）。

### P2（体验与合规）

10. 多语言（界面文案与系统提示模板分离）。
11. 无障碍：键盘全流程、aria-live 播报、风险等级不依赖颜色。
12. 外部审批流/工单集成，把高风险确认接到企业既有流程。
13. 产物版本、分享与访问审计看板。

## 6. 验收标准

- [ ] 五种确认模式均可完成"暂停 → 用户响应 → 恢复"，超时按场景回注。
- [ ] 确认回包只能由请求所属用户提交，重复提交不重复恢复。
- [ ] 页面刷新后可恢复未决确认（普通会话与聊天室至少各有一条路径）。
- [ ] 工具审批受 `trust_level` 控制，高风险工具未确认不执行。
- [ ] 表格录入支持列类型、默认值、预填行、必填校验，结果以结构化数据回注模型。
- [ ] 子智能体发起确认时，前端能识别来源智能体（或多智能体归属）。
- [ ] Web 聊天断线重连后能恢复运行状态，不重复执行。
- [ ] 渠道同一会话消息串行执行，重复 `event_id` 不重复触发。
- [ ] 渠道 `/stop` 与撤回能取消在跑任务，已产生部分结果保留并标记中断。
- [ ] 渠道工具黑名单生效，高危工具不会在渠道执行。
- [ ] 门户只返回脱敏 agent 字段，普通用户无法获取 prompt/工具/模型配置。
- [ ] 文件变更附着消息，刷新后仍可查看；已删除文件不可预览。
- [ ] 网页产物通过归属校验与短时 token 访问，历史卡片不因签名过期失效。
- [ ] 页内操作可中断，危险动作需确认，超时/刷新/断线不会让 Agent 无限挂起。
- [ ] 定时任务结果可区分执行状态与投递状态，静默原因可追溯。
- [ ] 用户不在线时，确认请求不会永久悬挂（当前未满足，需 P1 补齐）。
