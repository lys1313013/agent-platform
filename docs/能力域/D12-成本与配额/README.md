# D12 成本与配额

> **解决什么问题**：Agent 的 token 消耗不可预测，企业必须知道钱花在哪、并且能封顶。
> **适用读者**：后端、财务/运营、SRE、交付实施。
> **关联文档**：[D11 可观测性与运营](../D11-可观测性与运营/README.md) · [D03 模型接入与治理](../D03-模型接入与治理/README.md) · [能力全景 §5 D12](../../00-平台总览/README.md)
> **状态基准**：2026-11 实现。状态用 `已具备 / 部分 / 缺失`。

---

## 1. 边界

**本文负责**：计量、定价、成本核算、配额、限额执行、告警、账单与成本优化。

**本文不负责**：性能指标与告警平台（D11）、模型选型与路由质量（D03）、租户计费合同（商务）。

**核心原则**：

1. **先计量，再限额**。没有准确计量，配额只是拍脑袋。
2. **在请求进入前拦截**，不要等花完再报错。
3. **预算要传播**。父任务、子智能体、后台任务共享同一笔预算。
4. **计量要可归因**。租户、用户、智能体、模型、会话、任务六个维度至少能下钻到其中四个。

---

## 2. 计量维度

| 维度 | 用途 | 粒度 |
|---|---|---|
| 输入 token | 成本主因 | 每次模型调用 |
| 输出 token | 成本主因 | 每次模型调用 |
| 缓存读/写 token | 折扣核算 | 每次模型调用 |
| 工具调用次数 | 外部 API 成本 | 每次工具调用 |
| 沙箱时长 | 计算资源成本 | 每个会话/任务 |
| 存储 | 对象存储/工作区 | 每日快照 |
| 渠道消息 | IM 平台费用 | 每条消息 |
| 重试次数 | 隐性成本 | 每次调用 |

**归因键**：租户、用户、智能体、会话、链路、模型、供应商。

**时间口径**：按 UTC 日聚合；账单按租户时区展示。价格变更要记录生效时间，历史账单不重算。

## 3. 本项目现状

### 3.1 已具备

| 能力 | 实现 |
|---|---|
| 调用级明细 | 每次模型调用记录模型、供应商、输入/输出/总 token、缓存 token、首 token 延迟、耗时、吞吐、重试、状态、错误类型、上下文利用率、工具数 |
| 日聚合 | 按用户×日期×模型累加 token 与请求数 |
| 用量接口 | 个人/全局用量的汇总、趋势、分布、明细查询 |
| 前端 | 用量与用量分析页面 |
| 后台节流 | 记忆提取、摘要等后台模型调用降频 |
| 资源限额 | 沙箱工作区配额与 TTL；全局并发上限目前只有配置项、无执行点；宠物气泡、渠道绑定码、截图等局部配额 |

### 3.2 部分具备

- **成本字段存在但未计算**：费用字段始终写 0，模型与供应商没有价格配置。平台当前只能统计 token，不能算钱。
- **归因维度不足**：日聚合只有用户×日期×模型，没有租户与智能体；调用明细虽有这些维度，但没有对应的聚合表。
- **统计权限边界**：全局报表只检查管理员角色，查询没有按租户过滤。在只有全局管理员的当前模型下可用，但一旦引入租户管理员就会跨租户泄露。
- **限额是资源级不是用量级**：沙箱并发是进程/平台级，没有按租户分配；没有任何 token/费用上限。

### 3.3 缺失

- 模型价格表与成本计算。
- 租户/部门/用户/智能体/单任务的多层配额。
- 请求准入控制与超额策略。
- 预算传播到子智能体与后台任务。
- 成本告警与账单导出。
- 缓存计费、工具成本、沙箱时长计费。
- 成本优化策略（模型路由、提示词压缩、结果截断已有部分能力，但未与成本联动）。

## 4. 目标设计

### 4.1 价格与成本

- 价格表按供应商类型与模型匹配，支持通配；包含输入、输出、缓存读、缓存写单价，以及币种和生效区间。
- 价格变更插入新行，不覆盖历史；支持租户自定义加价系数。
- 费用按输入、输出、缓存读、缓存写四类 token 分别乘对应单价后累计。
- 费用写入每次调用明细并累加到日聚合；价格缺失时记空值并告警，不要记 0 掩盖问题。
- 聚合应覆盖租户、日期、用户、智能体、模型，汇总各类 token、请求数、工具调用数、沙箱时长与费用；原用户维度视图可保留或迁移后废弃。

### 4.2 配额层级

- 平台（可选）：全平台日/月上限。
  - 租户：月度预算、日 token、并发。
    - 部门（可选）。
      - 用户：月度预算、日 token。
        - 智能体：单次预算、模型白名单。
          - 任务：单次运行上限。

**继承规则**：子级未配置则继承父级；子级配置不得高于父级（除非显式放开）。每个层级都可设置月度费用上限、日 token 上限、最大并发运行数、单次调用 token 上限、可用模型白名单。

### 4.3 准入控制

在三个位置检查：

1. **请求进入**：创建运行前检查租户/用户/智能体配额与并发。
2. **每次模型调用前**：检查本次预计 token 是否超单次上限与剩余预算。
3. **每次工具调用前**：检查工具调用次数与外部成本配额。

**预算上下文**：创建运行时生成，随执行上下文传播，包含租户、用户、智能体、运行标识、费用上限与已用、token 上限与已用、超额动作（告警/降级/阻断）。

- 子智能体继承父预算，不能单独超额。
- 后台任务（定时、渠道、房间）使用来源租户的预算。
- 并发更新用原子累加，避免竞态。

### 4.4 超额策略

| 阈值 | 动作 |
|---|---|
| 50% | 通知租户管理员 |
| 80% | 通知 + 前端提示 |
| 100% | 按配置：拒绝新请求 / 降级到低价模型 / 只读模式 |
| 单次任务超限 | 终止任务并返回明确原因 |

**降级顺序**：便宜模型 → 缩短上下文 → 关闭非必要工具 → 拒绝。降级必须记录，事后可解释。

### 4.5 告警与账单

- 告警：租户/用户预算阈值、单日突增（同比/环比）、模型价格缺失、成本写入失败。
- 账单：按租户出月账单，含模型明细、工具、沙箱、存储；支持 CSV 导出。
- 成本看板：按租户、部门、用户、智能体、模型下钻；支持时间对比。

### 4.6 成本优化

- 模型路由：按任务复杂度选择模型，质量达标前提下优先低价。
- 上下文：压缩、缓存、工具结果截断（已有基础能力）。
- 工具：限制无意义重复调用，缓存只读结果。
- 批处理：非实时任务合并调用。
- 预算感知提示：接近上限时提示模型收敛。

## 5. 实施路线

### P0（先能算钱、能封顶）

1. **价格表 + 成本计算**：替换恒 0 的费用；价格缺失记空值并告警。
2. **用量归因**：聚合补租户与智能体维度；修复全局报表查询的租户过滤。
3. **租户 + 用户两级配额**：月度费用、日 token、并发；请求准入检查。
4. **单次运行预算**：单次费用上限、单次 token 上限，超限终止。
5. **子智能体预算传播**：父预算被子任务共享，超支即停。
6. **告警**：50/80/100% 阈值通知。

### P1

7. 部门/智能体级配额。
8. 超额降级策略（低价模型、上下文缩短）。
9. 账单导出与成本看板下钻。
10. 工具调用、沙箱时长、存储计入成本。
11. 缓存计费与价格变更历史。

### P2

12. 成本预测与预算建议。
13. 按项目/成本中心分摊。
14. 多币种与合同价。
