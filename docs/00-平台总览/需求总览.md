# 需求总览

> **本文是什么**：当前有效的产品级需求入口。产品目标、范围、能力域需求地图与横切需求都在这里。
>
> **实现现状**：每个能力域 README 标注 `已具备 / 部分 / 缺失`；差距与优先级见 [现状与差距](现状与差距.md)。

## 1. 产品定位

多租户、自托管、可演进的 AI 智能体平台：让企业在一个平台上创建、运行、治理和复用智能体。

**目标用户**：

| 用户 | 主要诉求 |
|---|---|
| 企业团队 | 统一部署，成员各自拥有 Agent 空间，数据隔离 |
| 开发者 | 用自然语言完成编码、调试、部署与工具集成 |
| 业务人员 | 通过智能体完成查询、分析、文档与流程类任务 |
| 平台管理员 | 管理模型、知识库、工具、渠道、配额与审计 |

**核心范围**：
- 智能体运行时、工具与外部集成、知识与记忆、多智能体协作。
- Web / 门户 / IM 渠道 / 开放 API 多种触达方式。
- 多租户、权限、安全、可观测、成本与交付治理。

**非目标**：
- 不是只做问答的 Chatbot。
- 不是固定流程编排器；Agent 负责运行时决策，Workflow 只作为确定性封装。
- 当前不做消费者桌面 Agent 与本地系统级控制。

## 4. 需求优先级

当前差距按“上线前必须完成 / 生产运营必需 / 竞争力与生态”三档维护，见 [现状与差距](现状与差距.md)。

产品级 P0 包括：审计接线、RBAC、服务账号与 API Key、配额执行、注入防护、备份恢复、SSO、任务级运行模式。

## 5. 需求维护规则

1. 新需求先归入能力域，写在该域子目录的 `01-需求.md`。
2. 产品级范围、用户或非目标变化时，更新本文。
3. 过时或被取代的需求直接删除，不保留历史副本。
4. 需求与实现状态分离：需求写“要什么”，能力域 README 写“现在有什么”。
