## 原评审的修复顺序与验收

1. **收紧对象归属与凭据边界。** 以两名用户、两个租户和一个私有知识库为验收数据，检查列表、详情、分块和渠道换绑后的历史归属。容器控制面和工具出站使用独立身份、独立可达范围。项目已记录角色是用户级全局角色；部署若要求同一用户在各租户权限不同，还需要成员级角色模型。[现有角色说明](../能力域/D01-身份组织与权限/README.md#L126)
2. **给已有副作用建立恢复规则。** 优先保护文件上传、外部工具操作、渠道事件。分别验证同步冲突、第二次模型调用失败、消息确认后立即重启，结果应能明确区分已完成、待重试与失败。
3. **将数据库事务缩到实际读写区间。** 聊天、委派和后台任务开始时记录状态并释放连接，结束时重新校验和提交。配合监控连接借出时间、等待者数量及 SSE 心跳延迟，再判断连接池容量。
4. **把接口验收延伸到第二次读取。** 置顶、归档、反馈等操作从新请求读取持久化结果。发布版本用改草稿后的第二次执行验收。前端加上多标签切租户、首发断网、凭据刷新 502 的端到端用例。

## 安全与租户隔离

### 01　P1　图谱文档的分块查询缺少知识库归属校验

管理员通过路由的知识库可见性检查后，服务只按文档 ID 读取分块并返回正文。给定不属于该库的文档标识，查询没有约束其租户或私有可见性。

用同一条查询限定授权知识库、文档和分块的关系，父子不匹配返回 404。覆盖两个租户及同租户私有库。 [routes.py L255](../../backend/src/agent_platform/graph_knowledge/routes.py#L255) · [service.py L311](../../backend/src/agent_platform/graph_knowledge/service.py#L311)

### 02　P1　租户工具的出站网络与容器管理网络重合

仓库默认 Compose 让后端同时承担租户可配置 HTTP 请求和 Docker 控制。工具允许内网目的地，而管理代理位于同一可达网络，并开放容器管理写操作。实际影响取决于部署网络策略及管理员配置权限。

将容器控制委托给只接受固定沙箱操作的独立服务，并从租户工具的出站环境隔离控制网络。分别验证业务内网连通与控制面隔离。 [docker-compose.yml L24](../../docker-compose.yml#L24) · [docker-compose.yml L38](../../docker-compose.yml#L38) · [ssrf.py L129](../../backend/src/agent_platform/tools/web/ssrf.py#L129) · [remote_tools.py L380](../../backend/src/agent_platform/interface/routes/remote_tools.py#L380)

### 03　P1　渠道账号换绑后可能沿用前一用户的会话

解绑只删除账号绑定。相同外部账号和聊天再次进来时，映射查询忽略新的平台用户，历史加载也只按 session_id。新消息可能进入原会话，允许绕过 RLS 的数据库角色还可能把原历史送进新用户的模型上下文。

在解绑事务中停用映射，每次复用前验证会话所有者及渠道归属。换绑验收应同时断言会话、历史、摘要和新消息的归属。 [binding.py L207](../../backend/src/agent_platform/channels/binding.py#L207) · [pipeline.py L714](../../backend/src/agent_platform/channels/pipeline.py#L714) · [chat.py L597](../../backend/src/agent_platform/core/chat.py#L597)

### 04　P1　远程工具在同一上游共享 Cookie

### 05　P1　改密或管理员重置密码后旧会话仍可续期

### 06　P1　登录令牌轮换的竞态会波及其他设备

## 执行架构与数据可靠性

### 13　P1　活跃沙箱的同步可能删除刚上传的文件
