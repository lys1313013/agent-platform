## 文档规范

**按用途分文件，不按开发阶段分**：

| 文件 | 写什么 |
|---|---|
| `README.md` | 目录入口：是什么、边界、现状、子文档索引 |
| `01-需求.md` | 为什么做、做什么、不做什么、验收 |
| `02-设计.md` | 怎么做：架构、数据模型、流程、失败模式 |
| `01-运行手册.md` | 部署、配置、巡检、故障处理 |
| `01-调研.md` | 外部方案对比与选型依据 |
| `03-实现详解.md` | 代码级实现细节（仅复杂模块） |

**约定**：

1. 只保留当前有效文档；被取代的内容直接删除，不保留历史副本。
2. 总览写能力与行为，不写代码路径、表名、函数名；这些放 `02-设计.md`。
3. 状态统一用 `已具备 / 部分 / 缺失`，不把设计写成已实现。
4. 能力域目录用 `README.md` 作为入口；子目录按 `01-需求.md` / `02-设计.md` 等类型命名；链接使用相对路径。
5. 数据模型或路由变更后，重新生成 `参考/` 下的文档。
