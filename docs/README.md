## 四、文档规范

**状态标注**：统一用 `已具备` / `部分` / `缺失`，禁止把设计写成已实现。状态与代码冲突时以代码为准，并同步更新文档。

**每篇能力文档应包含**：
- 边界：负责什么、不负责什么。
- 能力清单：企业级要求与关键设计点。
- 本项目现状：已具备 / 部分 / 缺失 + 代码位置。
- 关键设计：数据模型、流程、失败模式。
- 验收标准：可测试的 checkbox。

**更新时机**：能力范围变化、核心数据模型变化、实现状态变化时更新对应能力文档；参考文档由代码重新生成。
